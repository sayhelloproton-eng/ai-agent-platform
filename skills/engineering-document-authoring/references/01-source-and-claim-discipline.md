# Source and Claim Discipline

Use only supplied or explicitly retrieved sources. Label material statements as verified fact, accepted decision, current status, target design, future plan, inference, hypothesis or recommendation.

Do not:

- present target architecture as implemented;
- smooth over conflicting sources;
- use model familiarity as project evidence;
- copy dynamic task history into stable long-term documents;
- duplicate the same canonical explanation across multiple documents.

Each important claim should point to code, test, Commit, ADR, Registry record, accepted Context, experiment or named user decision when available.
