# 查重、冲突与经验演进

## 1. 目标

长期经验体系的风险不是条目太少，而是大量近义条目、相互矛盾的规则和被静默覆盖的历史。查重应基于底层机制和动作，不应只比较标题或关键词。

## 2. 查重所需输入

理想情况下需要：

- 当前候选；
- 已有洞见索引或相关洞见集合；
- 来源引用；
- 机制、原则、适用边界和建议动作；
- 既有 revision history。

如果无法访问已有洞见，必须标记：

```text
deduplication_status: unverified
```

不得声称“这是全新的经验”。

## 3. 洞见指纹

比较以下字段：

- generalized problem；
- underlying mechanism；
- principle；
- applicable contexts；
- recommended actions；
- prevention checks。

标题不同但上述字段高度重合，通常属于重复或同一模式的新 occurrence。

## 4. 关系类型

建议使用以下语义：

- `same_as`：本质相同；
- `occurrence_of`：新事件是既有洞见的新实例；
- `evidence_for`：补充支持证据；
- `refines`：增加机制或动作细节；
- `specializes`：适用于更窄条件；
- `broadens`：有证据支持更广适用范围；
- `contradicts`：关键结论或边界冲突；
- `supersedes`：新洞见经批准替代旧洞见；
- `related_to`：相关但不能归入以上关系。

## 5. 决策顺序

处理新候选时按以下顺序：

1. 是否与已有洞见机制相同？
2. 是否只是新的来源或 occurrence？
3. 是否只增加一个更窄的应用场景？
4. 是否要求扩展原边界？
5. 是否出现反例或冲突证据？
6. 是否确实存在新的机制和独立动作？

只有第 6 项成立时优先创建新洞见。

## 6. 合并规则

合并时更新：

- source references；
- evidence strength；
- occurrence 信息；
- applicability；
- related insights；
- maturity recommendation；
- revision history。

不得：

- 删除较弱或相反证据；
- 只增加 occurrence 数量而不保存来源；
- 因新标题更好听而创建重复条目；
- 自动将新 occurrence 升级为 `repeated`，必须经过规则检查和人工确认。

## 7. 冲突处理

出现冲突时：

1. 确认冲突是事实冲突、机制冲突、边界冲突还是建议冲突；
2. 比较证据直接性、时间、环境和适用条件；
3. 检查两条结论是否其实适用于不同场景；
4. 无法调和时并列保留，标记 `contradicts`；
5. 提出需要的验证或决策；
6. 未经人工审阅不得覆盖旧洞见。

## 8. 修订而非重写历史

修订必须记录：

- 旧版本；
- 新证据；
- 变化字段；
- 修订原因；
- 影响到的下游规则；
- 审批状态。

`revised` 和 `deprecated` 都不删除历史来源。

## 9. 稳定 ID

洞见一旦进入受治理资产，应使用稳定 `insight_id`。标题、范围和成熟度变化不应导致 ID 重建。拆分或合并时保留关系和来源链。

## 10. 经验演进不是自动学习

本 Skill 可以提出合并、修订或成熟度建议，但不拥有自动持久记忆，也不自动修改经验库。所有演进必须由 Git 管理的外部流程保存和审阅。
