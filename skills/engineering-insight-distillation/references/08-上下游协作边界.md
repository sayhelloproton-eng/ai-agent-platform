# 上下游协作边界

## 1. 核心原则

`engineering-insight-distillation` 只负责把已确认或明确标记不确定的事件材料提炼为工程洞见。它不负责获取所有原始上下文，也不拥有正式知识资产的自动写入权。

## 2. 可选上游：project-knowledge-synthesis

`project-knowledge-synthesis` 可以作为推荐上游，提供：

- 来源清单；
- 已核实事实；
- 时间线；
- 问题、影响和证据；
- 根因分析及不确定性；
- 决策演进；
- 解决结果；
- 原始来源引用。

该上游尚未存在、不可用或不适合当前任务时，本 Skill 仍可接受人工整理或其他流程生成的结构化 `experience candidate`。

因此：

- 它是可选协作方，不是运行依赖；
- 本 Skill 不定义、实现或修改它；
- 本 Skill 不假设上游输出天然正确，仍执行证据资格检查。

## 3. 可能下游

### project-knowledge-governance

可以接收已批准洞见或正式知识资产的发布清单，负责受控知识发布和回读。它不应接收未经审批的候选经验作为正式事实。

### 工程规范与架构决策

成熟洞见可以成为规则或决策输入，但正式采纳需要独立审阅、影响分析和稳定 ID。

### 测试与验收策略

洞见可以派生 test rule、acceptance gate 和真实路径验证要求。

### 任务规划与代码复审

洞见可以转化为任务约束、停止条件、审查清单和风险提示。

### 项目复盘与作品集

可以引用洞见解释工程判断力，但不得用抽象洞见替代具体事实和证据。

## 4. Handoff Contract

向下游移交时至少提供：

- 洞见 ID 和版本；
- 成熟度与审批状态；
- 证据强度；
- 适用和排除条件；
- 来源引用；
- 建议落位类型；
- 是否存在冲突或待验证问题；
- 下游不得自动扩大解释的边界。

## 5. 写入治理

本 Skill 可以：

- 生成洞见草案；
- 建议新建、合并、修订或废弃；
- 给出下游落位建议；
- 生成质量门和审批请求。

本 Skill 不可以：

- 直接修改其他 Skill；
- 直接修改项目状态、ADR、技术方案或工程规范；
- 自动发布外部知识平台；
- 自动把候选经验设为正式规则；
- 自动持久化跨会话记忆；
- 绕过 Git 单一真源和人工审阅。

## 6. Skill 自身演进

当输入或输出暴露 Skill 缺陷时：

1. 保存脱敏、可复现的失败案例；
2. 增加或修改 Fixture；
3. 明确预期和禁止行为；
4. 人工审阅方法变更；
5. 同步更新 SKILL、Reference、Schema 或 Template；
6. 更新 Changelog；
7. 对既有 Fixture 进行回归检查。

不得让本 Skill 在一次运行中自动修改自身。
