## Boundary

References 解释方法，不保存具体项目的正式经验记录。具体案例只应作为测试夹具或进入受治理的项目知识资产。

## Maintenance

当真实案例暴露规则缺口时，先补充或更新 Fixture，确认问题可复现，再修改对应 Reference、Schema 或 SKILL，并记录 Changelog。
