# Overlap, Conflict and Placement

Two files are duplicates when they own the same reader question and repeat the same Claim set, not merely because they share vocabulary.

Prefer:

- one stable owner document;
- concise cross-links to deeper product, architecture or technical assets;
- archive + superseded relation for historically useful retired assets;
- stable ID preservation when the conceptual asset continues;
- explicit conflicts rather than blended compromise prose.

Target placement:

- current shared state → `context/`;
- long-term explanation → `docs/knowledge/`;
- implementation plan → `docs/technical/`;
- accepted decision → `docs/adr/`;
- reusable method → `skills/`;
- engineering lesson → Engineering Insight Registry;
- runtime task state → Task Store / Checkpoint.
