# KNO-009 项目会话知识综合与仓库沉淀

## 1. 文档定位

定义如何把长 Chat、Codex 报告和执行记录转化为可审计 Git 知识，而不把原始聊天直接当正式事实。

## 2. 输入分类

先区分已确认事实、决策、假设、用户偏好、执行结果、未解决问题、私人上下文与可复用洞见。

## 3. 流程

`选择会话范围 → 提取 Claim → 对照 Git/证据 → 去重与冲突 → 选择目标资产 → Draft → Review → Registry/Release`。

## 4. 目标资产

当前事实进 Context；长期解释进 Knowledge；决定进 ADR；方案进 Technical；观察进 Experiment；方法进 Skill；经验进 Insight；动态任务进 Task Store。

## 5. 隐私

原始聊天可能含账号、路径、Token 或第三方内容，进入 Public Git 前必须最小化、脱敏、核对知识产权并人工 Review。

## 6. 当前实现边界

当前 Chat 负责事实恢复和正文，Codex/DeepSeek 负责落盘；AI Knowledge Skill 提供检索、Draft 和 Write Plan，但会话综合仍以人工为主。

## 7. 目标设计边界

目标支持带来源行号、Claim 状态和证据引用的 Conversation Synthesis；正式写入与公开仍需 Review。

## 8. 设计原则

- 原始聊天不是真源
- Claim 分事实/决策/假设
- 动态状态不沉淀为长期知识
- 私人上下文默认不公开
- 正式写入关联证据
