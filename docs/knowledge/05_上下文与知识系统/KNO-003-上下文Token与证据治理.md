# KNO-003 上下文 Token 与证据治理

## 1. 文档定位

把 Token、上下文窗口和证据选择视为系统资源，减少重复扫描并避免长上下文事实漂移。

## 2. 消耗来源

浪费来自重新解释项目、全仓扫描、复制原始资料、让模型重复做路径/Schema 检查、执行模型重新设计内容和失败后叠加 Prompt。

## 3. 预算

预算分为事实恢复与选择、决策与 Task Contract、实现、验证与 Review。高不确定任务保留更多验证预算，确定性落盘交给脚本或低成本执行器。

## 4. 证据压缩

保留稳定 ID、来源路径、Source Commit、Hash、关键断言、失败摘要与原始引用，不在每份报告复制完整日志。

## 5. 上下文健康

检查冲突版本、当前/目标混写、失效路径、缺失决策、敏感内容、窗口预算和压缩后约束是否完整。

## 6. 当前实现边界

当前已使用固定 SHA、简短 Context、确定性交付包和脚本门禁控制 Token；资料选择与压缩仍主要人工完成。

## 7. 目标设计边界

目标把 Context Package、Evidence Reference、Token Usage 和 Health Event 接入 Task Control。

## 8. 设计原则

- 程序判断不重复用模型
- 只加载最小证据
- 压缩保留约束与错误
- Token 不足以验证时停止
- 证据高于执行摘要
