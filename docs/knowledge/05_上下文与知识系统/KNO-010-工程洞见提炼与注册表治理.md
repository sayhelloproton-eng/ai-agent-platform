# KNO-010 工程洞见提炼与注册表治理

## 1. 文档定位

说明如何从已解决工程事件提炼可复用洞见，并用 Engineering Insight Registry 管理成熟度、Occurrence、反证和生命周期。

## 2. 输入资格

事件需要已解决或有证据、根因至少部分确认、改变工程决策、可形成防复发动作并可能跨任务复用。低影响或未知故障可拒绝。

## 3. 输出

包括 principle、problem、root_cause、pattern、anti_pattern、heuristic、preconditions、exclusions、evidence、recurrence_prevention 与 maturity。

## 4. Registry

维护稳定 insight ID、成熟度、生命周期、Occurrence、来源、关系、反证和修订历史。同一事件的多种材料只算一个 Occurrence。

## 5. 成熟度

`candidate → provisional → validated → repeated → established`。一次事件通常不高于 provisional；repeated 需要独立事件。

## 6. 当前实现边界

当前 Skill v0.2.0、两轮离线 Eval、Registry 和五条初始洞见已存在，其中四条 provisional、一条 candidate。

## 7. 目标设计边界

目标把洞见检索接入 Task Preflight、Review 与 Skill 修订；新证据可增加 Occurrence、修订边界或废弃旧洞见。

## 8. 设计原则

- 先 Screening
- 成熟度与生命周期分离
- 一次事件不成定律
- 正文不反向覆盖 Registry
- 使用时检查前提与排除
