# WFL-012 项目状态汇总与阶段汇报

## 1. 文档定位

本文定义从多来源收集项目事实、识别漂移并形成阶段汇报的受控流程。正式状态必须通过 Git Review，不由汇报生成器直接覆盖。

## 2. 流程

```text
Select Reporting Window
→ Collect Git / Task / Registry / Test Evidence
→ Normalize Status
→ Detect Drift and Gaps
→ Assess Risks and Decisions
→ Generate Draft Report
→ Human Review
→ Optional Context Update
```

## 3. 数据来源

读取固定 Commit、Release、Current Migration、Roadmap、Task、测试和外部依赖状态。执行者自然语言报告属于候选证据，必须与真实文件或系统回读核对。

## 4. 报告结构

报告说明时间范围、目标、完成事实、证据、未完成项、风险、偏差、资源、决策请求和下一阶段。不同受众可以改变摘要层级，但不改变底层状态。

## 5. Context 更新

发现漂移时先输出差异；经 Review 后生成 `context/current-status.md` 或 Roadmap Diff。更新必须同时检查 Registry、Release 和 Migration，避免只修一个入口。

## 6. 当前实现边界

当前状态由 Chat 和 Codex 报告人工综合，本次发现 Context 与 Registry 不一致；尚无自动汇总或漂移检测服务。

## 7. 目标设计边界

目标先让 AGT-010 只读生成候选报告和 Drift Report，再在明确 Git 授权下生成 Context Draft。

## 8. 设计原则

- 报告绑定时间范围和 Source Commit。
- 执行摘要必须由证据验证。
- 漂移先报告后修正。
- 正式 Context 更新需要 Git Review。
- 对外结果不超过真实证据。
