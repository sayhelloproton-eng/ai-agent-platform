# WFL-009 审批工作流

## 1. 文档定位

本文定义高风险动作从审批请求、决定、执行到回读和过期的完整工作流。审批是特定动作的一次治理决定，不是永久开放全部权限。

## 2. 请求

Approval Request 包含 task_id、version、action、target、scope、risk、reason、preview、expected_side_effect、rollback、evidence 和 expires_at。缺少目标或影响范围时不得请求笼统批准。

## 3. 决定

Approver 可以 approve、reject、request_changes 或缩小 Scope。决定记录身份、时间、理由和条件；修改 Task、动作或目标后旧决定失效。

## 4. 执行

Runtime 在执行前再次检查 Approval、Policy、Lease 和幂等键，执行后写入 Side-effect Ledger 并回读目标。批准不保证动作一定成功。

## 5. 超时与撤销

等待审批的 Task 进入 `waiting_approval`。审批过期、被撤销或环境变化时回到阻塞或重新规划，不自动沿用。

## 6. 当前实现边界

当前 Git Commit、Push 与飞书写入使用明确任务授权和确认短语，但没有统一 Approval Store 或自动过期机制。

## 7. 目标设计边界

目标先将 Git 与外部发布动作接入结构化 Approval 和 Ledger，再扩展其他高风险工具。

## 8. 设计原则

- 审批绑定具体动作、范围和版本。
- Preview 与执行分开。
- 批准不能绕过 Policy。
- 执行后必须回读和记录副作用。
- 过期和变更必须重新审批。
