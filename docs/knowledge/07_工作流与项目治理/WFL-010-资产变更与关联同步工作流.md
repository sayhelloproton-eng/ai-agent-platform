# WFL-010 资产变更与关联同步工作流

## 1. 文档定位

本文定义代码、知识、Skill、Agent、Workflow、Registry 和发布资产变化后，如何计算影响、同步关联资产并验证一致性。

## 2. 变更检测

从 Git Diff、Registry 生命周期和显式 Change Event 识别变化资产、旧新 Commit、变更类型和风险。未注册文件也必须进入范围检查，避免遗漏首次新增资产。

## 3. 影响计划

Impact Analyzer 遍历关系，生成受影响正文、Context、测试、Skill、Agent Profile、Knowledge Pack、Release 和 Projection 候选。计划列出确定影响和不确定影响，等待治理确认。

## 4. 同步顺序

```text
Canonical Asset
→ Registry / Relations
→ Tests / Evidence
→ Context / Navigation
→ Release
→ Derived Packages / Projection
```

派生目标不得反向覆盖 Git。

## 5. 验收

检查路径、ID、链接、Schema、生命周期、关系端点、测试、Hash、发布回读和远端 Commit。删除或迁移前确认目标已经验证并保留历史关系。

## 6. 当前实现边界

当前知识批次通过人工范围清单、Registry 校验、Markdown 链接和 Git Review 同步资产；尚无自动 Impact Analyzer。

## 7. 目标设计边界

目标先实现只读影响候选生成，再由 Task Control 创建 Review、Build、Migration 和 Publish 子任务。

## 8. 设计原则

- Canonical 资产先更新，派生目标后更新。
- 影响分析不自动授权写入。
- 未跟踪新增文件进入范围检查。
- 迁移前验证目标并保留历史。
- 发布后使用真实回读证据。
