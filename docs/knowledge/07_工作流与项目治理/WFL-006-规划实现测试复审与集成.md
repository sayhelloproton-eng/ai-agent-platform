# WFL-006 规划实现测试复审与集成

## 1. 文档定位

本文定义从规划、实现、测试、复审到集成的端到端工程工作流。每个阶段有独立输入、输出和门禁，避免执行模型在需求未冻结时直接修改仓库。

## 2. 阶段

```text
Context Recovery
→ Plan / Decision
→ Task Contract
→ Isolated Implementation
→ Deterministic Tests
→ Semantic Review
→ Integration
→ Release / Knowledge Update
```

## 3. 阶段门

规划门确认事实、范围和未决项；实现门确认 Branch / Worktree、权限和输入 SHA；测试门确认命令和结果；复审门检查语义、风险和范围；集成门重新验证合并后的状态。

## 4. 执行与复审

执行器只实现已冻结合同。Reviewer 不只读执行摘要，而是检查 Diff、文件、测试和 Registry。阻断问题回到对应阶段，普通措辞统一留到后续全库 Review。

## 5. 集成

Integration Task 处理并行结果、冲突、迁移、最终验证和 Release。成功提交后回读远端 SHA，并更新受影响 Context、Knowledge 或 Portfolio。

## 6. 当前实现边界

当前知识重构已经实践确定性交付包、固定 SHA、机械落库、完整验证和真实 Commit Review；自动 Worktree 与 Integration Task 尚未实现。

## 7. 目标设计边界

目标把现有实践编码为 Task Control 与 Execution Lane，先支持单任务和有限并行，不引入重型图编排框架。

## 8. 设计原则

- 决策冻结后才进入实现。
- 确定性测试和语义 Review 分开。
- 执行报告不能替代 Diff Review。
- 集成后重新验证。
- 返工回到产生缺陷的阶段。
