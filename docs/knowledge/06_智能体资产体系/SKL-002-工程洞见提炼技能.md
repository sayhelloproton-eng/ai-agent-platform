# SKL-002 工程洞见提炼技能

## 背景

普通复盘容易停留在事件流水账，能恢复历史，却不能稳定指导下一次行动；直接从一次事件生成全局规则，又会导致过度泛化和经验库膨胀。

`engineering-insight-distillation` 用于解决这两个问题。

## 定位

该 Skill 接收有证据支持的工程事件，剥离项目、供应商和临时实现细节，提炼为 Engineering Judgment、Pattern、Anti-pattern、Heuristic 和 Checklist。

每条洞见必须保留适用条件、排除条件、证据强度、成熟度、生命周期、来源引用、Occurrence、查重和治理状态。

## 不负责

- 不还原完整项目时间线；
- 不替代项目知识综合；
- 不保存原始聊天全文；
- 不把所有错误都沉淀；
- 不自动修改正式规范；
- 不自动升级成熟度；
- 不进行模型权重学习；
- 不把经验正文写入 Skill 内核。

可选上游是 `project-knowledge-synthesis`，但该 Skill 也能接收人工或其他流程整理的结构化事件。

## 架构

```text
具体工程事件
    ↓
Experience Candidate
    ↓ Screening
proceed_full / needs_evidence / reject
    ↓ Full
Engineering Insight
    ↓ deduplication / governance
Engineering Insight Registry
    ↓ retrieval / application
新任务的检查项、决策门和验收规则
```

## 运行模式

Screening 低成本判断是否值得长期保留、证据是否足够以及是否进入 Full。Full 执行输入资格、沉淀价值、底层机制、表达类型、适用边界、查重演进和可执行化七个 Checkpoint。Auto 根据用户意图、输入完整度和任务规模选择模式。

## 数据分层

```text
skills/engineering-insight-distillation/
  方法、Schema、模板、测试、Eval Harness

docs/technical/元数据/engineering-insights/
  工程洞见主记录和关系

docs/knowledge/工程经验/
  面向人阅读的分类文档
```

Git 是唯一真源。飞书只投影 `docs/knowledge/` 的人类阅读层。

## 评测

首轮 7 个真实案例有无 Skill 对照中，基线平均 5.7 / 16，使用 Skill 平均 14.7 / 16；5 个事件形成洞见提案，1 个证据不足事件返回 `needs_evidence`，1 个低价值事件返回 `reject`。

第二轮 Screening 对 7 个案例的处置全部符合预期，输出字符量约为完整 Full 的 16.7%。

这些结果证明结构性价值，但不代表已完成独立盲评、重复采样或跨领域统计验证。
