# AGT-010 项目治理与汇报智能体

## 1. 文档定位

本文定义项目治理与汇报智能体的候选职责。它聚合真实项目证据、发现状态漂移并生成候选汇报，不拥有修改事实或批准阶段的权限。

## 2. 任务目标

从 Task、Git、Registry、Release、测试、风险和资源记录生成一致的当前状态、阶段报告、阻塞清单和决策请求，并标记数据缺口或冲突。

## 3. 输入与输出

输入必须绑定时间范围和 Source Commit。输出包含已完成事实、未完成项、风险、偏差、证据引用、下一步和需要人类决定的事项；不得仅输出笼统总结。

## 4. 权限边界

默认只读。修改 `context/current-status.md`、Roadmap 或 Release 需要单独 Git 写入授权；不能自行把 partial 提升为 accepted，也不能把测试通过解释为产品完成。

## 5. 漂移治理

当 Context、Registry、Commit 和执行报告不一致时，先生成 Drift Report，列出冲突来源和建议真源；由 Reviewer 确认后再更新正式状态。

## 6. 当前实现边界

当前 Chat 人工综合状态，Registry 和 Git 提供证据；本次 Batch 04 Review 发现 `current-status.md` 残留旧批次状态，说明需要结构化漂移检查。

## 7. 目标设计边界

目标先实现只读状态汇总和 Drift 检查，再增加经授权的 Context Draft。所有正式写入仍经过 Review、Diff 和 Git Commit。

## 8. 设计原则

- 只读聚合优先。
- 汇报绑定时间范围和 Commit。
- 冲突先报告，不静默选择。
- 生命周期升级需要 Review 证据。
- 对外汇报不超过真实实现等级。
