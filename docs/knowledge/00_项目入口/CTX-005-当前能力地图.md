# CTX-005 当前能力地图

> 本文严格区分：已验证、部分实现、已设计、未开始、已替代和技术债务。能力判断以当前仓库代码、测试、真实调用、Context 和 Platform Registry 为依据；具体分支与 Commit 以根 README 和 `current-status.md` 为准。

## 1. 状态定义

| 状态 | 判定条件 |
| --- | --- |
| 已验证 | 有代码和实际测试、真实调用、回执或正式发布证据 |
| 部分实现 | 主边界存在，但范围窄、仍依赖静态配置或缺少完整治理 |
| 已设计 | 已形成经过讨论的模型和边界，但没有完整代码/测试 |

## 3. Contracts、Auth 与 Policy

### 已验证

- `@ai-agent-platform/contracts`：Task / Result / Error Contract v1、Capability 白名单、JSON 边界和运行时 validator。
- `@ai-agent-platform/auth`：Bearer 解析、API Key 格式校验、SHA-256 固定长度摘要、恒定时间比较和 Header 脱敏。
- `@ai-agent-platform/policy`：Deny by default、未知 Capability 拒绝、Allowlist 去重和固定顺序。
- Gateway 与 Runtime 使用分离的外部/内部 Key，并执行两层 Policy。

### 部分实现

当前认证是本机静态 API Key，适合 MVP，但没有自动轮换、用户身份、Agent Profile 动态映射、RBAC 或基于任务状态的细粒度授权。

## 4. Gateway 与 Local Runtime

### 已验证

- Gateway `/health`、`/ready`、安全 JSON、404/405、Request ID。
- 受保护的 `GET /v1/capabilities`、`POST /v1/tasks`、Custom GPT 专用零参数 `POST /v1/runtime/status`。
- Runtime `/health`、`/ready`、`/v1/tasks`、Body 限制、Task 校验、二次 Policy、Capability 调度和 `TaskResult`。
- Runtime Client 只允许 Loopback HTTP，具有默认 3000ms Timeout、响应大小限制和 Result 校验。
- 入站 Timeout、未读 Body 排空、Rate Limit、并发槽位和 Busy 映射已加固。
- 当前安全 Capability 为 `gateway.ping` 和 `runtime.status`；`system.info.safe` 未实现且默认拒绝。

### 边界

这是一条窄而可信的 Task 链路，不等于完整 Agent Runtime。它还没有通用 Task State、队列、重试编排、审批、补偿、持久事件日志和真实 Codex 执行适配。

## 5. Microsoft Dev Tunnels 与 Custom GPT Actions

### 已验证

- `apps/dev-tunnel` 使用官方 macOS x64 CLI，只公开 Gateway 8787；Gateway 和 Runtime 均只监听 Loopback。
- 本地与公网 health、未认证 401、已认证 capabilities 200、真实 `runtime.status` succeeded 已通过。
- 同一 Tunnel ID 重启 Host 后 URL 保持一致，30 天 refresh 已验证。
- OpenAPI 收窄为零参数 `getRuntimeStatus`；Builder、Preview 和正式 GPT 对话均已完成真实调用。

### 限制与债务

Dev Tunnels 为 Public Preview、无生产 SLA，连续 30 天无活动可能删除。它只用于开发期 MVP。Cloudflare 远端资源清理仍是独立债务，未经授权不得执行。
