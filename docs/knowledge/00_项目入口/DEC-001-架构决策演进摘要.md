# DEC-001 架构决策演进摘要
> **资产状态**：本文正文已在 Batch 02 交付包中完成内容 Review；进入仓库后先标记为 `partial / unpublished`，待真实 Commit 整体复审通过后再升级为 `accepted`。

## 1. Chat 与 Codex / Work 分工

- **日期/阶段**：2026-07-26 项目协作边界确认；2026-07-30 双会话合订本固化。
- **背景**：长对话适合推理和复审，真实仓库修改需要本地环境、命令和证据。
- **原方案**：模糊地把 ChatGPT、Codex 和本地 Agent 当作同一执行主体。
- **当前方案**：Chat 负责目标、架构、任务设计和复审；Codex / Work 负责授权范围内执行；用户手动转交任务。
- **原因**：避免假装已修改本机、减少上下文污染、保证 Diff 和验证可审计。
- **影响**：形成 Task Contract、执行提示词和结果复审流程。
- **状态**：现行决策。
- **证据**：根 `AGENTS.md` 角色边界、双会话合订本。
- **ADR**：候选；可与 Task/Session/Executor 分工一并记录。

## 2. Monorepo 与渐进式 workspace

- **日期/阶段**：2026-07-28，npm workspace 基线提交并开始逐包实现。
- **背景**：Gateway、Runtime 和共享 Contract 需要统一版本与验证入口。
- **原方案**：分散脚本和未来目录设想。
- **当前方案**：npm workspaces，真实存在六个 workspace；不提前创建无调用方空包。
- **原因**：共享 Contract、统一测试，同时保持 Skill 独立。
- **影响**：Node 20 / npm 10、`tsconfig.base.json` 和根级 verify 成为工程基线。
- **状态**：已实现并验证。
- **证据**：`package.json`、apps/packages README、测试。

## 3. Custom GPT Actions + Gateway

- **日期/阶段**：2026-07-28 至 2026-07-31，最终真实 Action 调用已验收。
- **背景**：普通 Chat 不能可靠直接操作本机，多个 Custom GPT 也不能通过共享记忆协作。
- **原方案**：浏览器转发或把 Custom GPT 当 Runtime。
- **当前方案**：Custom GPT → Actions → Gateway → Local Runtime；动态任务事实留在外部系统。
- **原因**：OpenAPI 契约、认证、授权和状态边界可测试。
- **影响**：形成 `runtime.status` 专用 endpoint、Actions Skill 和双层 Key/Policy。
- **状态**：窄链路已验证，完整任务治理未实现。
- **证据**：正式 GPT Action 回执、Gateway/Runtime 测试。

## 4. Git 唯一真源与飞书单向投影

- **日期/阶段**：2026-07-26 至 2026-07-28，ADR-002 与 Publisher 路线固化。
- **背景**：Git 与飞书都可编辑会导致冲突、合并和责任不清。
- **原方案**：Git + Feishu 双源、映射、同步或合并。
- **当前方案**：Git 是正式真源；只允许 Git → Feishu overwrite；不读取飞书旧正文；按 Git 映射逐篇 overwrite；写入后只验证 API、revision、图片和映射结果。
- **原因**：代码、文档、历史和验证可以统一审计。
- **影响**：Feishu Native 内容必须先晋升为 Git Draft。
- **状态**：现行决策。
- **证据**：`knowledge.config.yaml`、`knowledge-strategy.md`、治理规则。
- **ADR**：现有 ADR-001 需核对标题与当前内容；若仍含双源旧结论，应更新或 supersede。

## 5. 图片 Publisher：Raw URL → asset://

- **日期/阶段**：2026-07-28，`asset://` Publisher 方案进入仓库。
- **背景**：飞书无法稳定拉取 `raw.githubusercontent.com` 图片。
- **原方案**：Markdown 直接引用 GitHub Raw URL。
- **当前方案**：`knowledge-assets` 保存源图；main 使用 `asset://`；Publisher 上传飞书并生成 image block。
- **原因**：将图片发布变成受控流程，不依赖飞书外链抓取。
- **影响**：复杂图必须同时有 SVG/PNG，发布后回读检查。
- **状态**：方案已形成，Publisher 完整自动化仍需持续完善。

## 6. 两层 Knowledge Pack

- **日期/阶段**：2026-07-30 双会话知识综合。
- **背景**：每个 Custom GPT 既需要共同项目事实，也需要角色专属专业知识。
- **原方案**：每个 GPT 单独上传散乱文件，或把完整知识库全部复制。
- **当前方案**：通用基础包 + 角色专属包；均从 Git 正式知识派生；外部 RAG 负责实时共享知识。
- **原因**：控制 Token、减少重复、保持角色边界和版本可追踪。
- **影响**：未来建立 `knowledge-packs/`、manifest、release 和影响分析。
- **状态**：已确认设计，未实现。

## 7. 多 GPT 通过 Task State 协作

- **日期/阶段**：2026-07-29～30 Custom GPT 续学与多 Agent 设计。
- **背景**：Custom GPT 之间不能可靠直接程序化互调，也不共享稳定会话记忆。
- **原方案**：让多个 GPT 通过聊天转发或共享全部上下文。
- **当前方案**：共享 `goal_id`、`task_id`、状态、事件、审批、Artifact 和知识引用。
- **原因**：Task 是稳定身份，Session 和 Executor 可替换。
- **影响**：需要 Task Control、Event Log、Artifact Store 和 Gateway 命令模型。
- **状态**：核心设计，未实现完整控制面。

## 8. Cloudflare 路线被 Microsoft Dev Tunnels 替代

- **日期/阶段**：2026-07-31，Microsoft Dev Tunnels + Custom GPT 工作流提交完成。
- **背景**：Cloudflare Edge/Bridge 路线产生配置漂移、远端 Secret 和实现复杂度。
- **原方案**：Cloudflare Workers/Quick Tunnel/Edge Bridge 作为当前公网入口。
- **当前方案**：删除活跃 Cloudflare app 与 Bridge；使用持久 Microsoft Dev Tunnel 公开本地 Gateway；历史保留 superseded。
- **原因**：更贴合当前开发期 MVP，减少边缘组件；仍保持 Gateway Bearer 认证。
- **影响**：产生 Dev Tunnel Skill；保留 Cloudflare 远端清理债务。
- **状态**：当前开发期实现；非生产方案。

## 9. 当前不采用 LangGraph

- **日期/阶段**：2026-07-30 合订本固化。
- **背景**：需要状态、检查点和人工介入，但项目领域对象尚未稳定。
- **原方案**：可能直接引入完整 Agent Framework / LangGraph。
- **当前方案**：Agent + Skills + Contracts + 轻量 Task Control + Approval + Evidence + Recovery。
- **原因**：避免用框架结构代替领域设计和真实验证。
- **影响**：保留对 LangGraph 思想的研究，但当前代码不依赖。
- **状态**：现行技术路线。

## 10. 不创建根级 products/

- **日期/阶段**：2026-07-31 总控蓝图。
- **背景**：`ai-agent-platform` 本身是当前平台主体，AI 视频工作流尚未进入开发。
- **原方案**：为多产品提前建立根级产品树。
- **当前方案**：产品真正产生资产后，在 `apps/`、`packages/`、`docs/`、`agents/`、`skills/` 等按资产类型创建子目录；归属由 Registry 表达。
- **原因**：避免空壳结构和重复资产。
- **状态**：现行目录原则。

## 11. Platform Registry

- **日期/阶段**：2026-07-31 总控蓝图。
- **背景**：文档、代码、Agent、Skill、ADR、测试和飞书节点关系分散，YAML Front Matter 容易污染正文。
- **原方案**：每篇正文携带大量元数据或依赖旧 `docs/technical/元数据/`。
- **当前方案**：根级 `platform-registry/` 已统一资产 ID、关系、路径、实现状态、Migration、Projection 和 Release。
- **原因**：人类正文与系统元数据分离。
- **状态**：Batch 01 已落地，Batch 01-R1 已完成语义修正。
- **ADR**：候选。

## 12. 复杂图资产化

- **日期/阶段**：2026-07-31，V1 Review 后。
- **背景**：简单方框图无法独立表达当前/目标、状态、证据和决策影响。
- **原方案**：把 Markdown 小标题放进同级方框并导出图片。
- **当前方案**：复杂图先写图稿规格，输出可编辑 SVG + 发布 PNG，正文解释图中结构，交付前实际打开检查。
- **原因**：图必须成为知识资产，而非装饰。
- **状态**：治理原则已确认；正文冻结前暂停生成正式图片。
