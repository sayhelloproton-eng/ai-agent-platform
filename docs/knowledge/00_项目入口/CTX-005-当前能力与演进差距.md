# CTX-005 当前能力与演进差距

> 本文回答“当前真实完成了什么、明确没有完成什么、下一阶段还差什么”。精确分支和即时进度以 `context/current-status.md` 为准；完整目标架构以 `04_平台架构/ARC-001` 为准。

## 1. 状态定义

| 状态 | 判定条件 |
|---|---|
| 已验证 | 有代码和实际测试、真实调用、回执或正式发布证据 |
| 已接受 | 已完成实现、Review 和治理确认 |
| 部分实现 | 主边界存在，但范围窄或缺少完整治理 |
| 已设计 | 已形成明确模型和边界，但没有完整代码与测试 |
| 未开始 | 无对应实现，或只有 Roadmap 占位 |
| 已替代 | 不再作为当前路线，但保留历史价值 |

## 2. 当前真实调用链

```text
用户自然语言
→ Custom GPT
→ getRuntimeStatus Action
→ Microsoft Dev Tunnel
→ Action Gateway（127.0.0.1:8787）
→ Local Runtime（127.0.0.1:8790）
→ runtime.status Capability
→ Contract v1 TaskResult
→ Custom GPT 回答
```

该链路已完成本地、公网、Builder Preview 和正式 GPT 对话验证。它证明接口、认证、Policy、Runtime 和 Capability 可以协作，但不等于完整 Agent Runtime 已经完成。

## 3. 当前已验证能力

### Interface 与外部入口

- Custom GPT Action 的 OpenAPI、Builder Preview 和自然语言调用链；
- Microsoft Dev Tunnels 开发期持久公网入口；
- Tunnel 只公开 Gateway，Gateway 和 Runtime 均只监听 Loopback。

### Runtime、Contracts 与安全

- Task / Result / Error Contract v1；
- Gateway 与 Runtime 双层 API Key 和双层 Capability Policy；
- Deny by default、未知 Capability 拒绝；
- Timeout、请求和响应大小限制；
- Rate Limit、并发槽位和 Busy 快速失败；
- TaskResult `taskId` 对应校验；
- 安全错误映射和响应脱敏；
- 当前安全 Capability：`gateway.ping`、`runtime.status`。

### Knowledge 与治理

- Git 唯一真源和 Feishu 单向 Projection；
- `context/`、正式知识、技术方案、ADR 和 Platform Registry；
- `asset://` 与正式图片 Publisher；
- Engineering Insight Registry；
- 六个已验证或已接受 Skill；
- Planner Executor Handoff v0.5.1 / `accepted`；
- Context 唯一语义负责人、完整覆盖和 Scope Lock 约束；
- Project Knowledge Synthesis v0.1.0 已物化并完成首个目录聚合 Pilot，当前为 `in_review`。

### 确定性交付

- ZIP、Manifest、SHA-256 和安全解压门禁；
- Frozen Overlay、Delete Scope、逐文件字节一致性；
- 单 Commit、普通 Push 和远端回读；
- Planner 生成语义内容，Executor 不自行重写。

## 4. 当前明确未实现

- 持久化 Goal / Task / Version / State / Event；
- 动态 Task Store、队列和重试编排；
- Executor Adapter 与 Execution Lane；
- 结构化 Approval、Evidence 和 Side-effect Ledger；
- Health Event、Checkpoint、Snapshot、Recovery 和 Compensation；
- 多执行器和多 Agent 自动调度；
- Agent Profile、Knowledge Pack 及其确定性发布；
- 平台自有 MCP Server / Adapter / Governance；
- AI 视频工作流业务实现；
- Portfolio Release；
- 生产级公网入口和动态身份权限。

## 5. 当前与目标的差距

| 能力域 | 当前 | 下一目标 |
|---|---|---|
| Task | 单次请求内 Task | 持久 Goal / Task / Version / State / Event |
| 权限 | 静态 Key + Capability Allowlist | Agent / Client / Executor 身份、Scope 和状态校验 |
| 审批 | 人工在外部流程确认 | 结构化 Approval、风险分级和执行证据 |
| 执行 | 两个安全 Capability | Codex / Work / Skill Adapter 与 Execution Lane |
| 证据 | 测试、日志、Diff、TaskResult | Evidence Registry 与副作用账本 |
| 恢复 | 进程级失败和快速失败 | Health、Checkpoint、Snapshot、Handoff、Recovery |
| 知识 | Git、Context、Registry、人工综合 | Agent Profile、Knowledge Pack、外部知识服务和影响分析 |
| 业务 | 无正式业务工作流 | AI 视频工作流最小纵向切片 |

## 6. 最近演进顺序

当前不是继续增加 endpoint，而是依次完成：

1. 正式知识人工 Review、聚合和 Feishu 发布收口；
2. 轻量 Task State、expected version、幂等命令和 Evidence；
3. Approval、风险分级和 Side-effect Ledger；
4. Executor Adapter、Execution Lane 和恢复能力；
5. Agent Profile、Knowledge Pack 和 Custom GPT 资产化；
6. AI 视频工作流真实业务验证；
7. Portfolio Release 和生产化评估。

## 7. 当前约束

- Dev Tunnels 只是开发期 Public Preview，不是生产入口；
- 当前 Key 是本机静态 Key，没有自动轮换和用户身份；
- Project Knowledge Synthesis v0.1.0 只产生综合候选，不能自动写入或发布；
- `provisional` / `candidate` 工程洞见不等于 `accepted`；
- 设计资产必须显式标记为设计，不能冒充已实现。
