# REF-003 开源项目与框架索引

## 1. 文档定位

本文记录影响项目判断的开源项目和框架。被索引不代表已经引入依赖或采用其架构。

## 2. 当前参考

| 项目 | 用途 | 当前关系 |
|---|---|---|
| MCP-SuperAssistant | 浏览器与 MCP 桥接参考 | 调研，未集成 |
| Usher | 多编码工具 MCP / Skill 配置同步 | 候选 Adapter，未验证 |
| Backstage TechDocs | Docs-as-Code 与生成式发布参考 | 方法参考 |
| AgentLite 等 | 轻量 Agent 研究参考 | 未采用 |

## 3. 未采用的重型编排

项目当前不采用 LangGraph 等重型图编排框架。原因不是否定其能力，而是 MVP 优先验证 Task、Policy、Evidence 和最短用户路径；只有复杂分支、持久状态和调度需求真实出现后再评估。

## 4. 评估维度

- 是否解决当前真实问题；
- 是否引入新的真源；
- Contract 和数据能否保持 Provider-neutral；
- Secret、权限和供应链风险；
- 维护活跃度与许可证；
- Intel macOS 和现有工具兼容性；
- 退出与替换成本。

## 5. 记录规则

第三方项目进入仓库依赖前，需要单独技术调研、PoC、许可证与安全检查。星标、宣传和 Demo 不能替代项目证据。

## 6. 当前事实边界

当前代码不依赖 Usher、MCP-SuperAssistant、LangGraph 或上述 Agent 框架。项目使用 Node.js 自建最小 Gateway / Runtime，并保留 Adapter 边界。

## 7. 后续边界

后续根据 Browser Bridge、多 Host 配置和 Task Control 的真实需求选择 PoC，不提前锁定框架。

## 8. 结论与原则

- 索引不等于采用。
- 先验证问题，再选择框架。
- 第三方能力限制在 Adapter。
