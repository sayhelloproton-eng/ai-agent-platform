# REF-001 核心术语表

## 1. 文档定位

本文统一项目中的核心术语。术语解释用于阅读和沟通，不替代 Contract、Schema 或 Registry。

## 2. Agent 与任务

| 术语 | 定义 |
|---|---|
| Agent | 具备角色、目标、上下文、工具和边界的执行配置 |
| Agent Profile | Agent 的版本化静态配置资产 |
| Task | 具有稳定 ID、目标、范围、版本和验收的工作对象 |
| Session | 一次对话或执行上下文 |
| Executor | 实际运行任务的主体 |
| Execution Lane | Task Control 与执行器之间的受控执行通道 |
| Capability | 可被 Policy 判断和调用的最小能力 |


## 3. DDD 与边界建模

| 术语 | 定义 |
|---|---|
| 统一语言（Ubiquitous Language） | 在一个明确模型边界内，由业务与工程共同使用的精确语言 |
| 限界上下文（Bounded Context） | 某个领域模型保持内部一致、拥有独立语言和规则的边界 |
| 上下文映射（Context Map） | 描述不同限界上下文之间上游、下游、公开契约和防腐关系的视图 |
| 聚合（Aggregate） | 作为单一一致性单元处理的一组领域对象，由聚合根保护不变量 |
| 领域事件（Domain Event） | 已经发生、对领域有意义的业务事实 |
| 端口（Port） | 应用核心以领域语言定义的稳定交互契约 |
| 适配器（Adapter） | 在外部产品、协议或 Provider 与 Port 之间进行转换的实现 |

## 4. 知识与状态

| 术语 | 定义 |
|---|---|
| Git Truth | Git 中经过 Review 的唯一正式真源 |
| Knowledge Asset | 面向长期理解的正式内容资产 |
| Context | 短小、当前、任务相关的事实入口 |
| Memory | Host 或用户层的个性化记忆，不是 Task State |
| Knowledge Pack | 从 Git 派生、面向角色和 Host 的发布包 |
| Registry | 维护资产 ID、状态、关系和发布元数据的机器控制面 |

## 5. 治理与证据

| 术语 | 定义 |
|---|---|
| Approval | 对特定 Task 版本、动作和范围的授权 |
| Evidence | 可验证结果的引用、Hash、测试或回读 |
| Side-effect | 对 Git、外部系统或用户环境产生的变化 |
| Checkpoint | 可恢复的任务状态快照 |
| Accepted | 正文及其关系通过真实 Commit Review |
| Unpublished | 尚未向 Feishu 或其他目标发布 |

## 6. 产品与平台

| 术语 | 定义 |
|---|---|
| Custom GPT | ChatGPT 中配置化的专有 GPT |
| Action Gateway | Custom GPT Action 的受控 HTTP 入口 |
| Local Runtime | 仅 Loopback 的 Capability 执行服务 |
| Skill | 可复用、可触发、有流程和资源的 Agent 能力 |
| MCP | 模型与工具 / 数据服务的开放连接协议 |
| Projection | 从 Git 真源生成外部阅读或 Host 配置 |

## 7. 当前事实边界

术语已与当前知识体系对齐。不同产品的同名功能可能具有不同语义，使用时应引用对应正式文档。

## 8. 后续边界

新概念进入正式架构前先补充定义，并检查是否与现有 Contract 或领域对象重复。

## 9. 结论与原则

- 同一个概念只使用一个主名称。
- Memory、Knowledge、Context 和 State 不混用。
- 产品名与领域对象分开。
