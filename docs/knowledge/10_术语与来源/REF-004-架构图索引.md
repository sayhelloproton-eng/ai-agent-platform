## 3. 文档包规则

```text
Document-ID-title/
├── README.md
└── assets/
    ├── VIS-xxx-name.svg
    └── VIS-xxx-name.png
```

- 正文、SVG、PNG 和附件位于同一工作分支、同一 Commit、同一文档目录；
- Markdown 只使用 `./assets/...` 本地相对路径；
- 每个图片后必须立即出现 `### AI 可读语义镜像`；
- 图片与语义镜像是一个原子 Review 单元；
- 复杂架构、跨层关系、多角色协作、状态机和生命周期使用正式 SVG / PNG；Mermaid 只用于简单局部关系；
- 一个信息问题只对应一张正式图；图片生成器若合并章节、错写标签或丢失边界，必须拒绝并使用确定性 SVG；
- Visual Registry 记录稳定 ID、目标文档、来源、尺寸、Hash 与事实边界，但不替代正文。

## 4. Git 与 Feishu

```text
Git Document Bundle
  README.md + ./assets/*.png + AI 可读语义镜像
        |
        |  overwrite projection
        v
Feishu document
  text blocks + uploaded image blocks + same semantic mirror
```

Git 保存完整正式文档包。Publisher 在投影阶段上传本地 PNG，并把 Markdown 图片位置转换为 Feishu image block。Feishu Media Token、URL 和 Block ID 不回写 Git。两端要求语义等价，不要求物理语法相同。

## 5. 验收

- 文档入口和资源路径存在；
- SVG 不含脚本、外部资源、事件处理器或 `foreignObject`；
- PNG 签名、尺寸和 SHA-256 与 Registry 一致；
- 正文嵌入本地相对图片；
- 图片后紧邻 AI 可读语义镜像；
- Visual Asset ID、目标资产、Registry 与正文一致；
- Publisher 只处理已 Review、已授权的 Git 资产。

## 6. 历史边界

独立 `knowledge-assets` 分支与 `asset://` 属于已被 ADR-003 取代的历史策略。历史 Commit、Release 与审计记录保留，但不再作为当前正文或发布输入。
