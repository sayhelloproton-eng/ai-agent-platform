# 智能体工程探索录

AI Agent Platform 是一个面向个人学习、工程实践和求职作品集的长期 AI Agent 工程项目。本知识库记录项目为什么存在、如何设计、怎样演进，以及如何把讨论、实验和工程执行沉淀为可恢复、可验证的长期资产。

## 项目背景

AI 正在改变软件研发方式。项目从 AI Agent、内容创作和多端协作探索起步，逐渐明确三条递进主线：先建立 Git 与飞书之间受治理的 Knowledge Foundation，再打通 ChatGPT 到 Codex 的工程任务闭环，最后以 AI Video Workflow 验证平台的业务承载能力。

详细背景见 [CTX-001 项目上下文](./项目与产品/CTX-001-项目上下文.md)。

## 初始需求

- 让未来自己、新加入的 Agent 和 Codex 能快速恢复项目上下文。
- 把零散讨论、实验与工具调用转化为可追踪的知识、决策和工程证据。
- 让业务与模型、设备、工具和 Provider 解耦，保留替换能力。
- 形成可运行、可解释、可验证的作品集，而不是只有架构图的概念项目。
- 以 Git 保存正式项目事实，以飞书提供面向人的知识展示。

项目定位与目标见 [CTX-003 项目总览](./项目与产品/CTX-003-项目总览.md) 和 [PRD-001 平台愿景](./项目与产品/PRD-001-平台愿景.md)。

```text

        |
        v

        v

        |
        +----------------+----------------+
        |                |                |
        v                v                v
DDD 核心领域       能力 Port          数据与存储
                         |
                         v
              基础设施 Adapter
                         |
                         v
                   外部能力

[横切关注点]
安全 / 策略 / 可观测性
        +--> Gateway / 入口
        +--> 应用服务
        `--> 基础设施 Adapter
```

架构边界、数据流和演进策略见 [ARC-001 平台目标架构](./架构与领域/平台架构/ARC-001-平台目标架构.md)，领域模型见 [DOM-001 核心领域模型](./架构与领域/领域模型/DOM-001-核心领域模型.md)。

## 六个月路线

### 阶段 1：知识基础

完成 Git + Feishu + AI Knowledge Skill，建立项目知识、索引、受控投影、回读验收和 Drift 检测。

### 阶段 2：AI 编码工作流

完成 ChatGPT → Task → Codex → Git，建立 Task Contract、Gateway / Bridge、执行、测试、Result 和知识回写闭环。

### 阶段 3：AI 视频工作流

以 AI 视频工作流验证真实复杂业务，包括文本处理、故事分析、人物场景、分镜提示词、模型适配、评估重试、成本记录和 Demo。

阶段交付架构见 [ARC-003 六个月交付架构](./架构与领域/平台架构/ARC-003-六个月交付架构.md)。

## 知识边界

`docs/knowledge/` 保存面向人类阅读、项目展示和 Feishu Knowledge Projection 的正式知识。动态 Agent Context、工程实现、学习资产和 ADR 原文分别保存在 Git 的其他层，不进入本知识库。

```text
Git docs/knowledge/
        ↓
Feishu 知识库
```

Git Repository 是唯一真源。飞书只作为单向展示投影，不得反向覆盖 Git，也不得与 Git 双向同步。
