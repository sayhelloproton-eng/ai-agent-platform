# EXP-009 健康恢复与任务快照实验

## 1. 文档定位

本文记录通过真实批次中断进行的健康恢复演练。它是流程级实验，不表示 Health & Recovery 服务已经实现。

## 2. 实验场景

Batch 05 在 Registry 校验阶段因 Ruby 编码环境连续停止。每次停止都保留：

- 固定 Git SHA；
- 31 文件工作区；
- 暂存数量 0；
- 未创建 Commit；
- 已完成门禁；
- 原始错误；
- 下一次允许的最小修正。

## 3. 恢复过程

第一次尝试只设置 `RUBYOPT=-EUTF-8:UTF-8`，证明 I/O 编码改变，但 `ruby -e` 源码仍含中文并在解析前失败。

第二次将中文路径通过 Shell 环境变量传入，Ruby 源码保持 ASCII，并对 JSON / YAML 显式 UTF-8 读取。三项门禁随后通过，任务从原工作区继续，没有重新解压、复制或修改交付正文。

## 4. 验证结论

该演练验证：

- 停止边界可以保护未提交工作区；
- Checkpoint 必须包含 SHA、范围、已完成门禁和副作用状态；
- 恢复只应授权解决已确认根因的最小变化；
- 重复执行前需要重新 `cmp` 和范围检查；
- 安全恢复不等于自动重试。

## 5. 局限

当前快照由执行报告和 Git 状态人工形成；没有结构化 Schema、自动触发、Lease 撤销或恢复服务。

## 6. 当前事实边界

流程级恢复演练已成功，但 `ARC-014` 所描述的统一 Health Event、Checkpoint Store 和自动移交仍未实现。

## 7. 后续边界

下一步将本次字段沉淀为可机器读取的 Task Snapshot 候选，并在未来 Task Control 实现中验证。

## 8. 结论与原则

- 失败后先保全证据和工作区。
- 恢复授权只覆盖已确认根因。
- 继续前重新验证范围和输入版本。
- 自动重试必须满足幂等与预算。
