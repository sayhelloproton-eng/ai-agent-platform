# EXP-008 长上下文与知识综合复盘

## 1. 文档定位

本文复盘知识重构中长会话、上下文压缩、确定性交付包和真实 Commit Review 的效果与失败模式。

## 2. 观察

长上下文能保留大量历史，但也会产生：

- 旧状态与新状态并存；
- 文件名和 Schema 被手工抄错；
- 执行者重复读取同一背景；
- 补充指令层层叠加；
- 模型把计划、执行和 Review 混为一体。

## 3. 有效做法

本阶段逐步形成：

- Git 固定 SHA 作为事实基线；
- `context/` 提供短入口；
- Registry 提供机器状态；
- 最终 ZIP 内置唯一 Contract；
- Overlay、Manifest 和 Hash 做确定性落库；
- 执行后上传真实 Commit 快照；
- Review 只检查增量风险。

## 4. 失败案例

真实失败包括：

- `git diff --name-only` 遗漏未跟踪文件；
- 聊天任务书与 ZIP 真实文件名、字段不一致；
- Ruby 2.6 对中文 `-e` 源码按 US-ASCII 解析；
- Context 未随 Registry 状态更新。

这些问题都说明可预先由程序确定的内容不应依赖人工抄写。

## 5. 收敛方法

```text
最终资产
→ 自动生成 Manifest / Spec / Task
→ 临时仓库模拟
→ 机械执行
→ 真实 Commit Review
```

任务结束时同时更新 Context、Registry、Release 和 Migration，避免单点漂移。

## 6. 当前事实边界

当前知识批次已经采用最终 ZIP 唯一 Contract、Hash、范围和完整验证。Project Knowledge Synthesis v0.1.0 已把多源综合步骤结构化，并在 `00_项目入口` 完成首个真实 Pilot；总控 Planner 仍负责语义判断和完整文件生成。

## 7. 后续边界

后续继续用 01～10 知识目录进行 Pilot，完善来源行号、跨仓库索引、Impact Analyzer 和批量 Eval；在证据充分前保持 Skill `in_review`。

## 8. 结论与原则

- 长上下文不是正式状态数据库。
- 可确定字段从最终资产自动生成。
- 真实 Commit 高于执行摘要。
- 压缩必须保留目标、边界、错误和下一步。
