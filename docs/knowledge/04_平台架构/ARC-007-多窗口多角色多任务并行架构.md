# ARC-007 多窗口、多角色与多任务并行架构

## 1. 文档定位

定义 Chat、Codex、Work、脚本和未来专业 Agent 并行工作时的身份、状态与隔离模型。并行用于缩短独立任务等待时间，不允许多个执行器共享同一可写状态。

## 2. 稳定绑定

每个并行任务至少绑定 `task_id`、`role_id`、`session_id`、`executor_id`、`branch`、`worktree`、`capability` 和 `expected_version`。Task 是稳定身份；Session 和 Executor 可以更换。

## 3. 并行成立条件

只有目标可独立验收、写入路径可隔离、依赖已显式化、Review 能力足够且 Token/配额可控时才并行。决策未冻结、同一文件高频修改或共享不可重入服务时保持串行。

## 4. 角色与执行器

角色定义责任和评价标准；执行器定义环境与权限。产品、架构和测试是角色，Codex、Work、Runtime 和 Script 是执行器。

## 5. 汇合

并行结果由 Integration Task 汇合，检查输入 SHA、路径冲突、Contract 变化、测试证据和接受结果。禁止“最后写入者获胜”。

## 6. 当前实现边界

当前知识重构以单分支串行为主；平台尚无统一 Task Store、Session Registry 或自动冲突检测。

## 7. 目标设计边界

目标控制面维护 Task、依赖、Lease、Branch/Worktree、Executor、Evidence 和 Handoff，汇合由独立 Integration Task 完成。

## 8. 设计原则

- 默认串行，证明独立后再并行
- 一个可写 Task 绑定一个 Branch/Worktree
- 角色、Session、Executor 与 Task 分离
- 并行收益必须高于合并成本
- 冲突必须显式解决
