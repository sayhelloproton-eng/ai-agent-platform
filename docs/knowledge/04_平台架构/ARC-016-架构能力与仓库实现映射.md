# ARC-016 架构能力与仓库实现映射

## 1. 文档定位

把目标能力映射到当前仓库资产，防止把设计文档存在写成代码已经实现。机器状态以 Registry 为准。

## 2. 当前映射

Contracts 对应 `packages/contracts/`；认证对应 `packages/auth/`；Policy 对应 `packages/policy/`；外部 Adapter 对应 `apps/action-gateway/`；执行对应 `apps/local-runtime/`；开发入口对应 `apps/dev-tunnel/`；Skills 和 Registry 已有正式资产。

## 3. 缺口

尚无持久 Task State、Expected Version、Lease、Approval Store、Evidence Registry、Side-effect Ledger、Health/Recovery、多执行器 Adapter、Agent Profile、Knowledge Pack Publisher、MCP 与 AI 视频纵向切片。

## 4. 证据等级

`文档设计 < 代码存在 < 单元测试 < 集成测试 < 真实用户路径 < 可重复运营证据`。能力声明必须匹配证据等级。

## 5. 更新

代码或架构变化时更新实现状态、关系、Context、能力地图、Portfolio 与验证 Commit。

## 6. 当前实现边界

当前已验证 Custom GPT → Dev Tunnel → Gateway → Runtime 窄链路和知识治理；完整平台仍在设计与增量实现。

## 7. 目标设计边界

目标将每个能力关联到 Contract、代码、测试、实验、知识和 Release，并支持影响分析与 Portfolio 证据生成。

## 8. 设计原则

- 实现声明必须有路径和证据
- 设计不等于实现
- 单元测试不等于真实路径
- 机器状态由 Registry 管理
- 映射随 Commit 更新
