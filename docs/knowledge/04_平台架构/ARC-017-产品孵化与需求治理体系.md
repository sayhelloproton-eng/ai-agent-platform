# ARC-017 产品孵化与需求治理体系

## 1. 文档定位

本文定义新产品从机会发现、需求澄清、概念验证到进入正式设计或开发的治理体系。它服务于依托 `ai-agent-platform` 孵化真实上层产品，不代表现在创建根级多产品总仓或提前实现尚未验证的产品。

## 2. 治理对象

治理对象包括 Opportunity、Problem、User、Outcome、Assumption、Experiment、Product Concept、Capability Gap、Decision 和 Asset Plan。需求条目必须说明来源、用户、价值、证据和不做的后果，不能只保存功能清单。

## 3. 阶段门

```text
idea
→ discovery
→ problem_validated
→ concept_defined
→ experiment_ready
→ approved_for_design
→ approved_for_delivery
→ paused / rejected / archived
```

每次升级都需要明确证据、负责人、风险、下一阶段预算和停止条件。`candidate` 不等于已进入产品开发。

## 4. 资产生成

孵化过程按需生成：Product Brief、用户场景、能力缺口、领域模型、工作流、实验计划、ADR、Roadmap 和 Portfolio Evidence。只有真实进入设计或开发阶段时，才在现有相关目录下创建产品子目录。

## 5. 平台边界

平台提供 Task、Agent、Knowledge、Execution、Approval 和 Evidence 等通用机制；上层产品拥有自己的业务术语、规则和体验。尚未在多个产品中证明可复用的业务机制不提前下沉平台。

## 6. 当前实现边界

当前仓库已接受平台产品定义、用户价值、能力地图和 AI 视频产品概念，但没有统一 Opportunity Store、产品阶段门或自动资产生成器。产品孵化仍由 Project Owner 与 Chat 共同决策。

## 7. 目标设计边界

目标先以一个真实产品机会验证阶段门、证据和资产生成清单，再由需求与产品孵化智能体辅助整理候选内容。批准、预算和是否进入开发始终由 Project Owner 决定。

## 8. 设计原则

- 先验证问题和用户价值，再决定解决方案。
- 候选需求与正式承诺使用不同状态。
- 平台能力与产品业务资产保持边界。
- 每个阶段都允许暂停、拒绝和归档。
- 产品进入开发前必须形成可验收的最小纵向切片。
