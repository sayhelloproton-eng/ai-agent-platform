# PRT-005 关键问题与解决过程

## 1. 文档定位

本文用真实问题说明项目如何从错误假设收敛到可验证方案。

## 2. Git 与飞书双源冲突

**问题**：双向同步需要长期处理格式、权限和冲突。

**决定**：Git 唯一真源，Feishu 单向 overwrite；发布后回读，不合并旧正文。

**证明**：知识治理规则、AI Knowledge Skill 和历史发布实验。

## 3. 公网入口路线过重

**问题**：Cloudflare Edge、Tunnel、Origin 和 Secret 同时引入，无法快速证明 Actions 到本机链路。

**决定**：开发期改用 Microsoft Dev Tunnels，保留 Gateway / Runtime Contract。

**证明**：Superseded Cloudflare 审计、Dev Tunnel 应用和真实链路实验。

## 4. 长上下文与任务书漂移

**问题**：聊天中手工重写 ZIP 文件名、字段和门禁，导致执行模型按错误 Contract 停止。

**决定**：最终 ZIP 内置唯一任务书、Manifest 和 Spec；执行只接受包内 Contract。

**证明**：多个知识批次的停止、补充和最终单 Commit 记录。

## 5. Ruby 中文编码恢复

**问题**：Ruby 2.6 将 `-e` 中文源码按 US-ASCII 解析。

**决定**：中文路径通过环境变量传入，源码保持 ASCII，文件显式 UTF-8 读取。

**证明**：Batch 05 在不重新解压和复制的情况下恢复并完成。

## 6. 当前事实边界

这些问题已经形成正式实验、洞见、治理规则或工作流。它们证明项目不是一次顺利脚手架，而是经过证据驱动的架构收敛。

## 7. 后续边界

后续把重复出现的门禁错误进一步转化为生成器和 CI，不依赖补充指令。

## 8. 结论与原则

- 问题叙述包含背景、根因、决定和证据。
- 不隐藏失败，也不把一次事故过度包装。
- 复盘必须推动流程或工具变化。
