# PRT-003 核心架构亮点

## 1. 文档定位

本文面向作品集总结项目中已经形成的核心架构判断，并明确哪些只是目标设计。

## 2. 可信执行链

项目把公网入口、认证、Policy 和本机执行分层，形成：

```text
Custom GPT → Dev Tunnels → Gateway → Runtime
```

Gateway 与 Runtime 使用不同 Key 和两层默认拒绝 Policy，Runtime 只监听 Loopback。

## 3. 轻量 Task Control 路线

项目没有直接引入重型图编排框架，而是先定义 Task、Version、Approval、Evidence、Execution Lane、Health 和 Recovery 边界。当前代码仍是窄 Runtime，目标架构与实现状态分开。

## 4. Git 知识资产平台

Git 是唯一真源，Platform Registry 统一资产 ID、状态、关系、Release 和 Migration；Feishu、Custom GPT Knowledge 与未来 Publisher 都是派生目标。

## 5. Agent + Skills

Agent Profile、Skill、Knowledge Pack、Tool 和 Task 被设计为独立资产。当前已有六个正式 Skill 和工程洞见 Registry，为未来专业 Agent 提供可复用基础。

## 6. 当前事实边界

已验证的是知识治理、Registry、六个正式 Skill和 Custom GPT Actions 最小链路。动态 Task Control、多 Agent 自动协作、完整 Agent Profile Publisher 和 AI 视频产品仍未实现。

## 7. 后续边界

后续以 Task Control 纵向切片和 AI 视频工作流证明平台架构能否支撑真实业务。

## 8. 结论与原则

- 架构亮点必须绑定真实代码、测试或知识证据。
- 目标设计不伪装为已实现能力。
- 安全边界优先于功能数量。
