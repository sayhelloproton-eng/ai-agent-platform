# PRT-004 工程能力证明

## 1. 文档定位

本文把项目成果映射到可验证的工程能力，避免只罗列技术名词。

## 2. 需求与架构

- 从就业与作品集目标收敛平台范围；
- 区分当前实现、六个月目标和长期平台；
- 使用 DDD、Contract 和 Adapter 控制边界；
- 通过 ADR 与 Registry 保存演进决定。

## 3. 全栈与安全

- Node.js workspaces；
- Contracts、Auth、Policy 共享包；
- Gateway、Runtime、Dev Tunnel 应用；
- Loopback、双 Key、默认拒绝、限流、并发、超时和大小限制；
- 真实公网开发链路与本地链路验证。

## 4. Agent 工程

- Custom GPT Instructions / Knowledge / Actions 边界；
- Codex、Work、Chat 与执行器分工；
- Skills、AGENTS、MCP、Plugin 和 Profile 治理；
- Task Contract、Checkpoint、Approval 和 Evidence 设计。

## 5. 知识与交付

- Git 单一真源与 Feishu 投影；
- Platform Registry 和 Engineering Insight Registry；
- 确定性 ZIP、Manifest、Hash、范围和 Commit Review；
- Handoff v0.4.0 的严格 Artifact Schema、跨 Artifact 校验、负向测试、Feedback、Executor Switch Checkpoint 和真实 Commit 修正；
- 多模型 Token 与风险分工。

## 6. 当前事实边界

证据位于代码、测试、正式知识、实验、Release 和真实 Commit 中。尚未实现的能力不列为已掌握生产经验。

## 7. 后续边界

后续通过真实 Task Control 代码和 AI 视频产品纵向切片补充业务交付证据。

## 8. 结论与原则

- 每项能力附可追踪证据。
- 不使用无法解释的技术堆叠。
- 区分设计能力与生产运营经验。
