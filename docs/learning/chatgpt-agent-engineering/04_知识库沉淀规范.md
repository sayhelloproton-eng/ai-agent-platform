# ChatGPT Agent 工程体系知识库沉淀规范

## 1. Source of Truth

- **Git**：正式工程知识、架构、规则、ADR、实验、代码的版本根源。
- **飞书**：阅读、协作、导航、审批和面向人的知识门户。
- **ChatGPT Project**：学习互动、项目上下文和任务入口。
- **Memory**：长期稳定个人背景与偏好。
- **Runtime 数据库**：Task、Run、Step、状态和执行事件。

```text
Git 负责可审计正式版本
飞书负责可读与协作
ChatGPT 负责理解、讨论与生成
Memory 负责长期个人背景
Runtime 数据库负责任务状态
```

## 3. 文档类型

- README：目录用途、内容、入口、维护规则。
- Concept Note：稳定概念，不记录临时 UI。
- Capability Card：能力、作用域、输入输出、权限、风险、验证、官方来源。
- Lab：假设、环境、步骤、证据、结果、失败、结论。
- ADR：背景、选项、决定、理由、后果和复审条件。
- Progress：只记录进度，不混入正式概念。

## 4. 事实分类

- **Confirmed**：官方资料或实际实验确认。
- **Observed**：当前账号或设备观察到。
- **Inferred**：根据证据推断。
- **Decision**：项目选择。
- **Todo**：待验证。
- **Deprecated**：已过期。

禁止将推断写成官方事实。

## 6. 更新流程

```text
学习/实验 → 草稿 → 自检 → 人工 review → 合并 Git → 同步飞书 → 标记状态
```

Agent 可以生成草稿，但不能未经 review 将高影响决策标记为 accepted。

## 7. 飞书同步

适合同步：总纲、导航、已 review 概念、架构图、ADR 摘要、实验结论和进度。

不必同步：大量终端日志、临时代码、Secret、未确认推断和机器文件。

飞书页面保留 Git 路径、Commit/版本、更新时间、负责人和状态。

## 8. 每章完成条件

- 核心问题可独立回答；
- 实验执行并保存证据；
- 失败与限制记录；
- 文档 review；
- 项目决策写入 ADR；
- Git 更新；
- 需要的内容同步飞书；
- 下一章依赖清晰。
