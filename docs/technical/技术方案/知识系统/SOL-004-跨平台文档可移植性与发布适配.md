# SOL-004 跨平台文档可移植性与发布适配

## 1. 问题

Git Markdown、Feishu Block 和未来 HTML / Knowledge Pack 的物理格式不同。旧方案把图片放在独立 `knowledge-assets` 分支，通过 `asset://` 解析，导致正文与资源版本分离、Review 不完整、迁移与归档复杂。

## 2. 决策

采用 Document Bundle 与 Human-first、AI-lossless：

```text
Git Document Bundle
├── README.md
└── assets/
    ├── visual.svg
    └── visual.png
```

Git 保存完整可读资产；发布 Adapter 将相对资源转换成目标平台原生媒体。语义一一对应，物理语法不要求相同。

## 3. Git 规范

```markdown
![架构图](./assets/architecture.png)

### AI 可读语义镜像

```text
Interface → Gateway → Runtime
```
```

- 图片必须在当前文档包 `assets/` 内；
- SVG 是可编辑源，PNG 是稳定预览；
- 图片与镜像同步更新；
- 禁止远程图床、独立图片分支、`asset://` 和目标平台链接成为正式源。

## 4. Publisher 流程

1. 读取 Git `README.md`；
2. 解析本地相对图片；
3. 验证图片属于当前文档包并存在；
4. 验证图片后紧邻 AI 可读语义镜像；
5. 生成不含 Markdown 图片节点的文本发布体；
6. 以 overwrite 写入 Feishu；
7. 上传图片并按标题锚点插入 Feishu image block；
8. 回读正文、媒体和 revision；
9. 记录投影状态，但不把 media token 回写正文。

任何图片缺失、锚点不唯一或上传失败都会使发布失败，不允许仅发布文字后声称完成。

## 5. 映射

```text
Git bundle canonical_path
→ Platform Registry asset_id
→ Feishu node_id / projection status
```

一个 Git 文档包对应一个 Feishu 文档节点。资源是文档的组成部分，不建立独立知识真源。

## 6. 兼容边界

- Git/Markdown：本地相对路径；
- Feishu：原生图片块；
- HTML：构建时复制或指纹化资源；
- Custom GPT Knowledge：根据发布包要求嵌入或携带资源；
- 纯文本 Agent：依靠 AI 可读语义镜像无损读取。

## 7. 迁移

首批 10 个正式视觉资产从 `knowledge-assets` 迁入对应文档包，更新 Registry、链接、Hash 和校验器。旧分支策略被 supersede；历史记录保留，但不再参与当前发布。

## 8. 验收

- 文档包本地可完整阅读；
- 资源路径不跨出当前文档；
- 图片和镜像一一对应；
- SVG 无脚本、外部引用或事件处理器；
- PNG 尺寸和 Hash 与 Registry 一致；
- Feishu 投影不需要读取另一 Git 分支；
- 发布目标信息不污染 Git 正文。
