# 08｜失败、误报、被替代结论与工程经验

> 核心问题：哪些“FAIL”不能被继续当作手机模型能力失败？哪些历史结论已经被后续证据替代？

## 1. 失效/误报登记

|---|---|---|---|
| Production Sweet-Spot v2 | 大量 `contract fail` | harness/Contract 泄漏；很多 route tuple 实际正确 | **INVALID-AS-VERDICT** |

## 2. 重要的历史失败仍然是真失败

以下不能因为最终 GO 就抹掉：

- 早期 TSK Context + Vision 在 Approval missing / scope mismatch 上确实语义漂移；
- Sustainable Freeze v2 第三轮确实出现两条 Vision decision invariant 失败；
- 原始 REASON 在 2048 token 下确实出现 `<think>` 未闭合与 final JSON 缺失；
- Native OpenAI `message.tool_calls` 确实没有形成可靠链；
- iPhone 锁屏/后台导致 `server_paused` 是真实运行限制；
- 异模型并发会有 `model_busy`。

最终方案之所以可用，是因为架构和测试逐步吸收了这些失败，而不是这些失败“没发生”。

## 3. 被后续结论替代的早期方案

### 3.1 Gemma 作为生产主模型

被 Qwen no-think FAST + Qwen Thinking REASON 双角色替代。

### 3.2 Qwen3.5-9B + LoRA 作为必经路线

变成未来可选，不再是当前平台前置。

### 3.3 同一 model id 动态开/关 Thinking

被真机否定；改为不同 model IDs / artifacts。

### 3.4 模型自己决定下一步执行

被 Execution Flow Runtime 收敛为：Flow 拥有 transition，模型只返回 data。

### 3.5 Native tool_calls 是 Tool Integration 前置

被 Tool Proposal + Adapter + Policy/Approval + Executor 路线替代。

### 3.6 手机能力验证必须串 BHR/Gateway

被纠正。手机 capability gate 应 mock 其他领域，只真实调用手机算力；平台集成应由各领域 / 跨域验收独立负责。

## 4. 可复用工程经验

1. **先验证 harness，再评价模型。** 任何 real-phone case 前做 schema/preflight。
2. **控制语义和解释标签分开评分。** 安全/控制字段严格；纯 diagnostic taxonomy 不必制造无意义字符串脆弱性。
3. **用专项小 case 修边界，不用一个巨型 Prompt 反复碰运气。** Approval v4、route-target v6 是典型。
4. **Provider 能力不等于模型能力。** native tool parser 失败时，要区分模型 reasoning 与 serving protocol。
5. **压力测试和生产 duty-cycle 分开解释。** 热漂移要记录，但不能脱离真实调度节奏。
6. **容量和工程预算分开。** 128KB recall PASS 不意味着生产默认塞 128KB。
7. **模型置信度永远不升级为权限。** 权限必须由确定性平台事实决定。
