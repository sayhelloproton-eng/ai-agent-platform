## 1. 证据等级解释

```text
L1 真实副作用 / 文件 / Git / Runtime readback
L2 真实设备 API + raw structured output
L3 专项回归 / live gate
L4 综合 benchmark summary
L5 Chat / memory accepted decision
L6 设计 hypothesis
```

当前冻结基线尽量由 L1~L3 支撑；只有路线淘汰原因、Chat 过程和未物化为脚本的阶段判断会使用 L5。

## 2. 冲突处理原则

当两个历史来源矛盾：

1. 先看时间，后证据不自动赢，但可 supersede 早期 hypothesis；
2. 比较 raw evidence，而不是只看 `PASS/FAIL` summary；
3. 区分模型失败、Provider失败、harness失败和 checker失败；
4. 控制/安全字段比解释性 label 更高优先级；
5. Current Truth 只能由已明确接受且有足够证据的后续结论覆盖。
