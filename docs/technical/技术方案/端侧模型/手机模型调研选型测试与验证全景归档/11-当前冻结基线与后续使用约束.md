> 这是本归档的 Current Truth。历史文档与旧测试若与这里冲突，以这里及其对应最新证据为准。

## 1. 当前冻结

### Runtime / Device

```text
iPhone 17 Pro
MLXHub LAN Server
trusted LAN deployment during current experiments
```

物理 IP/端口是部署配置，不是公共合同。

### FAST

```text
sayhelloproton/Qwen3.5-4B-MLX-4bit-no-think
```

状态：**FROZEN / GO**。

适合：高频受约束理解、Task/Node/Evidence candidate judgement、Vision、Approval boundary 初判、结构化输出、allow-listed script/capability selection、普通结果验收。

### REASON

```text
mlx-community/Qwen3.5-4B-MLX-4bit
```

状态：**FROZEN / GO FOR LOW-FREQUENCY ESCALATION**。

适合：证据冲突、状态矛盾、风险元数据冲突、Scope ambiguity、因果恢复诊断、多个候选都无法由 FAST 安全确定的情况。

## 2. 调度

```text
max_inference_concurrency = 1
FAST + REASON share one serial lane per MLXHub backend/device
model switch serialized
failed inference must not poison queue
```

不要引入抢占、并行双模型或分布式调度，除非新证据证明有必要。

## 3. Context / Output

当前工程基线：

```text
preferred context ≈ 12KB
hard context      ≈ 16KB
FAST max_tokens   = 1024
```

128KB recall 是容量证据，不是默认 Prompt 策略。

REASON output budget不作为 Runtime 全局固定常量；按明确 Flow / Provider 配置控制。

## 4. Vision

FAST 为正式 Vision 路径。

支持：

```text
Base64 image_url
HTTP image_url
UI / spatial / color judgement
Approval boundary classification
```

Execution Flow Runtime v0 的 inference input 仍是 JSON/text contract；最终 capability gate 的 Vision 部分有意作为 MLXHub provider-level probe，不偷偷扩 Runtime multimodal schema。

## 8. 不再重复测试的内容

除非 MLXHub / model / device / protocol 有实质变化，不重复：

- native OpenAI tool_calls；
- FAST 31-case 旧集合；
- FAST 20-request platform capability gate；
- REASON 12-request capability gate；
- 单纯为了追求 diagnostic 字符串一致性的 Prompt tuning；
- 把 BHR/Gateway/Approval 串进“手机算力是否胜任”的能力测试。

## 9. 重新打开验证的触发器

只有出现以下条件，才重开对应 gate：

1. MLXHub 版本或 Serving protocol 发生实质变化；
2. FAST / REASON model artifact 或 Chat Template 更换；
3. iPhone / iOS / MLX backend 明显变化；
4. native tools 适配出现新的标准 `message.tool_calls` 支持；
5. 平台增加新的手机职责（例如 Runtime v1 正式多模态 contract）；
6. 生产真实 duty-cycle 与现有测试差异大到需要重新定容量/热稳定门槛。

## 10. Phase 3 长期边界

上层只表达：

```text
need FAST
need REASON
need Vision
need structured output
```

模型与推理 Provider 负责：

```text
physical endpoint
model mapping
health
serialization
provider errors
fallback
```

Execution Flow 负责：

```text
when inference runs
what input is projected
what schema output must satisfy
whether deterministic switch escalates to REASON
```

Task / Agent / Execution / Approval 各自保留自己的状态真源。

## 11. 最终结论

> iPhone + MLXHub + Qwen3.5-4B FAST/REASON 已从“可运行的手机模型”验证到“可作为平台受控推理算力 Provider”。其价值来自明确的边界、确定性 Runtime 和可替换架构，而不是给模型更高权限。
