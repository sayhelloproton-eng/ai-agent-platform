# 测试门禁与真实验收

## D1 — Contract Gate

- `module-contract` TS types compile；
- runtime schemas；
- Result/Error；
- version/compatibility；
- Provides/Requires；
- Config/Lifecycle；
- External Resource version separation。

## D2 — Template + Conformance Gate

至少生成并验证两种不同 Kind：

- library；
- service；
- 再至少一个 external-resource 或 browser-extension。

必须通过 Static/Package/Behavior 三层 Conformance。

## D3 — Platform CLI Offline Gate

使用 fake Modules 验证：

- dependency graph；
- missing dependency；
- config resolution；
- plan immutability；
- plan stale；
- apply resume；
- ACTION_REQUIRED；
- exclusive lock；
- verify history；
- manifest；
- upgrade fail + doctor；
- no automatic rollback。

## D4 — Real External Resource Gate

至少覆盖真实：

- 一个可完全自动管理的 External Resource；
- 一个需要 ACTION_REQUIRED 的 External Resource；
- 一个只可 status/verify、没有 start/stop 的 External Resource。

当前平台优先候选：Dev Tunnel、Chrome、Model API Provider。

## D5 — Cross-domain Deployment Gate

选一套最小真实平台实例，完成：

```text
preflight
→ plan
→ apply
→ services start
→ external resources verified
→ Module verify
→ cross-module verify
→ manifest READY
```

并进行一次 target version upgrade：

```text
old PASS
→ upgrade plan
→ target apply
→ new PASS/FAIL history preserved
```

## D6 — Failure Injection

至少：

- missing config；
- incompatible version；
- external API unavailable；
- Dev Tunnel login required；
- Browser Extension manual action；
- lifecycle failure；
- verify failure；
- stale plan；
- interrupted apply + resume。

## 通过标准

Deployment Domain 不是以“命令退出 0”判定成功，而是以**真实 Module 状态 + Verification + dependency graph + manifest**判定。

---

## 当前正式约束：Conformance 与 E2E 分离

Deployment Conformance 只证明 Module 治理合同，不证明领域业务正确。最终 D5/D6 需要调用各领域 verify 并参加 Cross-domain E2E/Fault Injection；PASS 使用机器可验证 evidence。OpenAI Carrier External Resource 的 Actions/schema/auth/capability 可在真实 E2E 中记录 VERIFIED/PENDING_SPIKE/REJECTED_OR_UNSUPPORTED。

## OpenAI Carrier 实验状态收口

真实 D4/D5 Gate 区分两类：

### 已进入正式合同

```text
openaiFileIdRefs/openaiFileResponse protocol
45s/100k/TLS/443
Action auth
explicit x-openai-isConsequential
no custom headers
File Bridge size/type/header validation
```

### `PENDING_SPIKE`

```text
Always Allow in target role
Multi-Action Worker Turn
Conversation-native file search
Code Interpreter Context Pack/Patch round-trip
```

Spike FAIL 只裁剪对应 Carrier optimization/fallback，不推翻 Task/Agent/Execution/Model Ownership。Multi-Action 若 FAIL，正式 fallback 是 bounded multiple Worker Turns：每 Turn 先重读 owning Domain 最新 facts/version/continuation，并不得重放已成功 Action/Effect。
### File Bridge P0 Conformance 必测

- [ ] `openaiFileIdRefs` >10、单文件 >10MB、aggregate >50MB 分别得到稳定 typed error；
- [ ] fetch 超过 15s、locator 过期、redirect 到 private/localhost/metadata 地址都 fail-closed，且不触发业务 Effect；
- [ ] malicious filename/path traversal、NUL/control chars 被拒绝；declared MIME 与 detected MIME 冲突按合同处理；
- [ ] relay token 只能 GET 指定 artifact/outputRef，TTL=5min；跨 artifact/token scope 使用被拒绝；
- [ ] GPT-facing request/response 都对最终 JSON 做 `<100,000 chars` hard guard：request 达到/超过上限时在进入 owning Domain 前返回 `OPENAI_ACTION_REQUEST_BUDGET_EXCEEDED`；`openaiFileResponse` inline 临界值前 PASS，达到/超过上限时自动改 URL relay，URL 形态仍超限则返回 `OPENAI_ACTION_RESPONSE_BUDGET_EXCEEDED`；
- [ ] relay response 提供 `Content-Type`/`Content-Disposition`，不泄露本地路径/secret；
- [ ] expired locator / fetch timeout recovery 只重试未产生 business mutation 的 transport，已有 Action/Effect 先查 owner facts/idempotency/result，不 blind replay。
