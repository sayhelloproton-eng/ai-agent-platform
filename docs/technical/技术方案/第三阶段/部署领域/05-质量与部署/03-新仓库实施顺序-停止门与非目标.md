# 新仓库实施顺序、停止门与非目标

## 1. 实施顺序

```text
P0-1 module-contract
        ↓
P0-2 module-template
        ↓
P0-3 deployment-conformance
        ↓
P0-4 platform-cli
        ↓
至少 2~3 种真实 Module Kind 验证
        ↓
External Resource Modules
        ↓
Upgrade + verification history
        ↓
P1 module-skill
```

`module-skill` 不允许早于规则和门禁。

## 2. 每阶段 Stop/Go

### module-contract GO

- TS + runtime schema；
- result/error；
- internal + external module examples；
- no unresolved ownership conflict。

### template GO

- library/service/external-resource profiles 可生成；
- `tsc --noEmit`；
- no fake lifecycle。

### conformance GO

- 三层 Gate 可在 CI 运行；
- 能拒绝故意错误 Module。

### platform-cli GO

- fake graph plan/apply 完整；
- ACTION_REQUIRED/resume；
- verify/manifest；
- upgrade；
- no stale state fake READY。

### module-skill GO

- 只调用/生成已冻结 Contract；
- 产物必须通过 Conformance。

## 3. v1 停止门

满足以下就停止继续设计：

- 所有领域正式 Module 可统一治理；
- External Resource 全部可纳入 Module Graph；
- 安装/配置/启动/验证/升级主链稳定；
- 人工步骤可恢复；
- version/verification history 可追踪；
- AI 无需猜测自然语言；
- 平台 READY 不造假。

## 4. 非目标

明确不做：

```text
Deployment daemon/service
SQLite Deployment DB
Workflow/Scheduler/Lease/Worker
Docker/K8s
Marketplace/Plugin Registry Service
Dynamic npm world discovery
Distributed lock
Fleet management
Canary/blue-green rollout
Automatic transactional rollback
Vault/Secret Service
Full observability platform
Complex Deployment UI
```

未来只在真实需求出现时增加。
