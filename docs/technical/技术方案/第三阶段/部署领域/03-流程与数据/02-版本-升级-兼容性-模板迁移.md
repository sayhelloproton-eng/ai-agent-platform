# 版本、升级、兼容性与模板迁移

## 1. 版本维度

v1 仅保留必要维度：

1. `moduleVersion`：内部 package 或 external adapter 版本；
2. `moduleContractVersion`；
3. `templateVersion`；
4. `platformCompatibility`；
5. Provides/Requires contract version；
6. External `resourceVersion?`（动态事实）。

不建设第二套独立“Deployment Version”体系。

## 2. Upgrade 是 v1 P0 能力

原因：五个 Deployment 基础包就是为了让后续各领域 npm 包、服务和外部资源长期可统一管理、测试、升级。

## 3. Upgrade Plan

```text
Installed / Current Reality
→ Target Module Set/Versions
→ Contract Compatibility
→ Provides/Requires Compatibility
→ Template Migration requirement
→ Conformance evidence
→ Config Migration
→ External Resource Actions
→ Data Migration primitive（若领域提供）
→ stop/start ordering
→ verify
```

## 4. Data Migration

数据库/schema migration 归数据 Owner 领域实现。Deployment 只：

- 识别 migration requirement；
- 计划调用公开 migration primitive；
- 安排顺序；
- 记录结果；
- verify。

## 5. Template Migration

Template 升级不等于 Module package upgrade。

若旧 Template 仍满足 Contract/Compatibility/Conformance，可以继续使用。

强制迁移条件必须明确，不因“有新模板”就大规模重写。

## 6. Verification History

按版本保留：

```text
module 1.0.0 PASS
module 1.0.1 FAIL
module 1.0.2 PASS
```

External Resource 没有传统版本时，以 adapterVersion + resource identity/config fingerprint 建立 Verification Record。

## 7. Rollback

v1 不做自动事务式 rollback。

Upgrade verify fail：

```text
STOP
→ 记录 FAIL
→ doctor
→ 生成 repair 或 target-old-version Plan
```

这样足够稳定且避免复杂补偿引擎。
