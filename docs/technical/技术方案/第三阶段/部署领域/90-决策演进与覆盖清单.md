# 决策演进与覆盖清单

## 1. 早期草案保留项

旧 Deployment 草案中以下方向继续有效：

- Domain → Subdomain → Bounded Context → Module；
- AI-native Deployment；
- “智能在 AI，确定性在 CLI”；
- module-contract / module-template / deployment-conformance / platform-cli / module-skill；
- structured JSON + stable error；
- Module 自描述；
- preflight/status/verify/doctor；
- Version Verification Records；
- Manifest 由真实状态生成；
- Template + Contract + Conformance 长期治理。

## 2. 被后续讨论覆盖的旧结论

### A. “每个 npm package 都是可部署单元” → 覆盖

新结论：所有正式 npm package 都是 Module Governance 对象，但只有真实运行/部署生命周期的才是 Deployment Unit。

### B. “模块自己完整 install/configure，Platform CLI 只透传” → 覆盖

新结论：Module 暴露 requirements/config/lifecycle primitives/verification/effects；Platform CLI 负责实例级 dependency graph、plan 与 apply。模块不自己决定整个平台拓扑。

### C. “通过 npm Scope 动态发现世界上的 Platform Module” → P0 收敛

新结论：v1 只处理平台目标/已知 Module Set；不建设 Marketplace、Registry Service 或全网动态发现。

### D. “外部资源只是 Requirement/Config” → 明确否定

新结论：所有外部资源必须成为 External Resource Module，通过 Adapter 纳入同一治理链。

### E. “Deployment 要 SQLite” → 最终否定

讨论中一度考虑 SQLite 用于 upgrade/plan/history，但用户理解原因后最终确认 v1 不需要 SQLite；repo-local files 足够。

### F. “Deployment 不需要五个包” → 明确否定

五个包全部是长期治理基础设施，必须保留。

## 3. 最终冻结主轴

```text
五包治理
+ Module 统一模型
+ External Resource Module 强制
+ Package != Deployment Unit
+ Platform Plan/Apply
+ ACTION_REQUIRED Resume
+ Version/Upgrade/Template Migration
+ Verify/Doctor/Manifest
+ repo-local file state
+ no overdesign
```
