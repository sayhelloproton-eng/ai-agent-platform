## 4. Domain Gates

- D1 Contract Gate：Module Contract TS/runtime schema/version/config/lifecycle/external-resource separation。
- D2 Template + Conformance：至少 library + service + external-resource/browser-extension profile，C1/C2/C3。
- D3 Platform CLI Offline：fake graph、missing dependency、plan/apply/ACTION_REQUIRED/resume/verify/manifest/upgrade。
- D4 Real External Resource：可自动管理、ACTION_REQUIRED、status/verify-only 三类。
- D5 Cross-domain Deployment：preflight→plan→apply→services/external resources→verify→manifest READY + upgrade history。
- D6 Failure Injection：missing config/version/resource unavailable/manual action/lifecycle/verify/stale plan/interrupted apply。

## 5. Domain Test Responsibility

- Domain Behavior：只证明本领域状态/invariant/idempotency/concurrency/error/recovery。
- Contract：Provider + Consumer 双侧，runtime schema 不能只靠 TS type。
- Integration：尽量使用真实 storage/serializer/schema/adapter；昂贵外部依赖才 fake。
- Real Acceptance：如果被验收能力就是 Browser/Carrier/Local Effect/Model/External Resource 本身，则不能只 Mock。
- Conformance：只证明平台治理结构，不替代 Domain PASS。
