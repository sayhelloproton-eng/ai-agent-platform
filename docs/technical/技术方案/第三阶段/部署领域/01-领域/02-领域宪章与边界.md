# 领域宪章与边界

## 1. Charter

Deployment Domain 是平台的软件落地与运行装配层，也是所有平台 Module 的统一工程治理入口。

它回答六个问题：

1. 这个东西是不是平台认可的 Module？
2. 它需要什么、提供什么、怎么配置？
3. 当前实例应当安装/连接/启动哪些 Module？
4. 应以什么顺序、什么 effects 完成部署或升级？
5. 当前真实环境是否可用？
6. 后续如何保持模块版本、模板和部署合同一致？

## 2. AI 与 CLI

AI：理解目标、解释 Plan、协助填写配置、请求人工确认、读取结构化结果、总结。

CLI：确定性 dependency resolution、plan/apply、lifecycle invocation、verify/doctor、状态与记录持久化。

AI 不应在存在 Platform CLI 能力时自行临时编写替代部署 Shell。

## 3. 与四领域边界

### Task & Orchestration

Deployment 只负责安装/升级 Task 包、配置 store/migration prerequisites、调用公开 verify。Task 状态机、Node、Task 文档不归 Deployment。

### Agent Runtime & Collaboration

Deployment 管 Agent Package、Gateway 运行单元、ChatGPT Carrier 外部资源和注册所需配置/人工步骤；Role/Worker/Conversation/Message Center 业务事实归 Agent。

### Execution

Deployment 管 Execution Runtime、Browser Extension、Chrome 外部资源等的安装/启动/verify；Execution Policy、Effect、Evidence、UNKNOWN_SIDE_EFFECT 归 Execution。

### Model & Reasoning

Deployment 管 Model Runtime 与 FAST/REASON Provider External Modules 的配置、可达性和调用 Model verify；推理路由、Reasoning Spec、Capability Proposal 归 Model。

## 4. 硬边界

- 不把 Logical Service 自动等价成 Process。
- 不让 Deployment 重新定义其他领域业务 Contract。
- 不让外部资源绕过 Module Governance。
- 不让 Module Skill 绕过 Conformance。
- 不让 `state.json` 代替实时 status/verify。
- 不让 doctor 偷偷 repair。
- 不为升级提前建设复杂 rollback engine。
