# 部署领域｜当前设计原则与不变量

## 1. 五包长期治理基础

```text
@ai-agent-platform/module-contract
@ai-agent-platform/module-template
@ai-agent-platform/deployment-conformance
@ai-agent-platform/platform-cli
@ai-agent-platform/module-skill
```

Deployment Domain 不建立常驻 daemon。

## 2. 工程单元不混淆

```text
Package != Module != Service != Process != Deployment Unit
```

所有正式平台 npm package 都进入 Module Governance；只有真实具备独立生命周期的对象才是 Deployment Unit。

## 3. Module 与 Platform Planner 分工

Module 声明 requirements、Provides/Requires、config slots、真实 lifecycle primitives、verify/doctor 能力与 effects；`platform-cli` 负责实例级 dependency graph、preflight、plan、apply、resume 与整体状态聚合。

Module 不自己决定整个平台拓扑。

## 4. Module Set

v1 处理平台目标中已知/已安装的 Module Set；不建设 Marketplace、Registry Service 或全网 npm Scope 自动发现体系。

## 5. External Resource Module

ChatGPT Carrier、Chrome Runtime、Dev Tunnel、Model Provider 等所有外部资源都必须通过对应 External Resource Module/Adapter 进入同一 Module Graph；不能仅作为散落 Requirement/Config。

## 6. Deployment State

v1 不使用 Deployment SQLite。计划、版本、验证、manifest、ACTION_REQUIRED 等状态使用 repo-local structured files，统一位于 `.ai-agent-platform/deployment/**`。

## 7. Plan / Apply / ACTION_REQUIRED

install/configure/upgrade/repair 都是 Plan Intent。apply 必须按依赖顺序执行确定性步骤；遇到必须由人/Web 完成的动作返回 `ACTION_REQUIRED`，保留同一 `planRef`，恢复后重新观察 reality 并跳过已满足步骤。

## 8. Lifecycle 真实性

External Resource 或 Library 不支持 start/stop 时禁止伪造 lifecycle verb。Deployment 只调用 Module 真实声明的能力。

## 9. Verify / Doctor / READY

Platform READY 必须综合版本、配置、依赖、Runtime、真实 verification、cross-module compatibility 和 blocking ACTION_REQUIRED；缓存状态或一次历史 PASS 不能代替当前 reality。

## 10. Upgrade / Template

Upgrade 是 v1 P0。Template version 变化不自动强迫所有 Module 立即迁移；只有 compatibility/conformance 明确要求时才产生 migration requirement。数据 schema migration 逻辑由数据 Owner Domain 实现，Deployment 只计划和调用公开 migration primitive。

## 11. GPT / Carrier 配置

Custom GPT 创建/编辑保持 Web-only；Deployment 通过 `ACTION_REQUIRED_WEB` 引导。Role READY 按 Actions schema、auth、required carrier capability 与真实 E2E behavior 判断，不 pin exact model id。
