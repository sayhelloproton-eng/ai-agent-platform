# 05｜包、模块与代码边界约定

> 状态：FROZEN  
> 目标：让领域边界能够在 monorepo、npm package、Application、Adapter 和未来独立部署中保持一致。

---

# 1. 逻辑层级

Phase 3 统一使用以下逻辑：

```text
Platform
→ Domain
→ Bounded Context
→ Module
→ Package / Process / Adapter（按需要）
```

不是每个 Bounded Context 都必须单独 npm package。

不是每个 Module 都必须单独进程。

DDD 边界和物理部署边界：

```text
相关，但不强制一一对应
```

---

# 2. Package 必须有 Owner

每个 Package / Module 必须能回答：

```text
domainOwner
moduleName
public surface
internal surface
```

禁止：

```text
无 Owner 的 common
无 Owner 的 utils
无 Owner 的 platform-core
```

如果一个 package 被多个领域消费：

```text
必须说明它是：
- 稳定 Shared Kernel
- Infrastructure
- Protocol Adapter
- Tooling
```

不能因为“大家都用”就默认公共。

---

# 3. Public Export

跨 package / 跨领域依赖：

```text
MUST 通过明确 Public Export
```

例如 package 应通过：

```text
exports
index.ts
public.ts
```

定义 Public Surface。

禁止消费者依赖：

```text
@pkg/src/internal/...
@pkg/dist/private/...
../../other-domain/src/...
```

---

# 4. Internal

领域内部：

```text
internal/**
```

或等价结构：

```text
MUST NOT 被其他领域 import
```

即使 TypeScript 路径能访问，也视为架构违规。

后续 SHOULD 用：

```text
package exports
lint rule
dependency conformance
```

自动阻止。

---

# 5. 依赖方向

允许：

```text
Domain Internal
→ 自己的 Public Contract

Application
→ 多 Domain Public

Adapter
→ 自己 Domain Port + 外部 SDK

Domain
→ Approved Shared Kernel
```

禁止：

```text
Domain A Internal
→ Domain B Internal

Domain A
→ Domain B Adapter implementation

Domain
→ UI / BFF

Domain
→ Deployment implementation
```

如果业务需要反向调用：

```text
定义 Public Port / Contract
```

而不是反向 import 实现。

---

# 6. Contract 与实现分离

Public Contract SHOULD 尽量能在不加载 Provider 实现的情况下引用。

例如：

```text
execution-contract
```

可以独立描述：

```text
ExecutionRequest
ExecutionResult
ExecutionError
```

但不能依赖：

```text
Playwright
Chrome Extension
Local Shell
```

这些属于 Adapter / implementation。

是否拆成独立 package 要看真实消费者，不在 v0.1 强制。

---

# 7. Adapter 组织

推荐逻辑：

```text
Execution Domain
├── core
├── public
└── adapters
    ├── browser
    ├── local
    ├── mcp  # future / non-v1 adapter slot；Execution v1 不使用 MCP 主执行链
    └── remote
```

模型领域类似：

```text
Inference
├── core
├── public
└── providers
    ├── mlxhub
    ├── openai
    └── ...
```

具体目录可以不同，但语义边界必须一致。

---

# 8. Application 层

Application 可以编排多个领域：

```text
controller-app
management-backend
gateway-app
```

Application：

```text
MAY 依赖多个 Domain Public API
MAY 处理 transport/auth/session 等应用问题
MAY 聚合 read model
```

但：

```text
MUST NOT 定义领域业务状态机
MUST NOT 拥有跨域共享业务表
MUST NOT 绕过领域 Public API 写内部数据
```

---

# 9. Presentation

前台 / 后台：

```text
按用户用例组织
```

而不是强制：

```text
一个领域 = 一个页面
```

后台导航可以接近五领域：

```text
任务
Agent
执行
模型
部署
```

但 UI 模块不是 Domain。

---

# 10. npm 命名

v0.1 冻结逻辑规则，不冻结最终 npm scope。

必须满足：

```text
Package 名可唯一定位用途
可判断 Owner
禁止同义乱命名
禁止 package 名承担运行时状态语义
```

在最终 scope 确认前，文档统一用逻辑名：

```text
<domain>/<module>
```

例如：

```text
task/workflow-runtime
agent/collaboration-runtime
execution/browser-adapter
inference/mlxhub-provider
deployment/module-contract
```

最终 npm 映射由后续 Package Convention 具体化，但不得破坏逻辑 Owner。

---

# 11. Shared Kernel

Shared Kernel 第一原则：

> 不提前创建“大公共包”。

允许进入 Shared Kernel 的候选：

```text
真正跨域且语义稳定的：
Ref primitive
Correlation primitive
Contract Version primitive
Event Envelope primitive
```

但只有真实多领域消费者出现后才能实现。

Shared Kernel 禁止包含：

```text
TaskStatus
ExecutionStatus
AgentRole
ProviderStatus
DeploymentStatus
某领域 Error Code
某领域 Repository
某领域 Service
```

---

# 12. 工程配置

Phase 3 SHOULD 尽量共享：

```text
TypeScript baseline
formatter
lint baseline
test runner baseline
build convention
```

但这些配置属于工程基础设施，不应反向约束领域模型设计。

如果某领域有真实技术原因偏离：

```text
允许偏离
必须记录原因
```

---

# 13. Generated Artifact

生成代码 / Schema / Client：

```text
MUST 可追溯到 Source of Truth
SHOULD 可重复生成
MUST NOT 手工维护生成物与源定义的双份真源
```

例如：

```text
JSON Schema
→ generated TypeScript
```

则 Schema 或 TypeScript 必须明确谁是真源。

禁止两个方向同时手改。

---

# 14. 配置与 Secret

配置：

```text
属于模块 / Runtime
```

Secret：

```text
MUST NOT 写入源码 Contract
MUST NOT 进入 Public Event
```

跨域如需 Secret 使用：

```text
credentialRef
secretRef
```

具体 Secret Store 后续再设计。

---

# 15. 循环依赖

代码级跨领域循环依赖：

```text
MUST NOT
```

如果出现：

```text
Task package → Agent package
Agent package → Task package
```

优先解决：

```text
提取 Public Contract
使用 Port
使用 Event
由 Application 组装
```

不要通过：

```text
dynamic import
require hack
复制类型
```

掩盖架构循环。

---

# 16. Conformance 方向

后续 SHOULD 自动检查：

```text
跨域 internal import
未声明 dependency
Public export 越界
循环依赖
无 Owner package
Shared Kernel 非法依赖
```

但 v0.1 首先以文档和 Review 为 Gate，待五领域真实目录稳定后再机器化。

---

## 当前正式约束：Package / Module / Service / Process

Package=发布边界；Module=Deployment治理单元；Service=逻辑服务；Process=OS进程；Deployment Unit=真实生命周期单元，五者禁止混同。所有正式平台 npm package 纳入 Module Governance，但 library 不伪造 daemon lifecycle。contracts package 保持薄；跨 package 只通过显式 exports，禁止 `src/**/internal` 深路径依赖。
