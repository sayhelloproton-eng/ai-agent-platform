# 测试证据与停止门

## 1. Evidence 分级

发布/实施状态必须区分：

```text
Implemented
Contract Verified
Domain/Module Verified
Integrated
E2E Verified
Real Environment Verified
Production Hardened
```

禁止 `Unit PASS → Production Ready`。

## 2. 机器可验证 Evidence

计划要求至少能产出：结构化 test result、contract/schema validation、持久化/owner fact snapshot/ref、Execution Record/Evidence、必要的 browser screenshot、real environment observation、failure/recovery trace。具体文件名/命令留到开发后 Test Case 阶段。

## 3. 全局 STOP

- 任一关键 Public Contract 不一致；
- 发现未知副作用状态但无 reality verification；
- 实现需要修改已冻结 Owner/State/Contract 才能通过测试；
- Test Plan 要求的 observable evidence 在设计中不存在；
- 外部行为与冻结假设冲突且 fallback 不成立；
- flaky critical test 只能靠无限 rerun 变绿；
- 测试污染真实账户/环境且无清理策略。

## 4. SPEC_GAP 处理

`SPEC_GAP` 不是失败测试，也不是允许 Codex 自己补设计。它是“开发前最后门”发现的规格缺口：阻断正确实现则 STOP + Contract/Design Change；不阻断则明确 PENDING_DECISION/PENDING_SPIKE 与 fallback。
