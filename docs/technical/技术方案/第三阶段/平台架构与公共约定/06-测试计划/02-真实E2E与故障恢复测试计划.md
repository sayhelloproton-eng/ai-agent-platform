# 真实 E2E 与故障恢复测试计划

## 1. 只验证 Phase 3 新/改变的真实语义

不为了“测试很多”重复证明旧链路；真实 E2E 聚焦 Phase 3 的新 Domain Contract、Agent/Carrier、Execution unified semantics、Model Router、Deployment Module Governance 与 recovery。

## 2. 最终真实主链

```text
product Worker exists
→ create Task
→ human authorization
→ provision/bind dev + test Workers
→ start Task / Node
→ WAKE target Worker
→ Actions / File Bridge（按需）
→ Model cognition（按需）
→ Execution real Effect / Evidence
→ Task owner formal transition
→ Collaboration delivery（按需）
→ Test Worker verification
→ complete / wait / reopen / resume
```

## 3. 必须破坏的故障族

- runtime restart / process crash；
- Extension reload / Content Script reload/navigation / Chrome restart；
- runtime↔extension disconnect；
- command received before effect disconnect；
- effect_started 后 disconnect；
- result/reply lost；
- model timeout / provider unavailable；
- version conflict / duplicate request；
- File Bridge locator expired / fetch timeout / relay expired；
- External Resource ACTION_REQUIRED / verify failure；
- persisted state stale 与 current reality 不一致。

## 4. 核心不变量

- 未确认的真实副作用绝不 blind retry；
- existing Worker 不 duplicate CREATE；
- stale ONLINE/old content instance 不冒充当前 reality；
- Task/Agent/Execution/Deployment 各自只修改自己的事实；
- recovery 先重读 owner facts/current reality；
- terminal Task 不产生新 collaboration/wake；
- PENDING_SPIKE 失败只回落 fallback，不推翻领域 ownership。

## 5. Real Environment

Browser/Carrier 必须真实 Chrome + ChatGPT Web；Local Effect 必须真实临时项目/进程；Model M2/M4 必须真实部署模型 API；Deployment D4/D5 必须真实 External Resource。Mock 仅用于故障注入和低层隔离。
