# 任务与编排领域｜设计决策记录与明确非目标

> 用途：防止后续 Chat / 实现者把已经否决的设计重新带回来。

---

# 1. 设计方法

用户明确要求：第一版满足真实需求即可、不要过度设计、时间有限、避免 Phase 2 式反复返工。

任何新增实体 / 状态 / 服务 / 包都必须回答：

> 当前第一版哪个真实需求没有它就无法完成？

答不出来，则不加入。

---

# 2. 已确认：领域独立但载体无关

Task Domain 有自己的状态 / API / Service / Store，但只通过 opaque refs 对接 Agent / Execution。当前 Custom GPT / Conversation 只是 Agent Domain 的一种载体，Task Domain 不依赖 ChatGPT URL 格式。

---

# 3. 已确认：Role 与 Worker 分开

```text
Role = 资格 / 角色要求
Worker = 具体 Custom GPT Conversation / 执行实例；`Session` 仅是历史或外部运行时措辞，不建立 Agent Session business entity
```

Task Node 保存 `requiredRoleRef / workerRef`。Role 不是全局锁。

---

# 4. 已确认：Task Context 与 Role 固定 Context 分开

Role 固定 Context 是职责 / 方法 / 系统提示 / 工作规范；Task Context 是 Requirement / PRD / Technical Design / Test Plan / Test Result。Task 文档随 taskId 走，不写进 Role 长期 Memory。

---

# 5. 已删除：WorkItem

曾考虑 `Node → WorkItem → Claim`，已明确删除。

原因：串行 Node、单 Node 单具体 Worker、没有 Node 并行、没有 reassign、没有 worker queue。

未来触发条件：一个 Node 同时拆多个真实子工作、一个 Node 多 Worker 并行、独立工作队列、复杂 retry/lease。

---

# 6. 已删除：Claim

第一版没有 Claim entity / table / state / API。`startNode` 原子绑定 workerRef。

未来出现抢占 / Lease / 重新分配 / 多 Worker 争抢再设计。

---

# 7. 已删除：并行 Node

第一版 Workflow 是有序串行 Node。现实前端 / 后端并行仍归“研发 + 项管”一个 Node。未来真实需要多 Worker 并行再升级。

---

# 8. 已删除：通用循环引擎

不做 A → B → C → A 静态回边 / 自动无限循环。替代机制是 `reopenNode`；Node 内业务多轮讨论由 Worker 自己处理。

---

# 9. 已确认：reopen

reopen 前序 Node：target runNo + 1、target READY、target workerRef null；later Nodes PENDING / workerRef null；history preserved；documents preserved；Task ACTIVE；currentNodeId = target。

这是第一版流程回退唯一正式机制。

---

# 10. 已确认：PAUSED 只在 Task 层

不逐个 Node IN_PROGRESS → PAUSED。Task PAUSED 是全局协作闸门，Node 保持当前状态。

---

# 11. 已确认：WAITING 是整 Task 停

任何 WAITING 都使 Node WAITING + Task WAITING + Message required。

---

# 12. 已确认：FAILED 可恢复

FAILED != TERMINATED。技术失败修复后可以 reopen。

---

# 13. 已确认：终止

统一中文“终止”，技术 enum `TERMINATED`，不使用 CANCELLED 作为主语义。终止不可恢复。

---

# 14. 已确认：普通 Node 没有审批

Worker 完成 + required output docs 存在 → SUCCEEDED → next READY。

人工介入只在 Task / TaskGroup start、业务明确确认、Action permission、Browser / Execution abnormal / risk。

---

# 15. 已确认：Markdown + Git

Task 文档正文 = Markdown / Git history；SQLite = 状态 / 索引 / path / hash。不建立 DB 正文副本。

---

# 16. 已确认：平台专有工作目录

平台自己的 Task working documents / state / logs / cache 等统一收敛在 `.ai-agent-platform/**`。目标仓库可以迭代一个或多个产品，与 Task Domain 方案无关。

---

# 17. 已确认：CodeGraph 不是业务存储

`.codegraph/codegraph.db` 是可重建代码索引，不是 Task DB。

---

# 18. 已确认：SQLite

第一版 SQLite + sqlite3@6.x + raw SQL + WAL。不使用 PostgreSQL / Redis / ORM / Kysely / Drizzle / Prisma。

原因：老 Mac、Node 20、少 daemon、低运维成本、当前表数量小。

---

# 19. 已确认：不用 XState / Temporal / DBOS

当前状态机足够简单。未来出现复杂 DAG / durable distributed workflow / multi-host scheduler 再评估。

---

# 20. 已确认：Event Store 不独立

TaskEventRepository 暂时属于 `@ai-agent-platform/task-store-sqlite`。未来多个领域真实共享 append-only journal 后再抽。

---

# 21. 已确认：Migration 包带 task 前缀

当前 `@ai-agent-platform/task-migration-runner`，不是 `@ai-agent-platform/migration-runner`。没有第二个真实消费者，不提前抽公共包。

---

# 24. 仍留给后续实现细化

以下不是重新讨论领域模型的问题：最终 HTTP path、具体 class / function 文件名、完整 Error Code 枚举、日志格式、具体 config key 名、SQLite driver wrapper 细节、Migration filename convention、测试文件目录、具体 `.ai-agent-platform` 子目录名。

只要不改变本文语义，可在实现时决定并回写文档。
