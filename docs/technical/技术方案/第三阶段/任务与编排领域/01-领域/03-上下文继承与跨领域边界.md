# 任务与编排领域｜上下文继承与跨领域边界

## 1. Task 是长期工作事实真源

Task Domain 只保存流程和长期业务事实，不拥有具体 Agent Carrier、Browser 页面现实、Model Runtime 或 Deployment lifecycle。

## 2. 与 Agent Domain

Task 持有 opaque `roleRef / workerRef` 与 `TaskRoleBinding`，但不解析 g-id/c-id 格式、不读取 Role Registry、不拥有 Conversation lifecycle。

```text
Agent owns: Role / Worker identity / logical collaboration
Task owns: TaskRoleBinding / Node / workflow
```

Task 创建可以携带产品已有 role+worker，以及研发/测试 role 空绑定；执行授权后通过 Agent + Execution provisioning 得到研发/测试 Worker，再由 Task Public Contract one-time 绑定。

## 3. 与 Execution Domain

```text
Task owns: what work should progress
Execution owns: whether/how a real effect was performed and what evidence exists
```

Browser CREATE/RESTORE/WAKE、permission、screenshot、submit、delivery、recovery 都属于 Execution。Browser 不直接写 Task Store；任何 Task 状态推进都必须调用 Task Public Command。

Business `WAITING/FAILED/TERMINATED` 与 Execution `UNKNOWN_SIDE_EFFECT` 是不同状态空间。Execution 不确定副作用不得被映射成 Task 自动重试。

## 4. 与 Model Domain

Task 可以通过公开推理合同请求认知结果，但 Model 不反向读取 Task DB；Task/调用方组装必要 context。模型输出不是 Task 状态变更授权。

## 5. 与 Deployment Domain

Deployment 负责 Task packages/store/migration prerequisites 的安装、配置、verify/doctor/upgrade；不拥有 Task state machine 或 TaskDocument 内容。

## 6. 与 platform-host

`platform-host` 只做 composition root、依赖注入、本地 transport 和轻量 health aggregation。Task package 不依赖 platform-host；platform-host 依赖并装配 Task package。

## 7. ref 与数据边界

- 跨域只传 Public Contract 中定义的 opaque ref 与 DTO。
- 禁止共享 SQLite 表、Repository、内部 Adapter 或 deep import。
- 任何跨域 mutable fact 只有一个 owner；其他领域只能缓存可丢弃 projection，不能形成第二真源。

## 8. 失败隔离

Agent/Execution/Model/Deployment 依赖失败必须通过 typed error / status 显式返回；Task 只根据自己拥有的业务语义决定 WAITING、FAILED、继续或恢复，不能借依赖失败私自改写其他领域状态。
