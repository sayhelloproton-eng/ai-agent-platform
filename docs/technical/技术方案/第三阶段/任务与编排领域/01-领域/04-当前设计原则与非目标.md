# 任务与编排领域｜当前设计原则与 v1 非目标

## 1. 第一版设计准则

第一版只实现真实需求和稳定性所必需的模型。任何新增实体、状态、服务或包必须回答：**没有它，哪个当前真实需求无法完成？** 无法回答则不加入。

## 2. Carrier 无关

Task Domain 拥有自己的状态、API、Service 与 Store，只通过 opaque `roleRef / workerRef / executionRef / modelRef` 对接其他领域。Custom GPT / Conversation 是 Agent Domain 的当前 Carrier，不进入 Task Domain 的身份格式和生命周期设计。

## 3. Role 与 Worker 分离

```text
Role = 当前 Node 所需角色资格
Worker = Task 内已绑定的具体执行人员/Conversation
```

Node 保存 `requiredRoleRef`，运行时 `workerRef` 必须由 `TaskRoleBinding` 解析。调用方不得在 `startNode` 任意指定 Worker。

## 4. Task Context 与 Role 固定 Context 分离

Role 固定 Context 只包含职责、方法、系统提示和稳定工作规范；Requirement、PRD、Technical Design、Test Plan、Test Result 等动态材料属于 TaskDocument，随 `taskId` 管理。

## 5. v1 明确不建立的调度实体

- 不建立 WorkItem。
- 不建立 Claim / Lease。
- 不建立并行 Node。
- 不建立通用 DAG / Edge Engine。
- 不建立自动无限 Loop Engine。
- 不建立独立 Scheduler / Queue 服务。

当前 Node 就是最小业务调度单元；流程回退统一使用 `reopenNode`。

## 6. reopen 的正式语义

reopen 到前序 Node 时：

- target `runNo + 1`；
- target 回到 `READY`；
- target 使用该 Task 原角色绑定 Worker；
- later Nodes 重置为 `PENDING`；
- 既有 execution history 与 documents 保留；
- Task 回到/保持 `ACTIVE`；
- `currentNodeId = target`。

## 7. Task / Node 状态原则

- `PAUSED` 只属于 Task 级协作闸门，不要求把当前 Node 改造成 PAUSED 状态。
- Node `WAITING` 必须同时让 Task 进入 `WAITING`，并写入可供恢复的 Message/原因。
- `FAILED` 是可恢复技术失败，不等同于终止。
- `TERMINATED` 是不可恢复业务终态；主语义不使用 CANCELLED。
- 普通 Node 没有人工审批门；Worker 完成且 required outputs 满足后即可成功推进。

## 8. 文档与状态存储

- Task 文档正文：Markdown + Git。
- SQLite：Task/Node/Binding/Message/Event/Document metadata、版本、索引、幂等记录。
- 不在 SQLite 再复制一份 Markdown 正文。
- 平台自身状态、文档、日志、缓存收敛到 `.ai-agent-platform/**`。
- 可重建代码索引不是 Task business store。

## 9. SQLite 技术边界

v1 使用 SQLite + raw SQL + WAL；不引入 PostgreSQL、Redis、ORM、Temporal、DBOS、XState。事务、乐观版本、幂等与约束直接服务当前小规模串行状态机。

## 10. Event 与 Migration 边界

- Task Event 持久化由 Task Store 承担，不抽全平台 Event Store。
- Task schema migration 使用 `@ai-agent-platform/task-migration-runner`，不提前抽通用 migration service。

## 11. 正式工程单元

```text
@ai-agent-platform/task-orchestration
@ai-agent-platform/task-store-sqlite
@ai-agent-platform/task-migration-runner
```

业务公开服务由 `task-orchestration` 承载：`TaskCommandService / TaskQueryService / TaskDocumentService`。

## 12. 只有真实触发器出现才升级

| 真实需求 | 才允许重新评估 |
|---|---|
| 一个 Node 多 Worker 并行 | WorkItem / parallel node |
| Worker 抢占、租约、重新分配 | Claim / Lease |
| 动态条件图 | DAG / Edge Engine |
| 自动复杂回环 | Loop Engine |
| 多机调度 | Queue / Scheduler / PostgreSQL |
| 多领域共享 append-only journal | 公共 Event Store |
| 多领域共享 migration | 公共 migration-runner |
| 跨 Task embedding / retrieval | 独立知识检索能力 |
| API 必须读取文档版本树 | Document version service |
