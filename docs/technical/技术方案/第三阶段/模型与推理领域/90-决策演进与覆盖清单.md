# 90 · 决策演进与覆盖清单

本文件记录本 Chat 在 Model & Reasoning Domain 讨论中出现的重要修正。后续看到旧说法时，以这里的最终覆盖关系为准。

## 1. 领域定位

**最初方向**：模型接入 + FAST/REASON。

**最终**：提升为平台认知计算层，提供可依赖算力；拥有模型接入、推理路由、Reasoning Spec、结构化输出、Runtime Health 与推理可观测；不拥有 Task/Agent/Execution/Approval。

## 2. 旧 MVP 影响规则

用户明确纠正：领域设计不能受上传 MVP 包已有内容影响。

最终：**greenfield-first**；旧 MVP 只有在领域冻结后才做 reuse audit。

本冻结包未以 `experiments.zip` 作为领域架构输入。

## 3. Provider Adapter

**被覆盖**：将 Provider 具体理解为 MLXHub、LAN endpoint、手机模型资源。

**最终**：Provider Adapter 必须是通用 API Adapter。手机/MLXHub 只是某种部署实现。FAST/REASON 可映射本地或远端 API。

## 4. FAST/REASON 能力约束

**最终新增**：thinking/no-thinking、image、structured output、context/output limit 是稳定性约束，不是可选 metadata。

## 5. Vision

**被删除**：独立 Vision 模型角色/服务。

**最终**：Vision = input modality；`FAST + image` / `REASON + image`。

## 6. Tool Calling

**被覆盖**：简单说“Model v1 不支持工具”。

**最终更准确**：v1 不依赖 API 原生 tool_calls；平台需要工具意图时，模型以结构化 Capability Proposal 输出，中间控制层校验后交 Execution 真实执行。

## 7. 小模型输入输出

用户明确要求：部署是小模型，不足以依赖开放式智能；输入输出必须有明确格式规范。

**最终**：正式引入版本化 Reasoning Spec；控制型推理使用 `specRef + typed payload`、固定 instruction、固定 schema、有限 vocabulary、runtime validation。

## 8. Capability Proposal

最终限制：

- 只能从输入候选中选择；
- 一个 inference 最多一个；
- typed args；
- 不能执行；
- 不能携带 secret；
- 不能绕过 Execution；
- 由调用领域控制有限 maxRounds。

## 9. 单 Lane

物理起因来自手机小模型实测，但最终提升为 **v1 平台稳定性策略**；即便换远端 API 仍单 Lane。

## 10. Queue

最终只保留 `business/background`；不做持久化、不做多优先级、不抢占已开始推理。

## 11. Runtime 数据

**没有复制 Execution Record**。

最终：queue/active memory-only；历史 structured disk logs。原因：inference 无真实 side effect。

## 12. Retry/repair

最终：transport 最多一次安全 retry；structured output 最多一次 bounded repair；无无限 self-loop。

## 13. Chain-of-Thought

最终：不要求、不依赖、不持久化长 CoT。只要 decision/confidence/reasonCode/短 rationale。

## 14. Model Capability Verification

最终：API 返回 200 不等于角色 READY；必须真实验证 declared capabilities。Deployment 执行 verify/doctor，Model Domain 定义合格标准。

## 15. 包/服务数量

最终冻结：

```text
model-contracts
model-runtime
```

2 包 / 1 服务 / 6 内部模块。

## 16. 防过度设计

用户再次明确：满足需求和稳定性就够，不要过度设计。

最终删除/禁止 v1：

```text
Prompt Service
Tool Service
Model Registry Service
Provider Plugin Framework
Inference Job/Scheduler
persistent queue
inference DB
multi-lane concurrency
independent Health/Logging/Evaluation service
complex metrics platform
```
