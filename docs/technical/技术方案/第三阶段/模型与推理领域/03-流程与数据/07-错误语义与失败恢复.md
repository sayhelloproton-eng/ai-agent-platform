# 12 · 错误语义与失败恢复

## 1. [FROZEN] 最小错误码

```ts
type InferenceErrorCode =
  | "INVALID_REQUEST"
  | "MODEL_UNAVAILABLE"
  | "CAPABILITY_UNSUPPORTED"
  | "CONTEXT_TOO_LARGE"
  | "QUEUE_TIMEOUT"
  | "INFERENCE_TIMEOUT"
  | "CANCELLED"
  | "PROVIDER_ERROR"
  | "INVALID_OUTPUT"
  | "INFERENCE_FAILED";
```

不在 v1 继续细拆 provider-specific error tree。

## 2. 错误语义

| Code | 含义 | 调用方典型处理 |
|---|---|---|
| INVALID_REQUEST | Envelope/Spec/payload 非法 | 修调用代码/输入 |
| MODEL_UNAVAILABLE | 目标逻辑角色不可用 | STOP/等待/业务升级 |
| CAPABILITY_UNSUPPORTED | thinking/image/structured/limit 不满足 | 换配置或改 Spec/mode |
| CONTEXT_TOO_LARGE | 输入超过限制 | 调用方重组 Context |
| QUEUE_TIMEOUT | 未获得 lane | 延后/重试由调用方决定 |
| INFERENCE_TIMEOUT | 已运行但超时 | 调用方决定是否重新调用 |
| CANCELLED | 请求被取消 | 正常终止 |
| PROVIDER_ERROR | API provider transport/protocol 错误 | 有界 retry 后返回 |
| INVALID_OUTPUT | 输出 parse/schema 失败 | bounded repair 后失败 |
| INFERENCE_FAILED | 其他已明确推理失败 | STOP/业务升级 |

## 3. [FROZEN] 为什么没有 UNKNOWN_SIDE_EFFECT

Inference 本身不产生真实世界 Effect。

即使 provider 超时，不需要像 Browser Submit 那样判断“是否已经产生副作用”。迟到 inference result 可以丢弃，调用方可重新请求。

## 4. [FROZEN] retry 上限

Runtime 内部只做：

- 明确未开始的瞬时 transport failure：最多一次；
- schema repair：最多一次（Spec 允许时）。

其他重试由调用领域重新发请求控制，不在 Model Runtime 做自循环。

## 5. [FROZEN] AUTO failure

AUTO 升级 REASON 后失败，不允许再降回 FAST 循环。直接返回最终失败/不可用。
