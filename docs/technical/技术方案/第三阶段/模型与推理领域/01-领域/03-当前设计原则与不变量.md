# 模型与推理领域｜当前设计原则与不变量

## 1. 领域定位

Model & Reasoning 是平台认知计算层，只负责模型接入、推理路由、ReasoningSpec、结构化输出、Runtime Health 与推理可观测；不拥有 Task、Agent、Execution、Approval 或 Deployment 业务事实。

## 2. Provider 抽象

Provider Adapter 是通用 API Adapter。任何具体本地/远端模型服务只是部署实现，不进入领域模型。FAST/REASON 可以映射到不同 Provider，但 Public Contract 不绑定具体产品。

## 3. Capability 是稳定性合同

`thinking/no-thinking`、image/vision、structured output、context limit、output limit、streaming 等都属于 Provider Capability Profile，运行前必须真实验证，不能只相信配置声明。

## 4. FAST / REASON / AUTO

- FAST 是默认高频路径。
- REASON 只处理需要升级的复杂/冲突/不确定情况。
- AUTO 是 Spec 允许的受控升级入口。
- Vision 是 input modality，不建立独立 Vision Agent/Service。

## 5. ReasoningSpec

控制型推理使用版本化静态 ReasoningSpec：`specRef + typed payload + fixed instruction + fixed output schema + limited vocabulary`。模型输出必须 runtime validate；小模型不依赖开放式自由发挥完成协议工作。

## 6. Capability Proposal

v1 不依赖 Provider 原生 tool_calls。需要表达工具意图时，模型最多输出一个结构化 Capability Proposal：

- 只能从 caller allowlist 选择；
- typed args；
- 不携带 secret；
- 不能执行；
- caller 负责 validation/maxRounds；
- 真实 Effect 交给 Execution。

## 7. 单 Lane 与 Queue

v1 整体保持严格单 Lane，优先级只有 `business / background`；不抢占已开始 inference，不做 persistent queue、不做多 lane scheduler。

## 8. Runtime 数据与恢复

queue/active inference 只在内存；推理过程可写 structured disk logs，但不建立业务 inference DB。Runtime restart 时 queued/running 请求明确失败，由 caller 决定是否安全重试。

## 9. Retry / Repair

transport 最多一次安全 retry；结构化输出最多一次 bounded repair；禁止无限 self-loop。

## 10. CoT

平台不要求、不依赖、不持久化长 Chain-of-Thought。业务只消费结构化 decision、confidence、reasonCode 和必要的短 rationale。

## 11. READY

Provider endpoint 返回 200 不等于 Model READY。READY 必须基于真实 capability verification 与行为测试；Deployment 执行 verify/doctor，Model Domain 定义合格标准。

## 12. 工程拓扑

```text
@ai-agent-platform/model-contracts
@ai-agent-platform/model-runtime
```

2 packages / 1 runtime service / 6 internal components。内部组件不是 6 个 Service，也不是 6 个 Bounded Context。

## 13. v1 明确不建立

Prompt Service、Tool Service、Model Registry Service、Provider Plugin Framework、Inference Job/Scheduler、persistent queue、inference DB、多 Lane 并发、独立 Health/Logging/Evaluation service、复杂 metrics platform。
