# 智能体运行与协作领域｜设计决策记录与已否决方案

> 用途：把本 Chat 数小时讨论中的**最终结论、纠偏、被覆盖方案**永久记录，防止后续 Chat / Codex / 实现者根据早期上下文重新引入已否决设计。

---

# 1. 设计方法

v1 核心原则：

```text
真实业务优先
当前 Carrier 优先
简单可落地优先
领域 Owner 清晰优先
静态明确优于动态聪明
防御性校验优于相信模型不会犯错
```

第一版不为了未来的通用 Agent Platform 完整性提前造 Agent Runtime framework。

---

# 2. CONFIRMED｜核心领域决策

## ADR-AGT-001｜第一版三个复合角色

```text
运营 + 产品经理
总控 = 项目管理 + 研发
测试 + 运维
```

第一版就这三个角色。

---

## ADR-AGT-002｜Agent Package 是 v1 Agent 实体定义

```text
Agent Package = npm package = versioned Agent definition
```

未来可转换为 OpenCode/Codex/Claude Code 等 Carrier 配置。

v1 不单独建立 Agent business entity。

---

## ADR-AGT-003｜Role 是部署后真实 Custom GPT

最终语义：

```text
roleRef = 用户实际创建 Custom GPT 后产生的真实 g-id
```

不能由 npm 包预先固定逻辑 roleRef。

`agentPackageRef` 与 `roleRef` 必须区分。

---

## ADR-AGT-004｜Worker/Person 是具体 Conversation

```text
workerRef = v1 Custom GPT Conversation c-id
```

同一 workerRef 对应同一个具体工作人员/对话上下文。

---

## ADR-AGT-005｜v1 不建 Agent / Session / AgentRun

真实生命周期已经由：

```text
Agent Package / Role / Worker
```

满足。

没有真实独立状态就不建实体。

---

## ADR-AGT-006｜一个 Agent Package 一个 Role

单工作区 v1：

```text
产品包 → 一个当前有效产品 Role
研发包 → 一个当前有效研发 Role
测试包 → 一个当前有效测试 Role
```

不允许同包注册多个当前 Role。

---

## ADR-AGT-007｜Role 不按 Task 生命周期释放

Role 是长期部署配置。

Task 完成不会删除 Role。

Task 的 role→worker binding 是 Task 历史事实，Task 完成归档后保留。

---

## ADR-AGT-008｜Role 变更 v1 只 delete + recreate/register

不做：

```text
updateRole
replaceRole
```

需要更换 GPT 时显式删除本地注册，再注册新 Role。

---

## ADR-AGT-009｜Role Runtime Public API 只保留 list/get

```text
listRegisteredRoles
getRegisteredRole
```

register/delete 是本地管理命令，不是 GPT Action/Public runtime API。

---

## ADR-AGT-010｜一个 Role 一个 Bearer Key

Role 注册后立即生成独立 key。

Gateway 由 key 反推出 roleRef，不信任 GPT 自报 roleRef。

---

## ADR-AGT-011｜Agent Package manifest 在 package.json

不创建 `agent.manifest.json`。

Custom GPT：

```text
name / description / conversation starters / Instructions
```

也直接由 package.json Agent 字段提供。

---

## ADR-AGT-012｜fixed-context 与 memory 分开

```text
context/fixed-context.md
memory/memory.md
```

语义分离，但 v1 Custom GPT Carrier 可把适合参考的长期材料作为 Knowledge 文件人工上传。

---

## ADR-AGT-013｜永久 Memory v1 不自动写

Agent 不在运行中自动修改长期 Memory。

长期材料变化：

```text
修改 Agent Package
→ 升版本
→ CLI 提示用户更新 Custom GPT Web
```

---

## ADR-AGT-014｜Custom GPT v1 人工 Web 创建/更新

Agent Package/CLI 提供机械向导和字段材料。

v1 不依赖一个 Custom GPT 管理 API 自动创建/更新 GPT。

---

## ADR-AGT-015｜Action Schema v1 静态写死

每个 Agent Package 自带固定 OpenAPI。

不做：

```text
Capability Catalog
动态 API discovery
Schema Composer
运行时 Action 裁剪
```

仅实例化 Gateway/public URL、认证等部署配置。

---

## ADR-AGT-016｜Action 防错三层

```text
Role Package 静态裁剪
+ 清晰 operationId/description
+ Owner 服务端最终校验
```

模型可犯错，但不能越过领域规则。

---

## ADR-AGT-017｜Gateway 是 Agent public ingress adapter

业务意义上 Gateway + public tunnel 是 Agent Carrier 与平台连接能力。

Gateway 负责：

```text
auth
schema/basic validation
routing
protocol normalization
```

不拥有 Task/Execution/Collaboration 的第二真源。

---

## ADR-AGT-018｜本地资源实现属于 Execution

File/Git/CodeGraph/CLI/Build/Test/Logs/Runtime 等真实访问由 Execution Domain 实现。

Gateway 只能调用 Execution Public API。

---

## ADR-AGT-019｜Task 是 Workflow 唯一真源

Agent 只表达：

```text
completeNode / waitNode / reopenNode
```

Agent 不直接设置“下一个节点=待测试”。

Task Domain 校验并自然推进。

---

## ADR-AGT-020｜Task-level role→worker binding

Task 需要长期稳定绑定产品/研发/测试人员。

```text
Task role binding = stable participant
Node.workerRef = current run worker
```

Owner 是 Task Domain。

---

## ADR-AGT-021｜产品角色发生在 Task 前

产品/运营先与用户形成/确认需求，再创建 Task。

产品 Worker 创建 Task 时绑定：

```text
产品 roleRef + 产品 workerRef
研发 roleRef
测试 roleRef
```

产品不因此必须成为 Task Node。

---

## ADR-AGT-022｜Task start 时立即创建 dev/test Worker

用户批准任务执行后，Extension 第一时间创建并绑定研发和测试 Conversation。

后续 Node 串行 READY 只负责决定**什么时候唤醒已绑定 Worker**。

---

## ADR-AGT-023｜Worker 创建只能由 Task-driven Extension

Collaboration 消息不能创建 Worker。

`TARGET_WORKER_NOT_BOUND` 可以作为防御错误，但不触发自动新建 Conversation。

---

## ADR-AGT-024｜reopen 必须原 Worker

同 Task 同角色 reopen：

```text
必须复用 Task 已绑定原 workerRef
```

而且 Extension 必须注入 Task Domain 的正式 reopen 信息。

---

## ADR-AGT-025｜Conversation context 可持续使用

不要求 Worker 每次 wake 强制先查 `getNodeContext`。

Worker 可以使用同 Conversation 历史。

但上下文不明确/可能过期时必须主动：

```text
查 Task
查本地资源
askPeer
```

---

## ADR-AGT-026｜跨角色协作属于 Agent Domain

公开给角色的最小协作 Action：

```text
askPeer
replyPeer
```

Message Center durable 保存，Extension 做 Browser 投递。

协作消息不改变 Task Workflow。

---

## ADR-AGT-027｜Collaboration 支持多轮但严格一问一答

```text
Q1 → A1 → Q2 → A2
```

不允许：

```text
Q1 → Q2（Q1 尚未回答）
```

---

## ADR-AGT-028｜Extension 多类轮询，接口分域

当前：

```text
Task pending drive
Collaboration pending delivery
```

未来还可新增类别。

不建立统一超级队列来吞并领域边界。

---

## ADR-AGT-029｜Agent Package SemVer

```text
patch / minor / major
```

分别表达文案小修、兼容能力变化、不兼容职责/合同变化。

Package 升级不自动产生新逻辑 Agent/Role。

---

# 3. SUPERSEDED｜曾讨论但已被后续结论覆盖

## S-01｜roleRef 是包内逻辑 ID

早期设想：

```text
roleRef = controller-dev / test-ops
```

**已覆盖。**

最终 v1：

```text
roleRef = 用户真实 Custom GPT g-id
agentPackageRef = 包身份
```

---

## S-02｜每次 wake 必须先 getNodeContext

**已覆盖。**

最终：Conversation 保持上下文，按需查询正式事实。

---

## S-03｜动态 Action Schema / Capability Catalog

**已覆盖。**

最终：v1 static schema per Agent Package。

---

## S-04｜Agent Domain 主动监听 READY Node 并调度 Worker

**已覆盖。**

最终：Browser Extension 轮询 Task，Task-driven 驱动 Worker。

Agent Domain 不需要 own READY scheduler。

---

## S-05｜只有 Node.workerRef 就够了

**已覆盖。**

最终：需要 Task-level role→worker binding + Node.workerRef。

---

## S-06｜reopen 清空后重新选 Worker

**已覆盖。**

最终：必须复用 Task-bound 原 Worker；Node run-level 可重新 start 同 workerRef。

---

## S-07｜Collaboration Message 可以顺便创建目标 Worker

**已覆盖。**

最终：Worker 只能由 Task start Extension 流程创建。

---

## S-08｜askPeer Action 直接调用扩展

**已覆盖。**

最终：

```text
Action → durable Message Center → Extension poll → Browser delivery
```

保证扩展离线时消息不丢。

---

## S-09｜registerRole/unregisterRole 是 Public API

**已覆盖。**

最终 runtime public 只 list/get；注册/删除是本地 CLI 管理。

---

## S-10｜Role 可以 update/replace

**已覆盖。**

最终 v1 delete + register。

---

## S-11｜Instructions 独立 instructions.md

**已覆盖。**

最终 Instructions 在 package.json Agent 字段。

---

## S-12｜fixed-context / memory 合并

**已覆盖。**

最终两者分开。

---

# 4. REJECTED / NON-GOALS｜v1 明确不做

```text
通用 Agent entity hierarchy
Session state machine
AgentRun state machine
Worker Pool / availability / scheduling algorithm
自动 reassign / steal / takeover
通用 Team / Org Tree
Spawn / Delegate / Handoff framework
A2A v1 实现
通用 Capability Registry
动态 OpenAPI discovery/composition
Agent 自动永久记忆
Agent 直接操作 Task DB
Agent 直接执行 Local/Shell/Browser
Gateway 直接执行业务底层
Collaboration 触发 Task Node 状态
Collaboration 创建 Worker
Role 全局互斥
Role Task 完成后解绑
角色跨 Task 自动复用同一 workerRef
Redis/Kafka/Temporal 作为 v1 前置
独立 Message Bus
复杂 RBAC/ABAC
```

注意：

> “同一个 Role 可以在不同 Task 创建不同 Worker”与“同一个 Task reopen 复用原 Worker”同时成立，不矛盾。

---

# 5. 保留为未来升级触发器

只有真实需求出现后再升级：

- Carrier 可程序化创建/管理 Agent；
- 同 Worker 多 Session；
- self-hosted Agent Runtime；
- A2A 跨系统 Agent；
- 多角色并行 Node；
- Worker migration/reassignment；
- Capability 自描述与动态 Schema；
- 跨 Task 长期学习/Memory write-back；
- WebSocket/SSE 取代轮询；
- 企业 RBAC/tenant/secret governance；
- 多机分布式协作。

这些不应进入当前实施关键路径。

# v0.2 新增 ADR

## ADR-AGT-020｜一个 Task 一组独立 Worker Conversations

**决定：**不同 Task 不复用 Worker；同一 Task/reopen 复用原 Worker。

```text
Task A → Product-A / Dev-A / Test-A
Task B → Product-B / Dev-B / Test-B
```

---

## ADR-AGT-021｜Task 批准后先绑定 Dev/Test，再正式执行 Node

**决定：**先 Dev、再 Test；两者都绑定完成后才开始正式 Node work。`WORKER_BIND` 不允许业务执行。

---

## ADR-AGT-022｜Collaboration 下一问必须等 Reply DELIVERED

**决定：**多轮严格串行：`Q1 → A1(DELIVERED) → Q2`。Reply 仅 durable 不够。

---

## ADR-AGT-023｜Role v1 只物理删除

**决定：**无 tombstone/逻辑删除。删除前 CLI 经 Task Public API 检查非终态引用；在用 `ROLE_IN_USE`。允许后删除 registry+secret。

---

## ADR-AGT-024｜Role Key 可独立轮换

**决定：**`rotate-role-key` 不改变 roleRef/Task history，只更新 credential 并引导 GPT Web 更新。

---

## ADR-AGT-025｜Browser Extension 使用 local-platform-token

**决定：**Role Key 只用于 Custom GPT→Gateway；Extension 使用本地平台 token，不冒充角色。

---

## ADR-AGT-026｜公网只暴露 Agent Gateway

**决定：**`Custom GPT → Dev Tunnel → Gateway`；Agent Runtime/Task/Execution/Browser bridge 不直接公网暴露。

---

## ADR-AGT-027｜[SUPERSEDED by ALIGN-008/029] 原七个独立 package/deployment units

**历史决定（已部分 Superseded）：** 原设计将 agent-runtime、agent-gateway、browser-extension、dev-tunnel、三个 Agent Package 均计入 Agent；最终裁决改为 Browser→Execution、Dev Tunnel→Deployment External Resource，其他 Agent packages 保留。

---

## ADR-AGT-028｜包自身部署闭环，总 Deployment 透传编排

**决定：**所有 package 遵循统一 lifecycle protocol，同时 package 自己拥有账号创建引导、login/config/bind/lifecycle/verify 等细节；平台总 Deployment 统一发现、顺序编排并透传。

该 ADR 覆盖早期“模块只暴露 primitives，Planner/Executor 负责具体 apply”的方案，需跨域同步 Deployment 文档。

---

## ADR-AGT-029｜产品 GPT 是 pre-Task Worker

**决定：**用户先与新的产品 GPT Conversation 全量沟通，需求形成后才 createTask；产品 Worker 不由 Task-driven Extension 创建。

产品必须可靠取得 c-id/Carrier identity；Carrier Context Action 是优先验证的轻量实现候选，不是当前保证。具体可靠机制必须真实 E2E，Action 不可靠时由 Execution Browser/Carrier observation 提供证据。

---

## ADR-AGT-030｜Task terminal 后不再处理 Collaboration

**决定：**终态后不投递/不新问答；既有消息原样作为历史，不改成 CANCELLED/TASK_TERMINAL。
