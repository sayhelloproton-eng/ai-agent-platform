# 2. agent-runtime

职责：

```text
Role Registry
Role Credential domain service
Collaboration Message Center
Collaboration durable state / idempotency
Agent Domain Public API
Role/Task participant defensive validation ports
```

不负责：

```text
Task workflow
Browser DOM injection
File/Git/Shell real effects
Model inference
公网 tunnel
```

Role Registry 与 Collaboration Message Center **不再拆独立 daemon/package**，作为 Agent Runtime 内部模块。

# 3. agent-gateway

这是 Agent Domain 的独立 npm 服务包。

职责：

```text
Custom GPT Action public ingress
role-specific Bearer authentication
Bearer key → authenticatedRoleRef
基础 schema/auth validation
Action route mapping
调用 Agent / Task / Execution Public Contracts
协议转换
结果标准化
```

严格禁止：

```text
直接读 Task SQLite
直接读 Agent Runtime SQLite
直接 exec git/shell
直接拥有 Task/Execution business state
```

公网链路：

```text
Internet
→ Microsoft Dev Tunnel
→ Agent Gateway
→ local public contracts
```

v1 **只允许 Gateway 被公网暴露**。

独立 npm 管理包，封装 Microsoft Dev Tunnels 的平台适配和用户引导。

它可以调用/包装官方 `devtunnel` CLI，但平台其他模块不应直接依赖微软 CLI 细节。

职责：


# 7. 统一 Package Lifecycle Protocol

所有独立包必须遵守平台统一生命周期协议，让总 Deployment 能稳定发现/调用。

协议至少应允许包声明自己支持的标准能力：

```text
describe / requirements
setup
configure
login
bind
start
stop
status
verify
doctor
```

不是所有包都必须实现全部命令；由 package descriptor 声明支持集合。

示意：

```text
agent-runtime:
  setup configure start stop status verify doctor

agent-gateway:
  setup configure bind start stop status verify doctor

dev-tunnel:
  setup login configure bind start stop status verify doctor

browser-extension:
  setup configure bind status verify doctor

agent-*:
  setup configure register-role show-role validate-role delete-role status verify doctor
```

每个包**允许增加专有命令**，例如：

```text
rotate-role-key
show-role-key
public-url
build-extension
export-custom-gpt-schema
```

总 Deployment 只依赖标准 protocol，不需要知道专有命令的内部语义。

# 8. “包自闭环，总部署透传”

本 Chat 最新确认：

> **各包负责自己的部署/配置/账号/登录/绑定/验证闭环；总部署负责统一入口、发现、顺序编排和透传，不替包重新实现细节。**

例如 Dev Tunnel：

```text
Platform Deployment
→ 调用 dev-tunnel package login/configure/bind/start/verify
→ dev-tunnel package 自己引导用户创建账号/登录并执行微软 CLI 细节
```

例如 Agent Package：

```text
Platform Deployment
→ 调用 agent-product setup
→ agent-product 自己告诉用户怎样在 ChatGPT Web 创建 GPT、复制字段、上传 Knowledge、注册 g-id、设置 Role Key
```

因此 Deployment Domain 需要一个薄而稳定的统一 lifecycle contract，而不是复制每个模块的业务安装知识。

这是对早期“Platform Planner/Executor 负责具体模块安装/apply”的方案的最新覆盖，必须进入 Phase 3 总纲跨域审计。

# 9. 建议仓库结构

在不违反最终 Deployment naming/template 的前提下，Agent Domain 推荐：

```text
packages/
├── agent-runtime/
├── agent-gateway/
├── browser-extension/
├── dev-tunnel/
├── agent-product/
├── agent-controller-dev/
└── agent-test-ops/
```

每个目录独立：

```text
package.json
src/
tests/
deployment/ or lifecycle adapter (按最终 template)
README/INSTALL material (按最终 Deployment contract)
```

Browser Extension 额外包含：

```text
manifest.json
background/service-worker
content scripts
side panel/ui
build output
```

Dev Tunnel 额外包含：

```text
cli wrapper/adapter
account/login guide
config materializer
process/lifecycle adapter
verify/doctor probes
```

# 10. 版本与独立升级

**Historical v0.2 statement（已部分 superseded）：** 原七单元按独立 SemVer/测试/verify/升级描述；当前按最终 Module ownership 与真实 kind/lifecycle 治理。

三个 Agent Package 使用：

```text
patch = 文案/提示词修正，不改变职责/API
minor = Knowledge/能力/Action 的兼容增减
major = 角色职责、Action Contract、Carrier 配置的不兼容变化
```

其他运行包同样遵守 SemVer，但版本语义按各包公共 Contract compatibility 定义。
