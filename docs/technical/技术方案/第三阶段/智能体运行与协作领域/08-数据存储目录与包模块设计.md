# 1. Service / Package / Process 三层分开

```text
Service = 逻辑业务能力
npm Package = 软件交付/版本边界
Process = 实际运行进程
```

v1 不要求每个逻辑 Service 独立 daemon。

可以同进程 composition，但禁止跨域直接 import internal implementation。

# 10. Role Registry：JSON 即可

v1 Role 数量极小且管理写频率低，不需要 SQLite。

逻辑文件：

```json
{
  "contractVersion": "1.0.0",
  "roles": [
    {
      "agentPackageRef": "@.../agent-product",
      "registeredPackageVersion": "1.0.0",
      "roleRef": "g-...",
      "carrierType": "custom-gpt",
      "carrierUrl": "https://chatgpt.com/g/g-...",
      "registeredAt": "..."
    }
  ]
}
```

写入要求：

```text
atomic write/rename
schema validation
agentPackageRef uniqueness
roleRef uniqueness
file permission
```

v1 Role 删除为**物理删除**：删除 entry，不保留 tombstone。

# 11. Secret Store

v1 采用本地受限权限文件。

```text
roleRef → role-specific Bearer Key
local component → local-platform-token
```

要求：

```text
Git ignored
minimum file permissions
not logged
not Knowledge
ordinary public API never returns full key
```

Role Key 支持 `rotate-role-key`。

# 12. Collaboration SQLite

需要 durable，因为：

```text
Browser offline/reload
message queue polling
strict Q→A→Q ordering
reply delivery gate
idempotency
retry attempts/receipt
```

建议表：

```text
collaboration_threads
collaboration_messages
collaboration_idempotency
```

Thread 至少需要表达：

```text
OPEN_AWAITING_REPLY
OPEN_REPLY_PENDING_DELIVERY
OPEN_CAN_ASK
```

Message 至少：

```text
message_id
thread_id
task_id
kind
from_role_ref/from_worker_ref
target_role_ref/target_worker_ref
reply_to_message_id
content
status = PENDING | DELIVERED
delivery_attempt_count
last_delivery_error_code
created_at
delivered_at
version
```

具体 DDL 见 `16-事务并发幂等与SQLite-DDL.md`，v0.2 应以“reply DELIVERED 才可下一问”为最终业务约束。

---

# 13. Collaboration 不复制其他领域数据

SQLite 只保存真正协作事实，不保存：

```text
Custom GPT 完整 transcript
Task Markdown 正文副本
Execution log 副本
Worker 全量上下文
```

只保存跨角色实际发出的 question/reply 和 delivery history。

# 14. Package Lifecycle

**Historical v0.2 lifecycle statement（已部分 superseded）：** 原七个单元均按统一 Package Lifecycle Protocol 描述；当前只对各 Module 采用其真实 kind/lifecycle，Browser/Dev Tunnel ownership 以顶部说明为准。

公共可发现能力示例：

```text
describe / requirements
setup
configure
login
bind
start
stop
status
verify
doctor
```

每包声明自己支持哪些。

关键最新原则：

> **包自身部署闭环，总 Deployment 统一发现/编排/透传。**

即总 Deployment 不重新实现：

```text
怎么登录 Microsoft Dev Tunnels
怎么在 GPT Web 创建角色
怎么配置 Gateway role key
怎么 build/load Chrome Extension
```

这些细节由对应 package 自己引导/执行。

总 Deployment 只依赖统一 lifecycle contract 来调用。

这项需要同步修正 Deployment Domain 的早期“Planner/Executor 负责模块具体 apply”的方案。
