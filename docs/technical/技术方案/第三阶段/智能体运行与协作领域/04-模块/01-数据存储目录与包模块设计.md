# 智能体运行与协作领域｜数据存储、仓库目录与 npm 模块设计

## 1. 工程单元分层

```text
Domain capability
→ Module
→ npm package
→ Service/Process（仅真实存在时）
→ Deployment Unit（仅真实有生命周期时）
```

Agent Domain 当前拥有 5 个正式 npm package：

```text
@ai-agent-platform/agent-runtime
@ai-agent-platform/agent-gateway
@ai-agent-platform/agent-product
@ai-agent-platform/agent-controller-dev
@ai-agent-platform/agent-test-ops
```

Browser Extension 属于 Execution Domain；Dev Tunnel 属于 Deployment External Resource Module。Agent 只通过 logical capability 依赖它们。

## 2. Agent Domain 内部逻辑模块

`agent-runtime` 内至少包含：

```text
Role Registry
Role Credential
Worker Identity
Collaboration Message Center
Task participant defensive validation ports
```

这些逻辑模块不拆独立 daemon/package。

## 3. `agent-runtime`

推荐结构：

```text
packages/agent-runtime/
├── package.json
├── src/
│   ├── contracts/
│   │   ├── role.ts
│   │   ├── worker.ts
│   │   ├── collaboration.ts
│   │   └── errors.ts
│   ├── services/
│   │   ├── role-registry-service.ts
│   │   ├── role-credential-service.ts
│   │   ├── worker-identity-service.ts
│   │   └── collaboration-service.ts
│   ├── ports/
│   │   ├── task-public-api.ts
│   │   ├── execution-public-api.ts
│   │   ├── role-registry-store.ts
│   │   ├── credential-store.ts
│   │   └── collaboration-store.ts
│   ├── adapters/
│   │   ├── role-registry-json.ts
│   │   ├── credential-file.ts
│   │   └── collaboration-sqlite.ts
│   ├── cli/
│   └── index.ts
└── tests/
```

Store adapter 不为形式完整拆额外 npm package。

## 4. `agent-gateway`

独立 Service package：

```text
packages/agent-gateway/
├── package.json
├── src/
│   ├── server/
│   ├── auth/
│   ├── routes/
│   ├── clients/
│   │   ├── agent-runtime-client.ts
│   │   ├── task-client.ts
│   │   └── execution-client.ts
│   ├── protocol/
│   │   ├── openai-actions.ts
│   │   └── openai-file-bridge.ts
│   ├── relay/
│   ├── lifecycle/
│   └── index.ts
└── tests/
```

Gateway 不持久化 Task/Collaboration/Execution 业务状态；短期 file relay 只保存受限 transport metadata。

## 5. 三个 Agent Package

```text
packages/agent-product/
packages/agent-controller-dev/
packages/agent-test-ops/
```

每包最低结构：

```text
package.json
context/fixed-context.md
memory/memory.md
knowledge/*
actions/custom-gpt.openapi.yaml
src/cli-or-materializer/*
tests/*
```

`package.json` 保存 Agent/GPT create metadata、recommended model hint、capability requirements、Actions schema pointer。动态 TaskDocument 不进入 Knowledge。

## 6. `.ai-agent-platform` Agent 数据

推荐：

```text
.ai-agent-platform/
└── agent/
    ├── roles.json
    ├── credentials/
    └── collaboration/
        └── collaboration.sqlite
```

最终具体文件名可实现时机械确定，但 Owner 与安全边界不得改变。

## 7. Role Registry

v1 使用 JSON 足够：Role 数量固定且很小，写入低频，主要通过本地 CLI 管理。

最低字段：

```text
roleRef
agentPackageRef
registeredPackageVersion
carrierType
carrierUrl/gptId metadata
createdAt/updatedAt
```

Registry 不保存 Task binding；TaskRoleBinding 仍归 Task Domain。

## 8. Credential Store

- 一个 Role 一个 Bearer/API key。
- credential 文件仅本机可读，不进入 Git。
- key rotation 不改变 roleRef。
- logs/error/doctor 必须 redaction。
- Browser Extension 使用独立 `local-platform-token`，不复用 Role key。

## 9. Collaboration SQLite

保存：

```text
thread/message identity
sender/receiver refs
question/reply relation
logical delivery state
physical delivery receipt ref/status
timestamps
idempotency records
```

不保存：

```text
full GPT transcript
TaskDocument body copy
Execution logs/evidence copy
Browser DOM snapshot as business truth
```

## 10. 跨域数据不复制

Agent SQLite/JSON 只保存 Agent-owned facts。Task role binding、Task status、Execution effect/evidence、Model inference state 都通过各自 Public Contract 查询。

## 11. Package lifecycle

- `agent-runtime`：library/in-process runtime，由 platform-host 装配。
- `agent-gateway`：独立 Service/Process/Deployment Unit。
- 三个 Agent Package：版本化配置/定义包，不伪造常驻 process。
- Browser/Dev Tunnel 作为外部依赖进入统一 Module Graph。

## 12. platform-host 组合

`platform-host` 可以 in-process 装配 `agent-runtime`，但不能吸收其源码或持久化。Agent package 不得反向依赖 platform-host。
