# 智能体运行与协作领域｜跨领域一致性验收清单

> 本清单只描述当前正式边界与验收要求，用于实现和 E2E 检查；不维护提案过程或版本演变记录。

## 1. Task 集成

- [ ] `TaskRoleBinding` 唯一 owner 是 Task Domain；Agent 不保存第二份 role→worker 业务绑定。
- [ ] `createTask` 能表达产品已有 role+worker 与研发/测试 role 要求。
- [ ] 人工执行授权后，研发/测试 Worker provisioning 完成前不得启动正式 Node work。
- [ ] `bindTaskWorker` 是 one-time + idempotent：同值重放成功，不同值覆盖冲突。
- [ ] `getTask`/必要 projection 可以返回 roleBindings；Agent 只 opaque 使用。
- [ ] `startNode` 根据 `requiredRoleRef → TaskRoleBinding.workerRef` 自动解析，不接受任意 Worker 选择。
- [ ] reopen 复用同一 Task 原 Worker；不得重新分配新的 Conversation。
- [ ] Task terminal 后 binding 保留为不可变业务事实。
- [ ] 不为 Agent 集成重新引入 WorkItem / Claim / Lease / parallel Node。

## 2. Worker provisioning

- [ ] 产品 Worker 可以在 Task 前存在；Task 创建时只记录其当前稳定 identity。
- [ ] 研发 Worker 先创建/识别/注册，再写 Task binding。
- [ ] 测试 Worker 在研发 Worker 成功后创建/识别/注册，再写 Task binding。
- [ ] 任一步失败后恢复时只补缺失部分，不重复创建已成功 Worker。
- [ ] Browser CREATE 成功只证明 Conversation reality，不等于 Task binding 成功。
- [ ] Task binding 成功后必须能重新查询确认 owner facts。

## 3. Browser / Execution 集成

- [ ] Browser Extension 唯一 owner 是 Execution。
- [ ] Agent 不直接操作 tab/window/content-script internal id。
- [ ] Worker identity 的 c-id 由真实 Conversation URL/页面 reality 获取和验证。
- [ ] 有 workerRef 时优先 RESTORE；只有确实无 Worker 才 CREATE。
- [ ] WAKE 只发送最小 identity/trigger envelope；大型动态上下文不经 DOM 大段注入。
- [ ] WAKE/submit result 不能被解释为 Node/Effect success。
- [ ] Collaboration physical delivery 通过 Execution Public Contract；Agent 只更新逻辑 delivery state。
- [ ] uncertain delivery/effect 不 blind retry，先 reality verification。

## 4. Collaboration

- [ ] Public API 只有 `askPeer / replyPeer` 两类逻辑动作。
- [ ] sender/receiver 必须属于同一 Task 已绑定参与者。
- [ ] 一问一答严格串行；下一问必须等当前 Reply `DELIVERED`。
- [ ] Task terminal 后不再产生新的 collaboration work。
- [ ] Message Center 不关心 Tab 在线与否，不承担 Browser 调度。

## 5. Agent Gateway

- [ ] Custom GPT Actions 只通过 agent-gateway 公网入口。
- [ ] Role credential 与 roleRef 一一绑定；Gateway 不信任客户端自报 roleRef。
- [ ] GPT-facing transport 不要求 arbitrary custom headers；task/node/idempotency/correlation 等必要 metadata 放 typed body/path/query，由 Gateway 归一化到内部 DTO。
- [ ] 所有外部输入先按 `unknown` 接收并 runtime validate。
- [ ] Gateway 只做 auth/basic validation/routing/protocol normalization/response serialization，不拥有下游业务事实。
- [ ] 45s Action ceiling 不被当成业务处理 timeout；长工作使用 quick accept/ref + 后续查询/继续。
- [ ] request/response 最终 JSON 均执行 `<100,000 chars` serializer hard guard。
- [ ] 429/5xx 返回真实 HTTP semantics。

## 6. File Bridge

- [ ] `openaiFileIdRefs` 最多 10 项；runtime object array 做专门 normalization。
- [ ] `download_link` 只作为短期 locator，不持久化为 durable business ref。
- [ ] filename/MIME/URL 视为 external-untrusted；物理 fetch/materialization 交 Execution。
- [ ] input size/aggregate/fetch timeout 使用平台 hard gate。
- [ ] `openaiFileResponse` 最多 10 文件、每文件 ≤10MB、禁止 image/video。
- [ ] inline payload 在 serializer 预算超限前自动切换 bounded URL relay；仍不满足则 typed error。
- [ ] relay token opaque、single-purpose、artifact-scoped、GET-only、bounded TTL。
- [ ] Gateway relay 不是 File Service，不形成业务文件数据库。

## 7. Consequential / Approval

- [ ] 每个 GPT Action operation 显式声明 `x-openai-isConsequential`。
- [ ] Carrier confirmation 与 Execution Approval 完全分层。
- [ ] `consequential:false` 不能跳过 Effect Policy/Approval。
- [ ] Always Allow 未验证或异常时，Browser permission fallback 可恢复。

## 8. Model 集成

- [ ] GPT native Function Calling 不改变 Model Runtime `ReasoningSpec → structured output/Capability Proposal` 架构。
- [ ] Agent 不要求本地 Model Runtime 实现 OpenAI tool_calls。
- [ ] Agent/Gateway 只通过 Model Public Contract 使用推理能力，不读取 provider internal state。

## 9. Deployment 集成

- [ ] Agent packages、agent-gateway、ChatGPT Carrier、Dev Tunnel 等都进入 Module Governance。
- [ ] Browser Extension 仍属于 Execution Module，不因 Agent Carrier 集成转移 ownership。
- [ ] Custom GPT create/edit 为 `ACTION_REQUIRED_WEB`。
- [ ] Role READY 按 Actions schema、auth、required carrier capabilities 与实际 E2E behavior 验证。
- [ ] Workspace domain allowlist、Privacy Policy、auth restore 等外部要求进入 Carrier doctor/verify，而不是埋在 Agent Runtime 业务逻辑。

## 10. 最终 E2E Gate

完整链必须真实证明：

```text
product Worker exists
→ create Task
→ human authorization
→ provision/bind dev + test Workers
→ start Task / Node
→ WAKE target Worker
→ GPT Actions / File Bridge as needed
→ Execution real Effect / Evidence
→ Task owner state transition
→ collaboration delivery when present
→ recover from reload/timeout/expired transient locator without duplicate business effect
```
