# 智能体运行与协作领域｜实施顺序与落库门禁

> 目标：按当前 Domain/Contract/Module 边界完成真实 Custom GPT Carrier 落地，不通过临时跨域直连绕过 Owner。

## P0｜Contract / Package 基线

- [ ] `agent-runtime / agent-gateway / agent-product / agent-controller-dev / agent-test-ops` package skeleton 与 Module Registry 一致。
- [ ] Agent Public Contract、Task dependency、Execution dependency、Deployment requirements 全部可从当前文档定位。
- [ ] Role/Worker/Collaboration DTO runtime schema 完成，外部输入 `unknown → validate → typed`。
- [ ] `agent-gateway` OpenAPI/transport hard limits 与 role credential contract 冻结。

GO：无 cross-domain direct DB/deep import；package/service/process ownership 与当前 Module Registry 一致。

## P1｜Role Registry + Credential

实现：

```text
RoleRegistryService
RoleCredentialService
WorkerIdentityService
RoleRegistryStore
CredentialStore
```

测试：one package one role、g-id parsing、register+key、ROLE_IN_USE delete guard、physical delete+register、key rotation、secret redaction、registeredPackageVersion drift。

## P2｜Collaboration Message Center

实现 `askPeer/replyPeer`、thread/message/idempotency/delivery state。

门禁：

- [ ] 同一 Task 已绑定参与者校验。
- [ ] strict one unanswered question。
- [ ] Reply physical `DELIVERED` 前禁止下一问。
- [ ] duplicate idempotency 安全。
- [ ] Task terminal 不创建新 collaboration work。
- [ ] physical delivery 只经 Execution Public Contract。

## P3｜Agent Packages / Custom GPT Materialization

三个 Agent Package 各自完成：

```text
package.json Agent metadata
fixed-context
memory baseline
knowledge list
actions/custom-gpt.openapi.yaml
carrier requirements
conformance tests
```

不引入 dynamic schema/capability catalog。

## P4｜Agent Gateway

- [ ] 公网 ingress + role Bearer auth。
- [ ] GPT-facing body/path/query → internal canonical DTO normalization。
- [ ] 无 arbitrary custom header 依赖。
- [ ] 45s / <100k / 429/5xx hard guards。
- [ ] `openaiFileIdRefs` object-array normalization。
- [ ] `openaiFileResponse` inline/URL relay + TTL/token/scope/SSRF/size guards。
- [ ] 每个 operation 显式 `x-openai-isConsequential`。
- [ ] Gateway 无业务 persistence。

## P5｜Worker Provisioning 集成

真实链：

```text
Task authorized
→ Execution Browser CREATE/observe dev c-id
→ Agent identity validate
→ Task.bindTaskWorker(dev)
→ Execution Browser CREATE/observe test c-id
→ Agent identity validate
→ Task.bindTaskWorker(test)
→ query Task owner facts
→ formal Node work
```

门禁：失败后只补缺失 Worker；不得重建已成功 Worker；Browser CREATE success 不等于 Task bind success。

## P6｜Worker Wake / Node / Collaboration Delivery

- [ ] RESTORE existing Worker before CREATE。
- [ ] WAKE 只传 minimal identity/trigger。
- [ ] 大型 TaskDocument/Artifact 使用 Task API / File Bridge。
- [ ] Node/Collaboration physical delivery result 返回 Agent/Task owner 处理。
- [ ] delivery uncertainty reality-first；无 blind resubmit。

## P7｜Product pre-Task Carrier

- [ ] 产品 GPT Web 创建/配置完成。
- [ ] 产品 Conversation 真实工作形成需求。
- [ ] Browser 可靠取得/核验产品 workerRef/c-id。
- [ ] createTask 带 product role+worker 与 dev/test role requirements。

任何 current-link/Action shortcut 只作为 Spike 优化，不替代 Browser correctness path。

## P8｜真实 Carrier E2E

必须覆盖：

```text
product pre-Task
→ createTask
→ human authorization
→ dev/test provisioning + binding
→ start Node
→ WAKE
→ Actions/File Bridge
→ Execution Effect/Evidence
→ complete/wait/reopen
→ Collaboration ask/reply delivery
→ reload/timeout/expired locator recovery
```

## GO 门

- Contract tests PASS。
- Agent Runtime persistence/restart PASS。
- Gateway security/transport conformance PASS。
- 三角色真实 Custom GPT Actions E2E PASS。
- Worker same-Task reuse/reopen PASS。
- no duplicate Task binding / browser submit / business Effect。

## STOP 门

立即停止实现并修正式设计，如果：

- 需要新增 Agent/Session/AgentRun business entity；
- 需要 Agent 直接写 Task/Execution state；
- 需要 Browser Extension 转移出 Execution ownership；
- 需要未验证 Carrier behavior 成为唯一 correctness path；
- 需要凭 undocumented c-id/header/API 才能工作；
- 需要增加新的常驻 Service 才能“更方便”。
