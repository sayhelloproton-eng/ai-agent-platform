# 智能体运行与协作领域｜失败恢复、版本、安全与 v1 验收

---

# 1. 总原则

```text
Owner validates its own business facts
model error cannot bypass service legality
all cross-domain access uses Public Contracts
Browser irreversible effects need stable intent + Receipt
unknown side effect is never blindly retried
Task terminal is final
Worker identity is Task-scoped
```

---

# 2. 身份模型

## Custom GPT

```text
one Role → one Bearer Key
Bearer Key → Gateway → authenticatedRoleRef
```

不信任 body 自报 roleRef。

## Browser Extension

```text
Browser Extension → local-platform-token → Execution Runtime Browser protocol surface
```

不得使用 Role Key 冒充 Agent。

## Task-scoped Worker

服务端对涉及 Task 的角色 Action 校验：

```text
authenticatedRoleRef
+ taskId
+ workerRef
+ Task role binding
+ Node.requiredRoleRef/Node.workerRef（按接口）
```

不同 Task 不复用同 Worker Conversation。

---

# 3. Secret

MUST NOT：

```text
Git
Knowledge
OpenAPI example
Task Markdown
logs
browser injected text
Execution readable local-resource result
```

v1 secret 存 `.ai-agent-platform` 受限文件。

支持：

```text
show-role-key (explicit local user action)
rotate-role-key
```

rotate 不改变 roleRef。

---

# 4. Role 注册/删除恢复

注册：

```text
validate g-id/url
→ write Role Registry
→ generate role key
→ validate registry+credential pair
→ guide Web auth
```

若 registry/key 半完成，doctor 必须检测，不得宽松认证。

删除：

```text
role delete
→ Task Public API query non-terminal role usage
→ in use: ROLE_IN_USE, zero mutation
→ not in use: physical delete role entry + secret
```

v1 无 tombstone/logical delete。

终态 Task 中既有 roleRef 保留，但 Agent Registry 可返回 ROLE_NOT_FOUND。

---

# 5. Task 启动初始化失败恢复

冻结业务顺序：

```text
user approves execution
→ create/bind Dev
→ create/bind Test
→ both complete
→ formal Node execution
```

失败例：

```text
Dev bound
Test creation failed
```

恢复：

```text
read current Task bindings
→ preserve Dev
→ create/bind only missing Test
→ do not send NODE_READY until initialization complete
```

不回滚/重建已经成功的 Worker，不新增 WorkItem/Claim。

Task API exact state/order 必须服从 Task Domain Public Contract，并通过跨领域 Contract/E2E 验证。

---

# 6. WORKER_BIND 安全

`WORKER_BIND`：

```text
create/identify Conversation
associate task/role/worker
```

MUST NOT：

```text
completeNode
execute dev/test task body
reopen/wait for unready node
perform business side effects
```

正式工作只能由：

```text
NODE_READY
REOPEN
```

触发。

---

# 7. Action 调错防御

```text
1. role package static Action surface
2. clear OpenAPI operation semantics
3. Gateway auth/schema validation
4. downstream Owner state/version/policy validation
```

不能依赖“LLM 一般不会选错”。

---

# 8. Collaboration 幂等/顺序

`askPeer/replyPeer` 必须带 `idempotencyKey`。

```text
same key + same semantic request → same response
same key + different request → IDEMPOTENCY_CONFLICT
```

Thread：

```text
Q1 PENDING/DELIVERED
→ A1 durable
→ A1 Browser DELIVERED back to asker
→ only then Q2 allowed
```

Reply 仅 durable 不够。

同一 Task 参与者才可问答；reply target 自动来自 thread。

---

# 9. Collaboration Delivery

Extension 以稳定：

```text
messageId
```

作为真实 Browser delivery intent。

必须：

```text
verify expected roleRef + workerRef
idempotent/effectively-once submit strategy；不承诺端到端 exactly-once
receipt/result refs
uncertain side effect → reconcile before retry
```

Message Center 不创建 Worker。

---

# 10. Task terminal

Task terminal 后：

```text
no new ask/reply
no pending collaboration browser delivery
no node wake
```

已有 Collaboration Message **原样作为历史保留**，不新增 `CANCELLED/TASK_TERMINAL` 状态。

消息不能恢复或阻塞 Task terminal。

---

# 11. Gateway / Tunnel failure

```text
Custom GPT → public tunnel → Gateway
```

故障：

```text
Tunnel down
Gateway down
URL changed
network failure
```

规则：

- HTTP/transport failure 不自动等于业务成功；
- 重试同一业务调用必须复用 idempotency semantics；
- 只 Gateway 允许公网 exposure；
- Agent Runtime/Task/Execution/Browser bridge 不直接公网暴露。

Dev Tunnel package 负责自身 account/login/start/status/verify/doctor 闭环。

---

# 12. Product Carrier identity 失败

产品 Worker createTask 前必须拿到自身 `workerRef`。

若 current carrier context 无法可靠获得：

```text
STOP task creation
→ clear error/guide
```

不得：

```text
invent c-id
use previous Task worker
create task with guessed worker identity
```

具体 current URL/c-id 提供机制必须真实 E2E。

---

# 13. SemVer / Web sync

Agent Package：

```text
patch = prompts/text correction, no role/API semantic break
minor = compatible Knowledge/capability/Action addition
major = incompatible role responsibility/Action/Carrier contract change
```

Package upgrade 不自动更新 GPT Web。

CLI：

```text
compare registeredPackageVersion
→ tell user which Web fields/Knowledge/schema need manual sync
→ user confirms sync
→ update local registered package version
```

v1 Agent 不自动写永久 memory。

# 15. 端到端 Happy Path

```text
A. Install/setup 7 units
→ Gateway/Runtime local ready
→ Dev Tunnel login/bind Gateway/public URL ready
→ Browser Extension installed/configured with local-platform-token
→ user creates 3 Custom GPT Roles using 3 Agent Packages
→ register each g-id
→ generate one role key each
→ configure GPT Action auth/schema

B. New requirement
→ user opens NEW Product Conversation
→ full product discussion
→ obtain Product workerRef via verified Carrier identity path（Action path = PENDING_SPIKE；Browser/Carrier observation fallback/current evidence）
→ listRegisteredRoles by package id
→ createTask(product role+worker, dev role, test role)

C. User approves Task execution
→ Extension creates/binds Dev Worker (WORKER_BIND only)
→ Extension creates/binds Test Worker (WORKER_BIND only)
→ both bound
→ formal first NODE_READY

D. Dev work
→ use Conversation context
→ query Task/Execution on demand
→ askPeer product if needed
→ completeNode

E. Test work
→ NODE_READY to existing Test Worker
→ if requirement unclear: askPeer(product)
→ Product replyPeer
→ reply real DELIVERED back to Test
→ optional next question
→ collaboration never auto changes Node

F. Test fails
→ formal test result
→ authorized controller/dev decides reopen
→ Task reopenContext/runNo
→ same Dev Worker REOPEN
→ fix

G. Test succeeds
→ Task terminal
→ no more collaboration delivery
→ Task/Node/history + collaboration messages remain auditable
```

# 18. STOP 门

出现以下任一情况先回架构/Owner：

```text
Task and Agent both become role→worker truth
Message Center creates Worker
different Task reuses same Worker Conversation
Extension infers Task state itself
Gateway directly reads another domain DB or executes tools
logical delete/tombstone is reintroduced in v1
reply durable alone opens next question
Task terminal is reopened by collaboration
public tunnel exposes Task/Execution/Runtime directly
Role Key is reused as Browser Extension identity
package lifecycle details are duplicated inside Platform Deployment
need WorkItem/Claim/Redis/Kafka/dynamic Capability Catalog to make v1 work
```

## 当前正式约束：恢复与真实 Carrier E2E

- Browser/Execution restart 后的 Conversation reality check 属于 Execution；Agent 只恢复 Role/Worker/Collaboration 持久事实。
- Collaboration delivery 采用可能重复调用 + idempotent/effectively-once；effect_started 后不确定必须由 Execution reality verification，禁止 blind resubmit。
- Carrier 行为必须真实 ChatGPT Web E2E；OpenAI 新能力按 VERIFIED/PENDING_SPIKE/REJECTED_OR_UNSUPPORTED 记录。

# 19. OpenAI Carrier File / Action Transport Failure

File Bridge 不改变领域 failure ownership，但增加以下明确恢复规则：

```text
input download_link expired / fetch timeout
→ 不持久化旧 URL
→ 先查询 owning Domain 最新 facts + 既有 idempotency/action/execution result
→ 由 Worker 取得/提交 fresh transient `openaiFileIdRefs`；只重试尚未产生 business mutation 的 fetch/materialization transport
→ 若原 Action 可能已经产生业务写入，必须先按原 idempotencyKey/fingerprint 查询结果，禁止 blind replay 整个 business Action
→ 不盲用旧 bytes

output relay fetch failed
→ TaskDocument / Execution Artifact 继续作为 canonical source of truth
→ 重新生成短期 relay
→ 不复制业务文件成为 Gateway-owned durable storage

Action 45s ceiling
→ 返回 accepted/ref 或明确错误
→ 后续查询/Worker continuation
→ 不让 Gateway 隐藏为长期 hanging request
```

Action auth、GPT Web schema、Role capability 失配属于 Carrier/Deployment problem；Execution 真实 Effect 已开始时仍按 Execution UNKNOWN/reality verification 处理，不能因为 Carrier request timeout 就重做 Effect。

`x-openai-isConsequential:false` + Always Allow 的目标环境稳定性未验证前，permission prompt 仍要保留现场与 continuation；验证通过后 routine permission handling 从 happy path 降级为异常恢复。
