# 90 · Execution Domain 决策演进、修正与覆盖清单

本文用于解释为什么当前设计是这样，并防止后续 Chat 从旧结论误恢复。

## 1. Execution 定位

最终确认：Execution 不是“工具集合”，而是连接各领域意图与现实 effect 的线，是 `Intent → Effect → Evidence` 的 real-world effect plane。

## 2. Browser Extension 领域归属修正

早期 Browser Extension 曾在 Agent/BHR 语境中讨论；Phase 3 最终修正为：**Browser Extension 完全归 Execution Domain**。

Agent 仍拥有 Role/Worker/Collaboration 语义；Task 拥有 workflow；Extension 只负责真实 Browser execution 与 evidence。

## 3. Browser 顶层调度模型覆盖

曾讨论多条独立 line / watchdog / reconciliation；最终收敛：

```text
Task Driver = 唯一业务驱动线
System Observer = 独立只读最低优先级线
```

`Collaboration` 是 Task Driver 子流，不独立调度。

**周期全局 business reconciliation 被用户明确判断过度设计并删除。**

仅保留：Task Node polling/未来 event + 当前 lane events + human result + startup/reload one-time Recovery Scan。

## 4. Action Permission 修正

GPT Action Allow popup 最终归 Task Driver 处理，是 carrier friction，不自动等于 Effect Approval。

如果异常且可能阻断 Worker，不能先点 Deny/Reject，要保现场找用户。

## 5. Browser ONLINE / Binding 设计来源

Phase 2 真实测试曾出现：

- Side Panel persisted `host.state` 导致 Host 断线/重启仍显示 ONLINE；
- Extension reload 后旧 binding/content script 可能残留；
- `tabs.sendMessage` 出现 `Could not establish connection. Receiving end does not exist.`；
- 旧 `Extension context invalidated`；
- captureVisibleTab 权限曾真实失败。

Phase 3 因此冻结：

- ONLINE = current session + heartbeat freshness；
- extension/content instance identity；
- transient worker↔tab binding；
- reload/restart one-time recovery；
- transport error 与 effect error 分离；
- Side Panel 显示真实 stale/unknown。

这些旧故障是设计动因，但新架构不直接复刻 Phase 2 BHR 数据模型。

## 6. Worker CREATE/RESTORE/WAKE 修正

最终利用 ChatGPT 真实 URL：

```text
/g/...              Role
/g/.../c/<c-id>      Worker Conversation
```

因此：

- workerRef 已存在就 RESTORE full URL；
- 不能因 Tab 丢失 CREATE；
- CREATE 通过 role page → bootstrap → URL 出现新 c-id；
- WAKE 必须真的提交 trigger message，因为仅打开 Conversation 不会自动继续工作。

## 7. Model 判断修正

一度容易把模型变成所有动作前置；最终冻结：

- 明确只读/确定性直接；
- 副作用或语义不确定才 FAST；
- FAST 低置信才 REASON；
- Human 极少。

push 不 blanket human；普通源码写入也不逐次人工。

## 8. execution-local 路径模型修正

曾讨论复杂多层路径域，用户明确收敛：**路径边界就是项目路径**。

最终只保留：projectRoot + `.ai-agent-platform` reserved exception + canonical/symlink 防绕出。

## 9. Secret 模型收敛

为加快进度，v1 不建 Vault/Secret Entity；采用 controlled env + redaction + 不主动暴露 `.env` secret。

## 10. Knowledge Retrieval 修正

曾建议加入 execution-local 第九能力；用户解释真实知识库是围绕产品/角色/Worker/Task 的产品领域知识。

最终：

- 从 Local P0 删除；
- v1 不实现；
- 只保留未来 Knowledge Access / Retrieval 扩展位。

## 11. MCP 删除

曾短暂设计 `execution-mcp`；用户明确：第一版没有 MCP 需求，过度设计。

最终完全删除，不占包、不占接口、不占测试。

## 12. Package/Service 收敛

最终：

```text
4 packages
1 backend service
2 executors
```

不微服务化 File/Git/Shell/Test/Policy/Evidence。

## 13. Node/TypeScript 修正

用户要求全 TS 类型约束。

Node 20.20.1 不能把原生 `node file.ts` 作为基线；最终采用 `tsx` 运行 + `tsc --noEmit` 强制 typecheck + runtime validation。

## 14. 执行可靠性核心不变

从始至终最终冻结的可靠性原则：

> **副作用可能已经发生但不确定时，UNKNOWN；绝不为了“自动化顺滑”盲重试。**
