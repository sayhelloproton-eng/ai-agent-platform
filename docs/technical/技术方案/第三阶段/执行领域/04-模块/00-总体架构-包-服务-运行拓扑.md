# 02 · 总体架构、包、服务与运行拓扑

## 1. [FROZEN] 包拆分

| 包 | 类型 | 是否独立服务 | 主要职责 |
|---|---|---:|---|
| `execution-contracts` | npm library | 否 | TS 公共合同、Capability Input/Result、状态、错误码、DTO |
| `execution-runtime` | npm package + Node Service | **是** | Execution 唯一控制面和持久化真源 |
| `execution-local` | npm executor library | 否 | File/Git/Package/Test/Process/Network/Shell 真实本机执行 |
| `execution-browser-extension` | Chrome Extension package | 否（浏览器运行单元） | Browser Executor、Task Driver、Worker Lane、Side Panel |

结论：**4 包 / 1 后端服务 / 2 Executor。**

## 2. 为什么 `execution-local` 不单独起服务

v1 推荐：

```text
execution-runtime
  └─ import execution-local
       └─ localExecutor.execute(...)
```

不推荐：

```text
execution-runtime → localhost:port → execution-local-service
```

理由：

- 同机单实例场景；
- 避免多进程鉴权、端口、部署、重启、通信故障；
- 仍通过 contracts 保持模块边界；
- 未来若需要进程隔离，可以只替换内部 transport，不改公共 Capability Contract。

## 3. Runtime Topology

```text
Custom GPT
   │
   ▼
Agent Gateway
   │
   ▼
┌──────────────────────────────────────┐
│       execution-runtime Service      │
│                                      │
│ Identity / Scope / Policy            │
│ FAST / REASON / Effect Approval      │
│ Execution Record / Idempotency       │
│ Result / Evidence / Recovery         │
└──────────────┬───────────────────────┘
               │
       ┌───────┴──────────┐
       ▼                  ▼
execution-local     execution-browser-extension
(in process)        (Chrome Extension)
       │                  │
       ▼                  ▼
File/Git/Test/...   ChatGPT Web / Worker pages
```

## 4. 两种执行发起路径

### 4.1 Worker-initiated

```text
Custom GPT Worker
→ Action
→ Dev Tunnel
→ Agent Gateway
→ execution-runtime
→ policy/model/approval
→ Local or Browser executor
→ Result/Evidence
→ Gateway
→ Worker
```

### 4.2 Platform-driven Browser Task Driver

```text
Browser Extension Task Driver
→ 发现当前 Task/Node/Collaboration 需要真实 Browser effect
→ execution-runtime 建 Execution Record + policy decision
→ 原 Extension 执行 Browser effect
→ report Result/Evidence
→ owning domain Public API 写回业务事实
```

注意：Runtime 不成为 Task/Agent orchestrator；Browser Task Driver 不成为 Task 业务真源。

## 5. Browser 与 Runtime transport

[FROZEN semantics, DEFERRED implementation]

必须支持：

```text
handshake
heartbeat
command delivery
stage/reporting
result/evidence reporting
pending recovery
human continuation
```

但 WebSocket / HTTP long-poll / 其他本地 bridge 不在架构阶段锁死，必须由真实 Chrome MV3 E2E 决定。

## 6. 依赖方向

推荐 package dependencies：

```text
execution-contracts
   ↑          ↑          ↑
   │          │          │
execution-runtime  execution-local  execution-browser-extension

execution-runtime → execution-local
execution-browser-extension ↔ execution-runtime (runtime protocol)
```

禁止 contracts 反向依赖 runtime/executor。

---

## 当前正式约束：平台拓扑

`execution-runtime` 保持独立 Service/Process/Deployment Unit；`execution-local` 仍是进程内 executor library；Browser Extension 是独立 Execution Deployment Unit。平台本地 Task/Agent Runtime 由独立 `@ai-agent-platform/platform-host` package 装配，Execution 通过其公开 transport/client访问 Task/Agent，禁止内部源码/Store 依赖。
