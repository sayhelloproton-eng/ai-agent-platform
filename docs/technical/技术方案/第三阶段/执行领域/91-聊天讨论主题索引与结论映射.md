# 91 · 聊天讨论主题索引与结论映射

> 本文件是**基于当前 Chat 可见讨论与项目上下文的结构化重建**，目的是保留讨论顺序、修正关系和最后落点；它不是逐字聊天导出，也不包含私有思维链。真正实现以 `00`~`14` 的冻结文档为准。

## 1. 从领域定位开始
讨论首先明确：如果五个领域是点，Execution 是把它们连接到现实的线。最终定义为 real-world effect plane，口号 `Intent → Effect → Evidence`。落点：`00 §1~2`、`01`。

## 2. 先切清与其他领域边界
确定 Task 只管流程/Node，Agent 管 Role/Worker/Collaboration，Model 管推理，Deployment 管部署；Execution 只持 opaque refs，不吞业务对象。Task Approval 与 Effect Approval 分离。落点：`01`、`08`、`11`。

## 3. Capability vs Tool
讨论拒绝“万能工具平台”方向，确定公共语义叫 Capability，CLI/fs/DOM 只是实现。Typed capability 优先，Shell 只做 escape hatch。落点：`00 §4`、`05`、`06`。

## 4. Model 判断边界
从“副作用需要模型”进一步收敛为：明确只读 deterministic；副作用或语义不确定 FAST；低置信/冲突 REASON；Human 极少。明确反对每次源码写入/每次 push 都人工。落点：`08`、`05`。

## 5. Browser Extension 正式归 Execution
把 Browser Extension 从旧 BHR/Agent 边界中完全转入 Execution。Agent 仍拥有 Role/Worker/Collaboration 事实，Extension 只做 browser effect/evidence。落点：`04`、`11`、`90`。

## 6. Browser 顶层模型反复收敛
最终只保留 `Task Driver + System Observer`。Collaboration 被降为 Task Driver 子流程，周期全局 reconciliation 被用户明确认为过度设计并删除；只留正常 Task polling + lane events + one-time Recovery Scan。落点：`04 §3`、`90 §3`。

## 7. Worker/Conversation 现实身份
结合真实 ChatGPT URL，明确 `/g/...` 是 Role，`/g/.../c/<c-id>` 是具体 Worker。由此冻结 CREATE/RESTORE/WAKE：有 c-id 只 RESTORE；CREATE 捕获新 c-id；WAKE 必须真实 submit trigger。落点：`04 §5~9`。

## 8. Page state、Progress Gap、Runtime Stall
确定页面只有 `IDLE/BUSY/BLOCKED/UNKNOWN`，另用 progress signal 判断是否真的推进。区分 page IDLE 但业务没推进的 Progress Gap，与 BUSY 但无进展的 Runtime Stall。落点：`04 §10~11`。

## 9. Action Permission / Human Decision
历史修正为 Task Driver 处理 ChatGPT Action Allow friction；后续 OpenAI Carrier 吸收进一步收敛：routine operation 在静态 Schema 显式 `x-openai-isConsequential:false`，目标环境验证 Always Allow 后不再把 Browser 自动点击作为 happy path；异常 prompt 仍保现场、Evidence、等待用户。Human 必须可从 continuation 恢复，reload 后也不重放。落点：`04 §12~13/§20`、Agent Carrier E2E。

## 10. 通信、ONLINE、reload/restart
吸收 Phase 2 stale ONLINE / stale binding / receiver missing 的真实问题：Extension/Content 都有 instance identity，ONLINE 只看当前 session+heartbeat。Browser execution 有 COMMAND_ACCEPTED/PRECONDITION/EFFECT_STARTED/RESULT；effect 后断线必须 UNKNOWN。恢复只做一次 Recovery Scan。落点：`04 §6,15,17`、`07`、`09`、`90 §5`。

## 11. Browser Result/Evidence
明确不能用 click/transport success 代替效果成功；所有写动作走 Precondition→Effect→Postcondition Verification→Result。Screenshot 是关键场景证据，不强制每次截图。落点：`04 §16`、`09`。

## 12. Side Panel 被提升为 P0
用户明确要求“哪怕有问题也一眼感知”。因此 Side Panel 必须显示 session freshness、Workers、Task/Node、execution stage/status、permission/human/progress gap/stall/UNKNOWN、Evidence/log/recovery、System Observer。落点：`10`。

## 13. execution-local 能力盘点
从 File/Git/Shell 扩展到真实研发闭环需要的 8 组：File、Git、Project/Package/Dependency、Build/Test/Quality、Code Query、Process、Network、Shell。落点：`05`。

## 14. Knowledge 的纠正
一度建议 Knowledge/Retrieval 作为 Local 第九能力；用户说明知识库是围绕产品、角色、Worker、Task 的领域知识。最终撤回 Local P0 实现，只保留未来跨域扩展位。落点：`00 §4.4`、`90 §10`。

## 15. 路径/Secret 快速收敛
用户明确“路径边界就是项目路径”。最终 projectRoot 为边界，`.ai-agent-platform` 为保留区。Secret 不造 Vault，采用 controlled env + redaction + 不主动暴露 `.env`。落点：`05 §4,13~14`。

## 16. Local Process / Result / Shell 一次收口
One-shot + Managed Process；统一 timeout/maxOutput/cancel/process-tree/stdout/stderr；Result envelope + typed data；完整日志落盘。Shell 始终至少 FAST，复杂 expression 升级风险。落点：`05 §10~16`、`09`。

## 17. MCP 被明确砍掉
曾设计 execution-mcp，用户立即指出第一版无需求、过度设计。最终从 package/interface/test 全删。落点：`00 §4.3`、`90 §11`。

## 18. Public Contract / Record / Error / Package 收口
统一 `executeCapability` typed union + getExecution/readOutput/cancel；主状态与 side-effect state；幂等；4 包/1 服务/2 executors。另保留已确认的 selective durability：简单同步 deterministic read 可只日志，副作用/异步/恢复类必须 durable。落点：`02`、`06`、`07`。

## 19. TypeScript / Node 20 最终约束
用户要求所有可约束项用 TS 类型。确认 Node 20.20.1 不以原生 `node .ts` 为基线，采用 `tsx` 执行 + `tsc --noEmit` 类型门禁 + runtime validation。落点：`13`、`06`。

## 20. 最终停止点
Execution 已达到可以进入“文档冻结/等待新仓库实施”的状态。继续扩 MCP、RAG、Scheduler、Plugin 等都属于当前过度设计。落点：`14`、`00 §25`。
