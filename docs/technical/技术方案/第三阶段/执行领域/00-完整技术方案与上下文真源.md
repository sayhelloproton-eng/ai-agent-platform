# 00 · Execution Domain 完整技术方案与上下文真源

## 0. 文档目的

本文是 Phase 3 Execution Domain 的顶层真源。它不是聊天摘要，而是把数小时讨论中形成的**最终语义、关键修正、运行路径、技术边界和实现停止线**固定下来，使新的实现 Chat / Codex / 开发者可以只依赖本文及专项文档继续工程化，不需要重新回看原聊天。

---

## 1. 领域 Charter

### 1.1 [FROZEN] 定义

**Execution Domain 是平台的 real-world effect plane。**

它负责把已经形成的 Intent 转换为：

```text
Intent
  ↓
受控执行
  ↓
真实 Effect
  ↓
Result + Evidence
```

领域核心口号：

> **From Intent to Effect, from Effect to Evidence.**
>
> **Execution is where platform “claims” become “facts”.**

Execution 不替代上层角色思考，也不拥有业务流程；它负责让“我要做某事”真正发生，并证明现实到底发生了什么。

### 1.2 [FROZEN] 与其他领域的基本边界

```text
Task & Orchestration
→ workflow / progress / Node / Task documents / worker binding facts

Agent Runtime & Collaboration
→ Role / Worker / Collaboration / Agent Package / Gateway / 意图与人员上下文

Model & Inference
→ FAST / REASON / Vision 推理资源与推理执行

Deployment
→ install / config / start / stop / status / verify / doctor / upgrade

Execution
→ real effect / policy enforcement / execution record / result / evidence / recovery
```

Execution 可以携带 `taskId / nodeId / runNo / roleRef / workerRef / callerRef / correlationId` 等 opaque refs，但**不拥有这些业务对象的含义或生命周期**。

## 2. [FROZEN] v1 统一执行链

正常执行统一为：

```text
调用 Capability
→ Identity + Scope 校验
→ Policy
→ Deterministic / FAST
→ 必要时 REASON
→ 必要时 Effect Approval / Human Decision
→ 真实执行
→ Result + Evidence
→ 返回调用方
```

关键约束：

1. **明确已知、无副作用、Scope 清晰的操作不调用模型。**
2. **任何真实副作用，或任何语义不确定性，进入模型判断。**
3. 默认 FAST；只有低置信、冲突、复杂副作用才串行升级 REASON。
4. REASON 仍不能可靠判断时，v1 停止并进入更高决策/人工，不让模型“猜着执行”。
5. Hard rule 优先于模型；模型不能覆盖 Identity、Scope、Schema、Hard DENY、Mandatory Approval、Approval validity。
6. 人工不是每次副作用都弹窗；只处理真正需要人承担责任或系统无法可靠判断的情况。

Policy v1 最终只保留：

```text
ALLOW
REQUIRE_APPROVAL
DENY
```

## 3. [FROZEN] Task Approval 与 Effect Approval 分离

```text
Task / Workflow Approval
→ 控制 Task 是否进入执行流程

Effect Approval
→ 控制某一个真实世界副作用是否允许发生
```

二者不等价：

> **Task Approval ≠ Effect Approval**

Effect Approval 必须绑定具体动作，而不是“大范围授权”。至少绑定：

```text
capability
target
critical parameters
caller/task refs
effect fingerprint
precondition
expiresAt
```

目标、参数、fingerprint、关键前置现实变化后，原 Approval 失效。

## 4. [FROZEN] Capability 而不是 Tool

Execution 对外公共语言叫 **Capability**。

```text
Capability = 稳定、类型化、带语义的执行承诺
Tool       = CLI / fs / Chrome DOM / Node API 等底层实现手段
```

v1 不建立动态 Capability Registry、Plugin Marketplace 或自动生成工具平台。

### 4.1 Local P0 Capability Families

```text
1. Workspace / File
2. Git
3. Project / Package / Dependency
4. Build / Test / Quality
5. Code Query / CodeGraph
6. Process / Runtime
7. Network / Endpoint
8. Shell / CLI Escape Hatch
```

### 4.2 Browser Capability Families

至少覆盖：

```text
Carrier Context
Observe
Screenshot
Navigate
Input
Click
Upload
Submit
Wait
Verify
Worker CREATE / RESTORE / WAKE
Collaboration physical delivery
Action Permission handling
```

### 4.3 [REMOVED] MCP

`execution-mcp` 曾被讨论，后明确判断 v1 无真实需求、属于过度设计，因此：

- 不建包；
- 不建接口；
- 不建占位服务；
- 不进入测试；
- 未来只有出现明确真实场景才重新提案。

### 4.4 [DEFERRED] Knowledge Access / Retrieval

知识库语义主要围绕产品、角色、Worker、Task，而不是普通本机文件搜索。

v1：

- 不做 RAG / Embedding / Vector DB / Retrieval Service；
- 不把 Knowledge 塞进 `execution-local` P0；
- 只记录未来 `Knowledge Access / Retrieval` 扩展位。

其中：

```text
Task 动态文档 / Node Context → Task Domain
Agent Package 固定 Instructions / Knowledge → Agent Domain
产品/角色可检索知识库 → 未来能力
Execution → 未来只负责“真实查询动作”，不拥有知识内容和授权业务语义
```

## 6. [FROZEN] Execution Runtime 的唯一控制面地位

`execution-runtime` 是 Execution Domain 的控制真源和 Execution Record 真源，负责：

```text
Public Execution API

Scope
Policy
Deterministic/FAST/REASON/Human 决策
Effect Approval
Idempotency
Execution Record
Executor routing

```

它**不直接**：

```text
操作 DOM
读写产品源码
spawn 任意 shell
拥有 Task / Agent / Model 业务状态
```

## 7. [FROZEN] Execution Record 与可靠性

v1 不建立独立 `ExecutionAttempt` 实体，不建立 Job/DAG/Scheduler。

**持久化不是所有调用一刀切。** 简单、同步、确定性的只读调用可以只产生结构化日志与 `executionRef`，不要求写入 durable `execution_records`；但以下执行必须持久化：**side-effect、Effect Approval、异步/长运行、Browser/external boundary、UNKNOWN、需要 restart recovery 的执行**。

对于需要 durable record 的一笔官方执行，只有一个主 `Execution Record`；安全重试仅通过 `attemptCount`、日志和同一 `executionRef` 体现。

主状态：

```text
PENDING
RUNNING
SUCCEEDED
FAILED
UNKNOWN
```

副作用状态：

```text
NOT_STARTED
STARTED
APPLIED
NOT_APPLIED
UNKNOWN
```

最关键规则：

> **UNKNOWN ≠ FAILED。**

如果副作用可能已经发生但无法确认，必须：

```text
UNKNOWN_SIDE_EFFECT
→ 禁止盲重试
→ observe/query/reconcile reality
→ 确认 applied → SUCCEEDED
→ 确认 not applied → 重新校验后可继续
→ 仍不清楚 → UNKNOWN / STOP / Human
```

危险动作必须**先持久化执行意图，再越过真实副作用边界**。

## 8. [FROZEN] Browser Extension 顶层运行模型

Browser Extension 顶层只存在两条线：

```text
1. Task Driver      # 唯一业务驱动线
2. System Observer  # 独立、只读、最低优先级稳定性观察线
```

明确删除：独立 Collaboration Scheduler、周期全局业务 reconciliation、复杂 Browser Host 状态机。

### 8.1 Task Driver

Task Driver 负责整个 Worker Browser Flow：

```text
Task/Node 驱动
Worker CREATE / RESTORE / WAKE
Collaboration Delivery（作为子流程）
GPT Action Permission
Worker 页面异常
Human Decision pause/wait/resume
安全恢复
```

同一 `workerRef` 的 Browser 写动作在 Worker Lane 串行。

v1 Browser 写操作优先全局串行以确保可靠性；不同 Worker 的 GPT 生成可以异步并存。真正浏览器并行写以后 E2E 再验证。

### 8.2 System Observer

System Observer：

- 完全独立于业务推进；
- 只读；
- 全系统最低优先级；
- 只在 browser/model 空闲或低负载时做较重观察；
- 不推进 Task、不发送协作、不处理权限、不自动恢复；
- 输出稳定性报告、异常建议、后续恢复报告。

## 9. [FROZEN] Worker / Role / Tab 身份

稳定业务身份：

```text
roleRef + workerRef
```

Custom GPT URL 现实：

```text
/g/<role...>                # Role
/g/<role...>/c/<workerRef>  # 一个具体 Worker Conversation
```

临时运行身份：

```text
tabId
extensionInstanceId
contentInstanceId
```

原则：

- `tabId` 永远不是 Worker 的业务身份；
- Worker↔Tab 绑定只是 transient cache；
- Extension reload / Chrome restart / page reload 后必须重建；
- 旧 persisted `ONLINE/READY` 不具权威性。

---

## 10. [FROZEN] Worker CREATE / RESTORE / WAKE

### RESTORE

已有 `workerRef`：

```text
打开稳定 /g/.../c/<workerRef>
→ 页面加载
→ 校验 g-id/c-id
→ 当前 content session healthy
→ 建立 transient binding
```

**有 workerRef 时绝不能因为 Tab 不在就 CREATE 新 Worker。**

### WAKE

打开 Worker 页面不等于 Worker 会继续工作。

WAKE 必须：

```text
确保目标 Worker 已 RESTORE
→ 确认页面可写
→ 注入明确 Node/trigger 指令
→ Submit
→ 验证该消息真实进入目标 Conversation
```

WAKE 成功只代表“工作已投递给 Worker”，**不代表 Node 完成**。

### CREATE

没有 workerRef 时：

```text
打开 Role-level /g/<role>
→ 发送最小 bootstrap / bind message
→ ChatGPT 自动导航到 /g/<role>/c/<new-c-id>
→ 从 URL/navigation 获得 c-id
→ 校验 Role + Conversation
→ 可做 harmless bootstrap-check Action
→ 调 Task Public API bind
→ STOP
```

CREATE 只负责创建并绑定 Worker，不能顺便开始 dev/test Node 工作。

若 CREATE 过程中断且 Conversation 可能已经生成：

```text
UNKNOWN_SIDE_EFFECT
→ 先恢复/定位已有 Conversation
→ 禁止盲目再 CREATE
```

## 11. [FROZEN] Browser 页面状态与进展

页面 Runtime 状态：

```text
IDLE
BUSY
BLOCKED
UNKNOWN
```

另维护：

```text
activityKind
lastProgressAt
lastProgressKind
```

必须区分：

```text
Progress Gap
= 页面 IDLE，但业务事实还没有推进

Runtime Stall
= 页面 BUSY，但长期无真实进展且不存在合法等待原因
```

判断优先：DOM / URL / runtime signal / heartbeat 等确定性事实；冲突或 UNKNOWN 再截图 → FAST Vision → 必要 REASON。

无固定万能 timeout；按 activity/capability 的合理 progress window 判断，具体阈值留给真实 E2E/perf。

## 12. [FROZEN] Action Permission 与 Human Decision

GPT Action 的 Allow permission popup 属于 Task Driver 的 carrier friction，不自动等价于平台业务 Approval。

已知 managed Worker + expected Gateway/domain/action/scope + Policy 允许：

```text
Extension 可以自动点击 Allow
```

如果异常、不能安全允许、无法可靠判断：

```text
不要先点 Deny/Reject
→ 保持现场
→ Evidence + screenshot/log
→ pause Worker Lane
→ 询问用户
→ 用户决定
→ revalidate 后从原 continuation 恢复
```

如果 Task Driver 打算做会阻断 Worker 的 Reject/Deny，也必须先由用户确认。

Human Decision 是原 Worker Lane 的 async wait，不自动创建 Task 状态。

必须保留 `continuationRef` 语义，Extension reload 后仍能从原断点继续，而不是重新 WAKE / replay effect。

## 13. [FROZEN] Collaboration 是 Task Driver 子流程

Agent Domain 拥有 `askPeer / replyPeer` 的 Message Center 业务事实。

Browser Extension 只负责**物理投递**。

要求：

- 同一 Task 内已绑定 participants；
- 同 Worker 写串行；
- reply 必须实际 `DELIVERED` 后才允许继续下一问；
- Collaboration 不是独立 scheduler；
- Delivery 事实和 Evidence 回到 Agent/Execution 对应所有者。

## 14. [FROZEN] Browser 可靠通信与重启恢复

Extension ONLINE 必须来自**当前活 Session + heartbeat freshness**，不能从持久化旧状态读取。

运行身份：

```text
runtimeInstanceId
extensionInstanceId
contentInstanceId
tabId
```

Browser 写执行至少记录以下阶段事实：

```text
COMMAND_ACCEPTED
PRECONDITION_VERIFIED
EFFECT_STARTED
RESULT_REPORTED
```

这些是同一 Execution 的内部阶段，不是新的业务实体。

关键规则：

- `EFFECT_STARTED` 前断线且可证明 NOT_APPLIED：同一 `executionRef` 重新校验后可以继续；
- `EFFECT_STARTED` 后失联：进入 UNKNOWN/reality verification，禁止盲重试；
- 已 SUCCEEDED 的 `executionRef` 再收到，只返回已有结果，不第二次执行；
- `Receiving end does not exist` 等 transport/content 错误不自动等于 Effect FAILED；先判断副作用边界。

Extension reload / Chrome restart / reconnect 后只做**一次性 Recovery Scan**：

```text
建立新 extensionInstanceId
→ handshake runtime
→ 扫描现存 Tabs
→ 解析 role/worker URL
→ 重新建立 content session / transient binding
→ 查询 unfinished Browser Execution / waiting continuation
→ 先恢复事实，再决定动作
→ Recovery Scan END
→ 回到正常 Task Node 驱动
```

v1 **不做周期全局 business reconciliation**。

## 15. [FROZEN] Browser Precondition / Result / Evidence

所有 Browser 写动作统一：

```text
Precondition
→ Effect
→ Postcondition Verification
→ Result
```

Precondition 使用**语义 fingerprint**，不使用脆弱的整页 DOM/pixel hash。

可包含：

```text
target role/worker
URL identity
Task/node/run
关键页面状态
目标控件/内容 fingerprint
current execution precondition
```

`click()` 成功、transport 成功都不是 Effect 成功。

每个 Capability 自己定义后验成功判据。例如 Submit：目标消息真实出现在目标 Conversation，内容 fingerprint 匹配。

Screenshot 只在关键副作用、异常/UNKNOWN、Vision 判断、人工现场等场景强价值，不要求每个动作都截图。

Browser Verifier 是 Extension 内部组件，不新增 Verification Service。

Side Panel 不成为业务真源，只展示真源 + Browser reality。

至少展示：

```text
Extension ONLINE / STALE / OFFLINE + heartbeat freshness
受管 Worker 列表
roleRef / workerRef / Tab / Conversation binding
IDLE / BUSY / BLOCKED / UNKNOWN
activityKind / lastProgressAt / lastProgressKind
Task / Node / run
in-flight executionRef
COMMAND_ACCEPTED / PRECONDITION_VERIFIED / EFFECT_STARTED / RESULT_REPORTED
SUCCEEDED / FAILED / UNKNOWN
Action Permission
Human Decision
Progress Gap
Runtime Stall
UNKNOWN_SIDE_EFFECT
Evidence / Screenshot
最近关键日志 / 错误摘要 / Recovery 状态

```

原则：**错误真实优先于漂亮状态。宁可显示 UNKNOWN/STALE，也不显示假 ONLINE/READY。**

## 17. [FROZEN] execution-local 安全模型

Local Execution Envelope：

```text
caller/task/worker
workspace(projectRoot)
capability
target
cwd
parameters
environment
timeout
output limit
executionRef
```

路径边界最终收敛为：

> **Worker 默认路径边界 = 当前项目根路径。**

但：

```text
projectRoot/.ai-agent-platform/**
```

是平台保留区，普通 Worker File/Shell Capability 不可访问。

canonical path / symlink 实际越出 projectRoot → Hard DENY。

### 默认判断矩阵

```text
明确只读 File/Git/CodeGraph/Runtime 查询 → Deterministic
正常 File/Git/Dependency/Process mutation → FAST
Build/Test/Project scripts → FAST
明确安全 Network GET/health → Deterministic
Network 写 → FAST
Shell runCommand → 始终至少 FAST，复杂时 REASON
证据冲突/范围模糊/复杂副作用 → REASON
REASON 仍不能可靠决定/需人承担责任 → Human
```

### Hard DENY

至少包括：

```text
cwd / canonical path 越出 projectRoot
访问 .ai-agent-platform 保留区
sudo / 提权
系统关机/重启
磁盘格式化/分区
明显系统级破坏
读取平台内部凭证
```

模型不可覆盖。

## 18. [FROZEN] Local Capability Map

### Workspace / File

只读：`readFile/listDirectory/searchFiles/searchText/getFileMetadata` → Scope 合法时 deterministic。

写类：`writeFile/createDirectory/movePath/deletePath` → FAST，必要 REASON/Human。

Evidence：path、beforeHash、afterHash、diff、bytes。

### Git

只读：status/diff/log/currentBranch/showCommit → deterministic。

mutation：branch/stage/commit → FAST。

push：不硬编码 ALWAYS_HUMAN；正常 remote/branch/task intent 清晰可自动，force push/异常历史覆盖再升级。

### Project / Package / Dependency

读取 project/package manager/scripts/dependencies → deterministic。

install/remove/installProjectDependencies → FAST；Evidence 包含 manifest/lockfile change、stdout/stderr。

### Build / Test / Quality

`runTests/runBuild/runLint/runTypecheck/runProjectScript` 默认 FAST，因为脚本可能写文件、启服务、联网。

### Code Query / CodeGraph

`findSymbol/findReferences/findCallers/findCallees/findImports` → v1 只读 deterministic。底层可用 rg / TS compiler / LSP，Capability 不变。

### Process / Runtime

只完整管理平台自己启动的 managed process。

status/logs/port → deterministic；start/stop/restart → FAST。

不通过 typed API 随意 kill 系统任意 PID。

### Network / Endpoint

明确允许目标上的安全 GET/health → deterministic。

POST/PUT/PATCH/DELETE/upload → FAST；必须控制 host/scheme/method/redirect/body/credential。

### Shell / CLI Escape Hatch

`runCommand` 是最后逃生口，不是中心 API；始终至少 FAST。

优先 argv：

```text
command + args
```

复杂 shell expression（pipe/redirection/&&/subshell 等）自动提高风险，通常升级 REASON。

Shell 不能绕过 Scope/Secret/Policy/UNKNOWN。

## 19. [FROZEN] Local Process Model

只分两类：

```text
One-shot
Managed Process
```

One-shot：test/build/install/git/shell 等，等待 exit/timeout/cancel。

Managed Process：dev server/API server/background worker；启动后返回 `processRef`，后续 status/logs/stop/restart。

所有进程型 Capability 统一支持：

```text
cwd
env
timeout
maxOutput
cancel
process-tree cleanup
stdout/stderr capture
```

Managed Process 启动成功不能只看 spawn；允许 readiness 条件：endpoint/port/logPattern。

## 20. [FROZEN] Secret / Environment

v1 不建 Secret Service/Vault。

规则：

- 子进程默认不继承平台完整 `process.env`；
- 只注入最小基础环境 + 当前项目明确允许的 env；
- 项目的 `.env*` 可由项目自身脚本正常加载；
- 平台不主动把 `.env` 全文送模型或写日志；
- 明显敏感文件优先返回 metadata/存在性/键名，不主动暴露 secret value；
- Bearer/API key/token/password/cookie/private key 等日志必须 redaction；
- `.ai-agent-platform` 内部 credential 永远不向普通 Worker 暴露。

## 21. [FROZEN] Result / Evidence

公共 Result 使用统一 Envelope + Capability-specific typed data。

理念：

> **模型说“完成了”不是 Evidence；真实执行器产生的现实结果才是 Evidence。**

Local Evidence 示例：

```text
File      → path/hash/diff
Git       → status/diff/HEAD/commitSha
Dependency→ manifest/lockfile/stdout
Test      → exitCode/report/stdout/stderr
Process   → pid/readiness/port/log
Network   → status/response metadata
Shell     → command fingerprint/exitCode/stdout/stderr
```

Browser Evidence：URL identity、DOM semantic evidence、message fingerprint、screenshotRef、page state、Action state 等。

大日志/报告/截图只保存引用，不全部塞进 SQLite 或模型上下文。

**Delivery 只在真实跨进程/跨 carrier 边界存在时记录。** Local 同进程 `readFile` 之类不制造虚假的 Delivery/Receipt；Browser/Collaboration 等真实投递边界才有 Delivery 语义。

stdout/stderr：**完整落盘，API 默认只返回有限摘要 + refs。**

## 22. [FROZEN] Public Contract

统一入口：

```text
executeCapability(request)
```

但 request 必须是 TypeScript **discriminated union**，不能退化成 `capability: string + input: any`。

另保留：

```text
getExecution(executionRef)
readExecutionOutput(executionRef, offset, limit)
cancelExecution(executionRef)
```

v1 不做 Execution Workflow / Attempt / Job Scheduler / Executor Registry API。

详见 `06`。

## 26. 实施时必须守住的最终句

> **Execution Runtime 决定“这件事能不能、该怎么执行”；Executor 负责“真的执行”；Result + Evidence 证明现实发生了什么。**

> **Task 决定流程，Agent 决定人员与协作，Model 提供推理，Deployment 管部署；Execution 不吞并这些领域。**

> **如果现实结果不确定，宁可 UNKNOWN，也绝不通过盲重试制造重复副作用。**
