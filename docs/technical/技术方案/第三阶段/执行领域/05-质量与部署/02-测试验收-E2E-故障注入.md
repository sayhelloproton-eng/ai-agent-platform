# 12 · 测试、验收、E2E 与故障注入

## 1. Gate E1 — Contract

必须自动测试：

- TypeScript compile；
- runtime validation；
- capability discriminated union；
- Result/Error union；
- state transition；
- idempotency；
- same key/different fingerprint conflict；
- redaction helper；
- path scope pure logic；
- policy hard rules。

停止门：`tsc --noEmit` + contract tests 0 fail。

## 2. Gate E2 — Local Real Execution

必须在真实临时 Git 项目运行，而不是全 mock：

```text
file read/write/search
Git status/diff/commit
package inspect/install（可用受控 fixture package）
typecheck/test/build
managed process + readiness
endpoint check
shell argv
```

安全 case：

```text
../ outside DENY
symlink outside DENY
.ai-agent-platform DENY
secret redaction
full process.env not inherited
sudo/system destructive DENY
timeout/cancel/process tree cleanup
```

可靠性：

- write response interruption → hash recover；
- commit response interruption → HEAD recover；
- managed process restart/status recover。

## 3. Gate E3 — Browser Real Execution

必须真实 Chrome + ChatGPT carrier。

核心场景：

```text
CREATE worker
RESTORE existing worker
WAKE worker
browser submit
Action Permission：目标环境已验证 Always Allow → routine Action 不发生 Browser click
Action Permission：Always Allow 未验证/失效、schema-domain-auth 变化或 consequential/异常 prompt → Browser permission fallback / human wait
Collaboration physical delivery
page state/progress detection
Side Panel truth display
screenshot/evidence
```

不接受纯 mock 宣称 Browser PASS。

## 4. Gate E4 — Reliability / Fault Injection

这是 Execution 的关键 Gate。

至少破坏：

```text
Extension reload
Content Script reload/navigation
Chrome restart
execution-runtime restart
runtime-extension connection loss
command received before effect disconnect
effect_started after disconnect
result reported/reply lost
```

验收：

- old ONLINE 不复活；
- old content instance invalid；
- worker↔tab binding 重新建立；
- existing worker 不被误 CREATE；
- effect_started 后不 blind retry；
- UNKNOWN 正确产生；
- reality recovery 能把 UNKNOWN 收敛；
- waiting human continuation 能恢复；
- WAKE 已完成时不重复 WAKE。

## 5. Gate E5 — Cross-domain E2E

目标：真实产品 Task 从研发到测试闭环。

示例：

```text
Task created/approved
→ Dev Worker bound/restored
→ WAKE
→ Worker reads context
→ Local code read/write
→ typecheck/test
→ managed service
→ endpoint verify
→ collaboration if needed
→ Test Worker wake
→ Browser/Local validation
→ formal Task transitions
→ Task completed
```

期间必须真实产生：

```text
Execution Records
FAST decision
必要时 REASON
Result/Evidence
Browser Side Panel state
persisted logs
```

验收目的：证明 **Intent → Effect → Evidence → Task Progress**，不是只证明单 API。

## 6. Mobile Model 测试假设

Execution E2E 必须按真实模型资源假设：

- FAST 默认；
- REASON 稀少；
- FAST→REASON 串行；
- 不按“两个模型并行”设计 load test；
- Browser System Observer 深评必须让路给业务模型请求。

## 7. 测试产物

推荐所有 Gate 输出：

```text
summary.json
execution records snapshot
structured logs
failure evidence refs
browser screenshots（必要场景）
```

失败必须能从 executionRef 下钻，不允许只输出 “E2E failed”。

---

## 当前正式约束：E2E / Fault Injection Gate

E5 必须覆盖 Task→Worker→WAKE→Model/Execution→Effect→Evidence→Task completion，以及 reopen/human wait/UNKNOWN recovery。Browser 关键链必须真实 Chrome + ChatGPT Web；Fault Injection 至少覆盖 network disconnect、runtime crash、Extension reload、response lost、persist failure、model timeout、version conflict。

## 8. OpenAI Carrier 联合 E2E 补充

Execution E3/E5 与 Agent/Deployment 联合验证：

- [ ] Browser WAKE 只注入 small identity/trigger，不注入完整 Task docs；
- [ ] `openaiFileIdRefs` 文件经 Gateway → Execution bounded fetch 后 hash/MIME/size 正确；
- [ ] input `download_link` 过期不会被持久化或盲 retry；
- [ ] `openaiFileResponse` URL relay 失败不会改变原 artifact truth；
- [ ] platform→GPT image 不走 `openaiFileResponse`，screenshot/Vision 路径仍可用；
- [ ] routine Action consequential=false 时，Execution Approval 仍独立生效；
- [ ] Multi-Action Turn 不产生重复 Browser submit/WAKE；
- [ ] effect-started 后 Carrier timeout 仍按 reality verification，而不是重新执行。
