# 执行领域｜当前设计原则与不变量

## 1. 领域定位

Execution 是平台唯一 real-world effect plane：

```text
Intent → Policy/Decision → Effect → Result + Evidence
```

它不拥有 Task workflow、Agent identity/context、Model judgment 或 Deployment lifecycle。

## 2. 审批语义

Task 业务授权与 Execution Effect Approval 是不同概念。OpenAI Carrier confirmation 也不等于 Execution Approval。任何外部 UI 确认都不能绕过平台 Effect Policy。

## 3. Capability 与 Tool

Capability 是平台公开的类型化执行能力；Tool 只是某个 Carrier/模型表达方式。v1 typed capability first，不建立泛化 Tool Runtime。

## 4. 决策顺序

```text
identity/scope
→ deterministic policy
→ deterministic path when sufficient
→ FAST when judgment required
→ REASON on uncertainty/escalation
→ Human only when policy/risk requires
→ real Effect
→ Result/Evidence
```

Policy 只返回 `ALLOW / REQUIRE_APPROVAL / DENY`。

## 5. Side Effect 安全不变量

- 危险 Effect 在实际执行前必须持久化 intent / execution identity。
- 已开始 Effect 但现实结果无法确定时进入 `UNKNOWN`。
- `UNKNOWN` 绝不 blind retry，必须先 reality verification。
- transport/click success 不等于 business/effect success。
- 简单 deterministic read 可不创建 durable Execution Record；Effect/Approval/async/Browser/UNKNOWN/recovery 必须 durable。

## 6. Browser 唯一 Owner

Execution Browser 唯一拥有：CREATE、RESTORE、WAKE、page runtime state、permission、screenshot、click/type/submit、Collaboration physical delivery、disconnect recovery。

稳定 identity 是 `roleRef + workerRef`；tab/window/content-script id 都是 transient locator。

## 7. Browser 调度模型

- Task Driver：唯一业务驱动浏览器流。
- System Observer：只读、最低优先级，不推进业务。
- 不建立周期性 global business reconcile；只在 startup/reload/reconnect 做一次 Recovery Scan。
- Browser write v1 全局串行；同 Worker 不并行提交。

## 8. CREATE / RESTORE / WAKE

- 已有 workerRef 时优先 RESTORE，不因 Tab 丢失 CREATE。
- CREATE 只用于确实没有 Worker 的场景，并从真实 Conversation URL 获得 c-id。
- WAKE 必须真正提交 trigger message；打开页面本身不代表 Worker 被唤醒。
- WAKE 成功只证明 trigger delivery，不等于 Node、Action 或 Effect 成功。

## 9. Permission

当 Carrier 已验证 Always Allow 且 operation 非 consequential 时，routine happy path 不依赖 Browser 自动点 Allow；未验证、异常或 consequential prompt 必须保留 Browser permission fallback。Carrier confirmation 不替代 Execution Approval。

## 10. Page / Recovery

页面状态统一为 `IDLE / BUSY / BLOCKED / UNKNOWN`；区分 Progress Gap 与 Runtime Stall。effect_started 后断线必须 reality-first recovery。关键场景截图按证据需要采集，不要求每一步截图。

## 11. Local Capability 边界

v1 提供 workspace/file/git/code/package/dependency/build-test/process/network/shell 等工程能力；项目边界就是 canonical `projectRoot`，`.ai-agent-platform` 为受保护例外；必须防 symlink/path traversal 越界。

Secret 采用受控 env/secretRef + redaction；不建立 Vault/Secret business entity。

Execution Network 只做 deterministic engineering network：localhost/LAN、exact URL download、authenticated HTTP、integration probe、package registry query；公共互联网 research 不属于 Execution。

## 12. Knowledge / MCP

v1 不实现动态 Knowledge Retrieval service，只保留未来扩展位；MCP 不进入当前主链。

## 13. 工程拓扑

```text
@ai-agent-platform/execution-contracts
@ai-agent-platform/execution-runtime
@ai-agent-platform/execution-local
@ai-agent-platform/execution-browser-extension
```

只有 `execution-runtime` 是 backend service；local executor 是 in-process library；Browser Extension 是独立浏览器部署单元。

## 14. TypeScript 约束

Node 20.20.1；TypeScript 运行采用 `tsx`；独立 `tsc --noEmit` 强制类型检查；所有外部边界从 `unknown` 进入 runtime validation；公共合同禁止 `any`。
