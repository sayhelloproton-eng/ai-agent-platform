# ARC-P3-001｜公共领域与模块边界总体设计（候选）

> 优先级：P0。  
> 这是 Phase 3 第一项架构设计，不以当前 `packages/contracts / auth / policy / gateway` 的目录为约束。

## 1. 需求目标

公共领域的任务不是建立一个“万能 common package”，而是定义：

> **任何模块要独立部署、替换和版本演进时必须共同遵守的最小平台语言。**

它必须解决 Phase 2 中反复出现的跨域漂移：claim、opaque ref、payload、approval、result、error、dispatch credential、provider location 等。

## 2. 公共领域应该拥有的语义

第一版候选：

### 2.1 Identity / Reference

- `task_ref`
- `work_ref`
- `dispatch_ref`
- `result_ref`
- `evidence_ref`
- `approval_ref`
- `backend_ref`
- `capability_ref`
- `command_ref`
- `module_ref`
- `provider_ref`

统一原则：opaque identity，Consumer 不解析内部结构。

### 2.2 Contract Envelope

所有跨模块请求 / 响应至少统一：

```text
contract_version
request_id
correlation_id
idempotency_key
producer_ref
```

### 2.3 Result / Error

统一 transport-neutral：

```text
SUCCEEDED
FAILED
PARTIAL
UNCERTAIN
CANCELLED
```

错误至少区分：

- validation；
- conflict；
- unavailable；
- policy；
- authorization；
- precondition；
- execution；
- uncertain-side-effect；
- timeout。

### 2.4 Capability Descriptor

模块公开“能做什么”，而不是暴露内部 class：

```text
capability_ref
input_contract
output_contract
side_effect_class
approval_class
idempotency_class
transport hints
version
```

### 2.5 Module Manifest

每个可部署模块公开：

- module id / version；
- supported protocol versions；
- capabilities；
- health / readiness；
- endpoint / transport metadata；
- optional auth requirements。

### 2.6 Approval / Evidence 基础语义

公共层只定义跨域协议，不拥有业务审批策略：

- approval request identity；
- grant identity；
- one-time consumption；
- effect fingerprint；
- expiry；
- evidence ref。

### 2.7 Runtime Configuration Reference

Runtime config 将逻辑引用解析为 Provider / Adapter：

```text
capability_ref → provider_ref
provider_ref   → adapter config
backend_ref    → inference provider/model mapping
command_ref    → command registry entry
```

Flow 不感知地址。

## 3. 公共领域不拥有

禁止 Common 层膨胀为新 God Module。

它不拥有：

- Task 状态机；
- Controller 决策；
- Browser DOM；
- Local FS / shell；
- 模型 Prompt；
- 具体 Storage schema；
- 具体 HTTP server 实现。

## 4. Port / Adapter 规则

每个模块 Core：

```text
只依赖本模块 public ports + 公共 contracts
```

外部依赖：

```text
Runtime-owned config
→ Composition Root
→ concrete Adapter / Provider
```

本地同进程实现只能是一种 Adapter，不得成为架构前提。

## 5. 独立部署最低验收

对于任意核心模块，至少证明：

```text
Core + InProcessAdapter
```

与：

```text
Core + HttpAdapter
```

对上层调用者提供相同语义。

## 6. Phase 3 第一轮需要冻结的文档 / 代码资产

- Public contract inventory；
- Ref taxonomy；
- Result / Error taxonomy；
- Capability descriptor schema；
- Module manifest schema；
- Provider config schema；
- Port / Adapter coding rule；
- compatibility policy；
- reference conformance tests。
