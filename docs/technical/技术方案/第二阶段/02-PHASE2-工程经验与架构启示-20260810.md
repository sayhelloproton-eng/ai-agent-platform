# Phase 2｜工程经验与架构启示（2026-08-10）

## 1. 最大经验：真实问题不是 DOM，而是生命周期所有权

Phase 2 后半程暴露的主要问题包括：

- Journal 100/100 导致 polling starvation；
- Approval 等待期间 claim / reclaim 不断增长；
- `user_reviewing` false positive；
- React send button 异步 readiness；
- Controller Wake 在 generation 中提前写 composer；
- Action Allow 被误判成 `RESPONSE_INTERRUPTED_BY_USER`；
- Observation 主动滚动页面；
- 长 Conversation 增长后 viewport / scroll 位置漂移；
- Browser Delivery 已经成功，但后续 response failure 反向把 Browser Work 判 FAILED。

这些问题表面不同，核心相同：

> **Observation、Execution、Approval waiting、Response lifecycle、Human interaction、Continuation 被耦合在同一个 Browser command 生命周期里。**

## 2. 冻结经验一：OBSERVE != MUTATE

Observation 必须纯读取。

`OBSERVE_PAGE` 不应该隐式：

- `scrollToBottom()`；
- focus；
- click；
- composer write；
- 改 viewport。

否则观察本身会改变被观察对象，并产生 user-reviewing、动态 scroll、precondition 等反馈环。

## 3. 冻结经验二：Delivery 是不可逆事实边界

对于 `SUBMIT_MESSAGE`：

```text
PREPARED
→ EXECUTING
→ SEND
→ DELIVERY CONFIRMED
→ SUCCEEDED
```

一旦 Delivery 已确认，后续 Controller response、Tool Call、Action Allow、用户交互不能反向把该 Browser mutation 改判失败。

如果后续 Controller 失败，应该表达为：

```text
browser-submit = SUCCEEDED
controller-continuation = FAILED / BLOCKED
```

而不是：

```text
browser-submit = FAILED
```

## 4. 冻结经验三：Human Approval 是协议事件

人工动作至少有两类：

1. 平台 Approval Grant；
2. ChatGPT 原生 Action Allow / Deny。

它们是协议中明确要求的人机协作，不应该默认等价于“用户接管页面”。

当前通过 selector / activity epoch 给合法点击做豁免，只能作为兼容实现，不能成为长期领域模型。

## 5. 冻结经验四：Business Wait != Execution Lease

Approval waiting 是业务状态，不应该长期持有 execution claim。

目标模型：

```text
PREPARED
→ WAITING_FOR_APPROVAL
→ release execution lease

Grant
→ READY_TO_EXECUTE
→ claim
→ EXECUTING
```

而不是反复：

```text
claim
→ wait
→ expire
→ reclaim
```

## 6. 冻结经验五：Controller Wake 是通知

`CONTROLLER_WAKE` 只应该负责“让 Browser-backed Controller Session 获知有新状态”。

目标语义：

```text
BUSY → DEFER
IDLE → SUBMIT WAKE
DELIVERED → SUCCEEDED → END
```

它不应该继续拥有 Controller response 生命周期。

## 7. 冻结经验六：动态页面使用语义位置，不使用绝对位置

聊天页面持续增长，`scrollHeight` 会变化，DOM 也可能重新布局。

长期模型应表达：

```text
FOLLOWING_LATEST
USER_REVIEWING_HISTORY
AUTOMATION_REVEAL_TARGET
```

必要时使用 message / element anchor + relative offset，而不是保存固定 `scrollTop` 或每次强制追 `scrollHeight`。

## 8. 冻结经验七：Browser Host 不应该成为隐藏 Workflow Engine

理想 Browser Executor：

```text
receive command
→ validate target / authorization
→ observe precondition
→ execute exactly one browser capability
→ confirm effect
→ report
→ END
```

Phase 2 实现逐渐承担了 heartbeat / binding / polling / observation / scrolling / user-control / approval / response wait / wake / journal 等大量职责。Phase 3 必须重新切层，避免状态组合爆炸。

## 9. 冻结经验八：真实 Browser 应是 Acceptance，不是主要 Debugger

Phase 3 必须加强：

- deterministic state-machine tests；
- fake clock；
- lease expiry matrix；
- approval timing matrix；
- crash / restart / replay；
- delivery boundary tests；
- continuation race tests；
- Browser adapter contract fixtures。

真实 Chrome 只验证最终能力和少量关键现实约束。
