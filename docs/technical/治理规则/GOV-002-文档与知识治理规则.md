# GOV-002 文档与知识治理规则

## 1. 目标

正式文档必须同时满足：人类易读、AI 语义无损、Git 可审计、Registry 可追踪、Feishu 可重建。

## 2. 文档职责

- README：目录或文档包入口，不复制完整领域正文；
- Context：短、小、当前、可信，由总控 Planner 维护；
- Knowledge：面向人和 Agent 的长期正式解释；
- Technical：实现方案、调研、治理、Runbook、迁移和证据；
- ADR：说明为什么选择某个重要方向；
- Registry：机器身份、关系、状态、路径和投影，不承载长正文。

每篇正式文档只拥有一个核心问题。重复内容应链接到 Canonical Owner，而不是复制后分别维护。

## 3. Document Bundle

包含正式资源的文档使用：

```text
DOC-ID-title/
├── README.md
└── assets/
```

规则：

- 资源与正文同目录、同分支、同 Commit、同 Review；
- Markdown 图片必须使用 `./assets/...`；
- 禁止 `asset://`、独立图片分支、GitHub Raw 图床和 Feishu URL 成为 Git 正式引用；
- 文档移动、归档或 supersede 时资源整体移动；
- 简单无资源文档可以保持单文件。

## 4. Human-first, AI-lossless

正式内容首先给人阅读：骨架清楚、信息密度高，优先使用架构图、流程图、状态机、矩阵、表格、时间线和清单，减少连续长段叙述。

每张图片下方必须立即出现：

```markdown
### AI 可读语义镜像
```

镜像必须保留图中的节点、关系、方向、边界、状态、转换条件、例外与关键结论。可使用结构化叙述、表格、ASCII 图、文本流程或状态列表。Alt Text 不能替代语义镜像。

图片与镜像构成原子视觉块，任何一侧变化都必须重新 Review 另一侧。

## 5. 当前、目标和证据

文档必须显式区分：已验证实现、部分实现、已接受决策、目标设计、未来候选、被替代和历史归档。事实优先回查代码、测试、真实调用、Registry、Release、Migration 和 Context。

## 6. 稳定 ID 与 Registry

概念继续时保留稳定 ID；标题和路径可以治理性调整。被替代资产保留历史，通过 `superseded_by` 指向替代项。所有路径、关系、发布和实现状态变化同步 Registry。

## 7. Feishu

`docs/knowledge/` 是 Feishu 唯一正式发布源。Publisher 读取 Git 文档包，上传本地图片、覆盖正文、插入媒体块并回读。Feishu 内容不参与语义合并，也不反向改写 Git。

## 8. 验收

- 标题、核心问题和读者明确；
- 当前与目标不混淆；
- 链接和本地资源存在；
- 每个图片都有紧邻的 AI 可读语义镜像；
- README、Registry、Context 和相关映射同步；
- Secret、隐私和未授权第三方全文不存在；
- 实际校验、Commit 和限制被报告。
