## 角色

- Chat：负责事实判断、内容取舍、最终正文和 Review 结论；
- 高级 Codex：可读取大范围仓库，核对路径、代码、测试、Git 历史和 Registry，返回证据并按授权落库；
- Executor：仅在冻结的执行权限内修改与回传证据，不获得规划权或 Artifact 作者权。

## Review 顺序

1. R-01 项目入口与上下文；
2. R-02 产品体系与架构；
3. R-03 平台核心系统；
4. R-04 智能体与 Skills；
5. R-05 工作流、治理与交付；
6. R-06 实验、反思、遗漏与 Portfolio。

六个域是检查域，不是 Git 批次数。不得默认每域创建远程 Branch / PR，也不得为了保持六域形式制造六个无意义 Commit。实际落库可以根据依赖与变更量合并为较少批次；Branch、Worktree、Push、PR、Merge、Rebase、删除和清理由每个任务自己的 Git Operating Policy 决定。

## 每域工作法

1. 固定 Source Commit，先只读核对代码、测试、Registry、Context、ADR 与正文；
2. 区分已验证实现、部分实现、已确认设计、未来候选、历史归档和冲突；
3. 输出事实表、阻塞问题、逐文件建议与证据位置；
4. 由 Chat 冻结正文或在已授权边界内由高级 Codex 收敛明确漂移；
5. 按任务 Git Operating Policy 落库、验证、Commit 与 Push；
6. 以真实 Diff、测试与 Commit 作为完成证据。
