# KNO-002 多级领域上下文架构

## 1. 文档定位

定义 Agent 启动和执行所需上下文层级，在足够准确的前提下加载最小必要信息。

## 2. 层级

L0 Platform Constitution、L1 Project Context、L2 Domain/Product Context、L3 Task Context、L4 Execution Context、L5 Evidence Context。

## 3. 职责

上层保存稳定规则与项目状态；任务层保存目标、范围、SHA、验收和停止条件；执行层保存环境、Git、Tool 和权限；证据层保存测试、Diff、Hash 与回读。

## 4. Context Package

包记录 package_id、task_id、source_commit、selected_assets、selection_reason、private_context_refs、evidence_refs 与 generated_at。大型资料按需引用。

## 5. 漂移

任务开始验证 Source Commit；任务结束检查 Context、Registry 和 Release。Memory、旧会话或过期路径不能替代 Git。

## 6. 当前实现边界

当前 `context/` 提供项目、架构、状态、知识策略和路线；Project Knowledge Governance Skill 支持索引优先，但没有通用 Context Package 服务。

## 7. 目标设计边界

目标由 Registry 和检索策略选择最小资产集，生成版本化 Context Package，并在执行和 Handoff 中保存选择依据。

## 8. 设计原则

- 索引优先不全仓扫描
- 稳定规则/当前状态/任务输入分层
- 上下文包绑定 Commit
- 私人上下文按需引用
- 证据不与目标混写
