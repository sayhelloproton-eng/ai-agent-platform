# KNO-008 知识与资产变更影响分析

## 1. 文档定位

定义资产变化后如何根据 Registry 关系计算需要 Review、重建、测试或重新发布的范围。

## 2. 输入

读取变更资产 ID、旧新 Commit、变更类型、生命周期、关系图、实现/发布映射和风险等级。

## 3. 传播

Contract 变化传播到实现、测试、Adapter 和调用文档；Architecture 传播到 Context、能力地图和 Portfolio；Knowledge 传播到 Pack 与 Feishu；Skill 传播到 Agent、Workflow 和 Eval。

## 4. 输出

输出 directly_changed、affected_assets、required_reviews、required_tests、packages_to_rebuild、projections_to_update、blocked_by 与 risk_level。

## 5. 风险

低风险为格式/链接；中风险为跨文档语义/关系/状态；高风险为 Contract、权限、数据、外部写入和不可逆动作。

## 6. 当前实现边界

当前影响分析主要人工完成；Registry 有稳定 ID 和关系，但无自动遍历与 Review Plan 生成器。

## 7. 目标设计边界

目标提供只读 Impact Analyzer，由 Git Diff 与关系图生成候选清单，再由 Task Control 创建后续 Task。

## 8. 设计原则

- 先计算候选再确认
- 关系缺失标记不确定
- 旧证据按边界复用
- 发布与代码验证分任务
- 分析不自动授权写入
