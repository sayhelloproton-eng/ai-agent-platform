# KNO-007 平台资产关联模型

## 1. 文档定位

定义 Platform Registry 如何统一表示知识、代码、Skill、Agent、Workflow、实验、Release 与发布目标的关系。

## 2. 身份

长期资产具有 asset_id、asset_type、title、status、evidence_level、materialized、canonical_path、publication_status 与 migration_state。移动和重命名保持 ID。

## 3. 关系

使用 depends_on、implements、explains、validated_by、derived_from、governed_by、uses_skill、loads_knowledge、projected_to、supersedes 等受控语义。

## 4. 分离

Registry 保存路径、状态、关系和发布元数据；正文服务人的理解，不维护第二套大 Front Matter。

## 5. 一致性

校验 ID、路径、canonical 唯一、端点、关系类型、superseded、materialized、Release 与 Migration 生命周期。

## 6. 当前实现边界

当前 Registry 已管理 126 个资产、关系、Release、Migration 与 Engineering Insight Registry，并纳入仓库验证。

## 7. 目标设计边界

目标增加 Agent Profile、Knowledge Pack、Task Evidence 和 Feishu Mapping 统一关系，并生成影响图和索引。

## 8. 设计原则

- 机器状态只在 Registry
- 关系词来自受控枚举
- 移动保持 ID
- 关系支持查询与影响分析
- 正文与元数据分离
